## 一、我们要做什么

我们研究不同创作者怎样通过旅游帖子呈现青岛，例如：提供出行信息、介绍地方文化，或描写景色与感受。

**文本是主要依据，身份用于分组，图片用于补充和对照。** 同一篇帖子的文字和图片可以通过帖子编号`postid`对应。你仍按各自任务的材料独立判断；负责人会在分析时把结果放到同一篇帖子下，比较不同创作者怎样用文字和图片呈现目的地，不需要你额外填写图文关系标签。

**编码，就是阅读材料后，按照统一规则选择标签。** 例如，把“门票很贵”记录为价格方面的负面评价。你不需要写程序，也不需要计算权重或汇总比例，这些由程序完成。

**试编码，就是先做一批材料，检查说明是否清楚、不同人能否按同样的办法判断。** 两人先独立作答，保存首次答案后再讨论。讨论前不互看答案，不用AI代填，也不自行上网补找材料。

## 二、每批处理哪些材料

| 任务 | 本轮安排 | 你要做什么 |
|---|---|---|
| 文本 | 每批50篇完整帖子，每篇带有已经分好的全部片段；片段数另行统计 | 先读全文，再逐段填写。50篇不等于50个片段 |
| 作者身份 | 本批文本和图片样本的账号合并去重，另加约10个负责人选定的检验账号；不另设50名配额 | 等本批文本、图片首次答案都提交后再做；同一账号、同一批固定资料只判断一次 |
| 图片 | 首轮30张，先做15张，保存答案并讨论后，再做另外15张 | 两人看相同图片，每张只回答四个问题 |

50篇是逐批积累训练材料的安排。初期随机抽取，后期根据模型负责人的反馈补充材料；编码员不自行挑选或替换样本。每轮仍先保存两人的独立答案，再处理分歧。

**试编码答案不会自动成为训练标准答案。** 标准答案有时称为“金标”，指经过人工核对、解决分歧并最终确认的答案。规则变了，负责人还要说明哪些旧答案需要重新检查；存在未解决问题的记录先不进入正式训练材料。

三类任务的数量分别计算。30张图片不表示要编码这50篇帖子的全部配图。你只处理自己收到的任务。

**先做文本，后判身份。** 同一批里，先完成并提交文本任务（以及图片任务）的首次答案，之后才领取身份任务。这样读帖子时不会预先知道作者是机构还是高粉博主，避免身份印象影响对内容的判断。做文本和图片时看不到身份资料；提交后的文本答案也不因为后来看到身份资料而回头修改。

## 三、文本怎样填写

### 第一步：读完整帖，填写帖子信息

先了解整篇在讲什么，再按页面要求填写：

- **明确商业披露**：原文明确写了广告、赞助、合作、受邀体验等，才选“有”。只出现品牌、购买建议或夸赞，不足以判断合作；选“没有”也不证明实际上不存在合作。
- **帖子信息**：平台、图片数量等已填写的信息保持原样；需要你判断的目的地类型等，按全文选择。

**目的地类型看整篇：** 从自然、文化、城市、度假、混合、未呈现明确取向（NONE）六项中选一项。城市整体游览中包含海边、古建筑和餐饮，仍可属于城市取向；自然观光帖附带交通或吃饭信息，仍可属于自然取向。不能因出现青岛、市区地点就直接选城市，也不能因资源多、地点多就直接选混合。不同取向都实质展开、全文没有清晰主次时才选混合；完整文字仅报告一般旅行动态，没有可识别取向时选NONE。例如“假期开始，去海滨小城逛逛”可选NONE，“去山顶看日出”虽短仍选自然。已有具体内容但拿不准分类时标疑问，必要时点“暂未解决”；材料缺失或加载失败时报材料问题，均不用NONE代替。NONE是已完成判断的正式答案，其他字段照常填，不把整篇清零。平台尚无此选项时留下疑问并报告选项缺失，不拿混合顶替。完整规则见[编码表](../data-dictionary/编码表.md#destination-orientation-none-20261025)。

这不影响下一步逐段填写：整帖选了城市，片段仍可记录自然、历史、美食等资源。不需要另填一套美食、住宿、交通等整帖子类，也不根据片段标签数量推算整帖类型。

### 第二步：逐段回答四类问题

“固定片段”指系统按embedding自然语义切分配置提前生成、经发放核对后固定的片段。具体分段由负责人和工程统一落实，编码员无需运行模型。不要自行拆分、合并或修改编号；即使一句中有“但、不过”或多个评价，也按给定片段填写。认为切分影响判断时，注明“切分问题”。

| 页面中的编号 | 用普通话理解 | 填写范围 |
|---|---|---|
| V3 内容策略 | 作者用什么方式表达？如提供实用信息、解释知识、描写体验或邀请互动 | 看整个片段，可同时选中多个符合条件的策略 |
| V4 旅游资源 | 写到了什么？如海景、建筑、美食、住宿、活动或旅游购品 | 看整个片段，可同时记录多类资源 |
| V5 语言功能与情感 | 在陈述事实、作评价还是提建议？评价是什么方向、程度怎样？ | 事实、评价、建议可共存；评价类别、方向和强度围绕下文选出的主导评价填写 |
| V6 目的地属性 | 在评价或建议哪一方面？如价格、服务、卫生、交通便利 | 每段只记录一个主导属性 |

**其他策略怎么选：** 有明确寒暄、篇章导航或创作／平台元话语时，可与信息、知识、情感、互动策略及彼此并记，不要求另句或另段。纯符号SYM只看整个片段，正文夹emoji不加记；其他残余RES只用于整段前四类均未命中、且GRE／STR／MET／SYM均不适用的情况，不为剩下几个字额外加记。父类与子类仍分别填写，共现本身不算冲突。自拟对照：“大家好，这条路线全程约两小时”可同时记信息参数与寒暄。详见[编码表](../data-dictionary/编码表.md#cs-oth-cooccurrence-20261022)，旧记录保留原答案及实际版本，受影响项另行复核。

**建筑与遗迹怎么选：** 描述建筑外观、空间设计或住宿、交通、服务等使用功能时，按ARC判断；调用年代、遗产身份或历史意义时，按HIS判断。历史建筑只谈外观且相关语境没有调用历史意义时可选ARC，不凭熟悉的地名或外部常识补HIS；同段两方面均有证据时可以并选。人工花海、水体仍按实际资源内容判断。“出片”“打卡”不能单独证明对象是建筑，也不自动产生REC或其他标签。自拟对照：“展馆的曲面外墙很特别”按ARC；“旧车站见证铁路发展历史”按HIS。完整判据见[编码表ARC／HIS边界](../data-dictionary/编码表.md#arc-his-boundary-20261022)。旧记录保留原答案与版本，受影响项目另行回原文复核。

**休闲游憩怎么选：** 单纯列游览站点、总用时或照片地点索引，不据此选REC；赏叶、观海、动物互动、登山、骑行等有明确活动内容时可以选。普通地点路线与明确的骑行／徒步线路分开判断，不要求作者已做过。REC不成立时，路线、时间参数及其他资源仍照常判断。详见[编码表REC边界](../data-dictionary/编码表.md#rec-activity-boundary-20261022)。

**旅游购品怎么选：** 地方特产、旅游纪念品和文创商品用`RS-R-GDS`；如青岛地标冰箱贴、作为伴手礼的崂山茶。只吃海鲜不自动选购品；地方食品作为伴手礼可同时选饮食文化和旅游购品。只介绍商场设施按建筑设施判断，普通矿泉水等旅途补给不自动选购品。无需已经购买，但商品须有明确地方关联或旅游纪念意义。页面若未提供新字段，标记字段缺失并交负责人核对，不自行用“其他”替代。

**地方生活风貌怎么选（v3.24.3新增）：** 当地居民的日常生产、生计、买卖、邻里交往或社区生活被具体描写、观察时用`RS-R-LIF`；不要求传统性或作者参与。只出现“有居民／有商店／当地人”等泛称、普通付款或一次性服务接触不算；评价“烟火气／松弛”按ATM，不选LIF。传统礼俗与非遗按FOL，商品与餐饮按GDS／GAS，建筑与历史意义按ARC／HIS，具体游憩活动按REC。

“大类／小类”也叫“父类／子类”。例如“消费、服务与设施”是大类，“价格与性价比”是其小类。页面要求填写两级时，两级都要判断。

### 第三步：分清“写到了什么”和“在评价什么”

下面均为虚构教学例子，只列相关判断，不是实际样本答案：

| 原文 | 资源：写到了什么 | 属性与评价：在评价什么 |
|---|---|---|
| “这家酒店每晚300元。” | 住宿 | 只是说明价格，没有价格好坏评价；属性不适用 |
| “这家酒店太贵了。” | 住宿 | 价格与性价比，负面评价 |
| “这家酒店服务很周到。” | 住宿 | 服务态度与专业性，正面评价 |
| “昨天我和朋友在崂山登山。” | REC休闲游憩活动 | 只有活动事实，V6不适用，ACT等属性记NA |
| “游客沿湖骑行。” | REC休闲游憩活动 | 他人的活动也可记录；没有评价／建议，V6不适用 |
| “这次登山过程很有趣。” | REC休闲游憩活动 | ACT活动与游览体验 |
| “我们沿海骑行，沿途海景特别美。” | REC及有证据的景观资源 | RES资源品质；ACT为0，因为评价指向海景 |

看到“酒店”不能直接选设施体验，看到金额也不能直接选价格评价。先判断是否有针对目的地属性的评价或建议；没有时，“是否涉及属性”填0，其余属性项按规定填“不适用”。

**提到活动不等于评价活动：** 作者、朋友或其他游客进行了明确的目的地休闲游憩活动，即使没有好坏评价，也可记REC；赛事等仍按REC／EVT原边界判断。ACT属于V6，只有活动／游览体验被评价或建议且选为主导时才填1，不能由REC生成。整段只有活动事实时ACT填NA；有其他适用属性成为主导时ACT填0。这两种情况不要混写。

**拍照适宜性怎么选（v3.22.0新增）：** 明确评价某处／某机位是否出片、是否容易拍到理想照片、拍摄是否便利，或明确围绕该适宜性提建议时，按`ASP-PHO/asp_pho`判断。不要求作者已经拍过。“这个位置随手拍都好看”是正面，“背景太乱，很难拍好看”是负面；同一主导属性正负并存时沿用MIX。只说建筑漂亮、只列拍摄点位置或只说拍过照片，不自动选此项；对摄影师、相机、滤镜或修图的评价也不自动纳入。

拍照适宜性仍受下文主导评价规则约束，不增加正负两套标签、不统计段内次数。被选为主导时，对应小类和“吸引力与体验”大类填1，方向与强度在V5填写。页面若未提供新字段，记录字段缺失交负责人，不用其他属性代替，不把旧任务缺列填0；详细边界见[编码表](../data-dictionary/编码表.md#photo-suitability-20261022)。

**天气与气候适宜性怎么选（v3.23.0新增）：** 明确评价气温、湿度、风雨、日照、季节等让目的地游览是否舒适、是否适合出行或开展游览，或围绕这点提建议，按`ASP-WEA/asp_wea`判断。不要求作者已去过。只报气温、天气预报或一般提醒带伞／防晒，不自动选此项；也不能看到V4“天象气候”就补选WEA。

以下是自拟对照，只列相关判断：

| 表达 | 应看哪一项 |
|---|---|
| “今天20℃，午后有雨。” | 纯天气事实，V6不适用 |
| “天气凉爽不闷热，游览很舒服。” | WEA，正面 |
| “风雨太大，在外面游览很不舒服。” | WEA，负面；不凭不舒适推断风险 |
| “雨后晚霞的景观很美。” | RES资源品质 |
| “阴天这个机位很好出片。” | PHO拍照适宜性 |
| “大浪可能把人卷走，别下礁石。” | SAF明确风险 |

仍先按下文规则选一个主导属性；只有WEA被选中时，其小类及“吸引力与体验”大类填1。方向与强度在V5记录；同一天气适宜性属性正负并存时记MIX，不因多次提天气或多个季节而重复计数，不改片段。页面缺字段交负责人核对，旧答案缺项不补0或改签版本；详细规则与兼容要求见[编码表WEA判据](../data-dictionary/编码表.md#weather-suitability-20261022)。

### 第四步：选出一个主导评价

**主导评价**指按下面顺序选出的、这一段用于记录属性和情感的主要评价。它只限制V6属性及V5的评价类别、方向、强度；其他策略、资源和语言功能仍看整个片段。

**活动体验还是资源／氛围：** 评价具体活动或整体游览过程的趣味、参与感、体验价值及适宜性时按ACT；评价景色、建筑、美食本身的品质时按RES；评价场所气氛、生活节奏及社会环境时按ATM。自拟对照：“沿途海景很美”看RES；“沿海慢慢走、看看海，这样游览很享受”看ACT；“街区氛围悠闲松弛，让人很放松”看ATM。活动词可以只是背景，不能单凭“舒服、体验、值得来”选ACT。整体游览适宜性须有相关语境支持，不自行补出未表达的原因；多个独立评价仍按下列原顺序选择。详见[编码表REC／ACT判据](../data-dictionary/编码表.md#rec-act-boundary-20261023)，拿不准照常留疑问，旧答案按实际版本另行复核。

**资源品质还是地方氛围：** 若选中的评价只是对建筑、景观等资源的整体审美称赞，如单独说“这座建筑很有氛围感”，本段没有明确相关的场所氛围含义，按RES资源品质判断。同一固定片段内，相关句子说明了该评价所指的悠闲、浪漫、热闹等场所氛围时，按ATM判断；分成两句话或换行仍可一起理解。“这里的氛围很好”等简短但明确评价场所氛围的说法，也可选ATM，不要求详细描写。

若说明在另一固定片段，不自动把那段的独立描述补成本段证据；指代关系可回看，拿不准则标疑问，不改段。若同段分别有建筑品质与场所氛围两项评价，仍按下列主导顺序选择，不能见到氛围词就一律选ATM。该判据不把所有模糊“环境好／体验好”归RES；详见[自拟对照与边界](../data-dictionary/编码表.md#res-atm-boundary-20261022)。

**设施还是氛围：** 评价座椅、隔音、房间空间、设备、卫生间等设施本身的配置或使用感受时按FAC；评价安静、浪漫、热闹、松弛、烟火气、适合聊天等场所气氛或社会情境时按ATM。只说“环境好／环境超棒”而没有设施或氛围线索时，不默认归某一类：选最可辩护的一个，标`?`，原因写`BOUNDARY`，替代值填另一类，并摘原文。两者都明确时仍按下面的主导顺序选一个，不能同时把FAC和ATM都填1。自拟对照：“座椅很舒服，隔音也好”看FAC；“餐厅氛围温馨，适合聊天”看ATM；“吹海风小酌超惬意”看ACT；“餐厅环境超棒”没有展开则标`?`。详见[编码表FAC／ATM判据](../data-dictionary/编码表.md#fac-atm-boundary-20261023)。

**客流还是活动体验：** CRO记录客流、排队、等待或拥挤的评价／建议，ACT记录活动或整体游览过程的评价／建议。单独说“排队排了一小时”仅记AT-INF信息性陈述；没有其他评价或建议时，`asp_applicable=0`，V6属性为NA，情感不可判定且方向／强度为NA。加上“实在太久了”才有明确的等待评价；不凭时长替作者判断好坏，也不自动记CS-INF-PAR。原因与评价可以同时成立：“人太多，根本没玩尽兴”两处均有评价依据，前者不因属于原因而退出候选。仍按“转折后→强度高→先出现”只选一个主导属性；后句明确更强可选ACT，强度明确相同取先出现者，无法明确判断时标`?`、保留另一候选及证据，不新增原因／结果优先规则。“体验很差”须按实际评价对象区分，不凭该词自动归ACT。详见[编码表CRO／ACT判据](../data-dictionary/编码表.md#cro-act-evaluation-evidence-20261023)。

1. **转折后优先**：有“但、不过”等，而且后面确实在评价目的地属性，取后面的评价。
2. **表达更强的优先**：没有转折、且强度差别明确时，取表达更强的一项。
3. **同样强时取先出现的**：各项强度明确相同时，取先出现的评价。

| 虚构片段 | 主导属性 | 为什么这样选 |
|---|---|---|
| “景色很美，但厕所很脏。” | 环境与食品卫生 | 转折后的评价优先；景色仍可在资源中记录，但不另填景色评价 |
| “服务一般，隔音简直差到离谱。” | 设施完备与使用体验 | 隔音评价更强烈 |
| “位置方便，早餐也不错。” | 交通与可达性 | 强度相当，取先出现的评价 |

以上顺序无法明确解决时，自行选择最有依据的主导评价，标`?`、写一句理由（建议同时摘一处原文，可选），并记录合理的另一候选属性。例如，“风景很漂亮，但是娃有点闹腾”中的后半句不是目的地评价，不能机械地按转折后优先。完全无法作出有依据的选择时，按第六节记录“待讨论”。

选定后，V6只把对应的一个小类及其大类填1，其余填0；有明确属性但现有小类都不适用时选“其他属性”，不同时选具名小类。“其他”不表示拿不准。

**赞赏还是满意：** 对已选出的主导评价，称赞对象的美感、特色或品质时按ADM赞赏／惊叹；评价体验满足需要、满意或舒适时按SAT满意／舒适。高低唤醒只作这两类的典型特征。自拟对照：“景色很好看”可记ADM、正面强度1；“景色美得令人震撼”可记ADM、2；“住宿住得很舒心”可记SAT、1；“住宿满意极了”可记SAT、2。例子假定没有其他影响主导选择与强度的表达。

亚类与方向、强度各自查原文，填写顺序不决定结果；仍按本段主导属性的同方向最高表达记强度，重复普通赞美不升档。“不错”“值得来”须结合语境，先区分评价和建议，不默认归SAT；拿不准按既有疑问流程处理。其余亚类、主导顺序与NA规则保留。详细边界及旧记录复核要求见[编码表](../data-dictionary/编码表.md#adm-sat-boundary-20261022)。

**六类都不合适时选“其他”：** 主导评价已经成立，但原文没有充分证据归入赞赏、满意、兴奋、失望、沮丧或怀旧时，亚类选“其他／未命中现有评价亚类”（`OTH`）；方向和强度仍按这条主导评价独立填写，不要因为选了“其他”就改成中性、清空或记NA。若只是在两个具名亚类之间拿不准，仍按疑问规则标`?`，不选“其他”。

**情感方向与强度也只针对这个主导属性：**

- 方向按实际情况选正面、负面、正负都有或中性。中性是明确没有褒贬，不等于没评价。
- 正面、负面强度各填一次：0＝没出现该方向；1＝一般表达；2＝明确强烈表达。同方向有多个表达时取最高程度，重复说几次不自动升为2。
- 同一主导属性正负都有，就两边都记。例如，“这家店服务周到，另一家服务敷衍”，服务是同一属性，两边都是一般表达时，正面1、负面1，方向选正负都有。不新增具体店铺记录。
- 评价类别按主导评价单选；哪些类别适用，查本批标签说明。不满足某项填写条件时，用规定的“不适用”，不强行填中性或0。

帖子层的属性集合和情感汇总由程序完成，不再人工填一遍。

### 第五步：留意三种容易混淆的情况

| 容易混淆的地方 | 怎么区分（均为虚构例句） |
|---|---|
| 实用信息与普通事实 | “门票80元”可供别人出行参考，两者都算；“我12点到达”只是自己的经过，不因此标实用参数 |
| 情感描写与简短评价 | “太美了”是评价，不单凭这句话标情感渲染；“红瓦绿树，尽收眼底，很漂亮”有具体画面，两者都算 |
| 操作指导与建议 | “坐地铁后步行200米到入口”有可照做的步骤，但没有劝导措辞；“必去”是建议，但没有操作步骤。“早上去人少”可作选时间的指导，不按明确建议记录 |

第一人称叙述也可以提供实用信息。知识性的事实可以同时属于知识解释；不能把所有事实都标成出行信息。邀请“评论、收藏、转发”等才属于相应互动号召，普通旅行建议不自动算互动。

### 第六步：只摘录需要的原文

- **原文证据是可选项。** V6选出主导属性时，建议留一处能支持该判断的原文；若同时记录正负方向，证据最好覆盖两边。不填不影响提交。
- **V3、V4、V5的其他选中标签，只有标了疑问时才必须摘录；正常判断可不摘录。** 同一句能支持多个判断时可以共用，不必重复找不同句子。
- 复制最短但意思完整的原文；否定词、程度词和转折会改变意思时一并保留，不改写。
- 不手算文字位置、不写程序格式。摘录或定位入口由负责人发放前说明。

## 四、作者身份怎样填写

只看统一发放的固定账号资料，不用帖子内容猜身份。先完成并锁定内容首次答案，再领取身份任务；不实时查主页，不拼接采集阶段。

1. **先判断主体。** 认证或用户名明确为机构即可确认；签约、合作或任职不使个人变机构。主体不清留疑问与原因，机构不设粉丝门槛。
2. **全部个人都判断定位。** 所有可确认个人账号都判断相关公开定位，粉丝数独立记录，不再以低于门槛直接认定“普通个人”。`creator_positioning`填写`CLEAR`（明确相关定位）、`NOT_SEEN`（资料充分且核查未见）、`UNK`（资料不足或冲突）；已确认机构或非机构多人共用账号用`NA`，未判断留空。主体未明时定位记`UNK`并留原因。明确提供户外攻略、旅行路线等内容可支持定位，不要求逐字自称“博主”；单纯旅游爱好、合作联系方式或未知来源职业标签不足以独立支持。粉丝真实0保留，缺失不补0，粉丝缺失不抹去可判定位。
3. **最后独立记录规模。** 保留粉丝原值、原始显示与来源时间；“万”等按单位换算，不另取整。定位未明时仍可保存有效粉丝数。

例如，700粉但简介明确提供“户外攻略与旅行路线分享”的个人记`CLEAR`；只写“热爱生活”且资料已充分核查记`NOT_SEEN`；简介未提取则记`UNK`。以上是虚构教学例，不代填实际作者答案。

明确定位保留原文；核查未见记录材料范围；资料不足说明缺口。旧“普通个人”答案不能直接改成“未见定位”。最终比较分组尚未确定，不强填旧角色或用未知值替代未定方案。两人独立答案与讨论裁决分别保存。

详细规则见[编码表V0当前规则](../data-dictionary/编码表.md#creator-positioning-scale-separated-20261029)及[身份轨操作协议](身份轨试编码操作协议.md)。若界面仍以粉丝门槛跳过定位或强制派生旧角色，交负责人按新版字段承接后再发放，不把新判断塞进旧字段。

## 五、图片怎样填写

只看当前分配的整张图和共同使用的[青岛地标参考清单](../data-dictionary/青岛地标参考清单.md)，可以放大；不裁剪、不拆拼图、不搜索原帖，也不看外部配文或作者资料。图里本来有的文字可以看。本轮两人均为本地人，参考清单只列名称及常用别名；仍要能从画面认出地点，不能只因拍摄地点在清单里就判为标志性场景。日常场景型地点即使现在走红，也按画面内容判断，不因清单或网络知名度改选标志性场景。

**每张只回答四个问题，每个问题各选一个答案：**

| 问题 | 可选内容及解释 |
|---|---|
| 主要展示什么？（V7） | 自然景观、建筑遗产（也包括现代地标）、人物活动、美食或物产、服务设施 |
| 场景是什么？（V8） | 标志性场景：画面中有仅凭图片即可辨认的具体地点特征，例如建筑、雕塑、门楼、招牌、标志性海岸线；日常场景：街道、市场、社区或市井生活，不论该地现在是否出名；其他或不适用：如食物特写、室内设施 |
| 拍得多近？（V8景别） | 特写：局部细节；中景：主体及近旁环境；全景：大范围空间。这里的“景别”就是画面呈现的范围 |
| 从什么角度拍？（V8视角） | 平视或常规视角；高位俯视：明显从高处向下看；航拍：有显著高空、大范围鸟瞰特征，不要求查拍摄设备 |

先看有无明显突出的主体，再看大致占画面多少，不测量面积。人物很小、只是陪衬时，不因画面有人就选人物；菜品特写选美食，餐厅空间为主体时选服务设施。以建筑为主体且能直接辨认住宿、交通等服务用途时选服务设施；否则按建筑判断。

以下为虚构教学画面：

| 画面描述 | 四个答案 |
|---|---|
| 普通斜侧角度拍一盘海鲜，餐桌只露出一点 | 美食或物产；其他或不适用；特写；平视或常规视角 |
| 参考页可确认的建筑地标是主体，岸上常规高度拍摄，包含大范围海岸 | 建筑遗产；标志性场景；全景；平视或常规视角 |
| 早市摊位、买菜人群和街边交易，没有可确认的门楼或招牌 | 人物活动；日常场景；中景或全景；平视或常规视角 |
| 大学路红墙作为画面主体，墙面特征清楚 | 建筑遗产；标志性场景；中景或特写；平视或常规视角 |
| 人物近景，背景模糊，无法确认具体地点 | 人物活动；日常场景或待讨论；特写；平视或常规视角 |

不认识的建筑不能仅凭清单或正文判标志性场景；如果画面本身是普通街景、市场或社区，按日常场景判断；疑似地标而图片无法确认时，标“待讨论”。高楼向下拍不自动算航拍。地图、文字图和拼图保留任务，各问题分别判断，不能判断的项标“待讨论”，不把所有项一起作废。

本轮不填V9人物细项、V10消费符号、V11可见状态；未启用项保持原样，不填0或“不适用”。正常图片只填四个答案，不逐张写理由、不圈图、不增加图片类型记录。有疑问时用“前景”“右下角”等普通话说明即可。完整选项见[图片上手说明](图片轨试编码上手方案.md)。

## 六、拿不准时怎样处理

“字段”就是页面中一个需要回答的问题。不是每个字段都允许下列所有值，只使用本批说明列出的选项。

| 意思 | 页面可能显示 | 什么时候使用 |
|---|---|---|
| 没有 | `0` | 已看过，问题适用，但没有这个特征；不是没做或不会判 |
| 不适用 | `NA` | 该问题的前提不成立，例如没有属性评价时的后续属性项 |
| 尚未完成 | 答案空白 | 还没有做，不能当作0；未启用项按负责人说明保持原样 |
| 待讨论 | `UNRESOLVED` | 文本或图片试编码中，现有材料和规则无法支持唯一答案；同时标`?`并写一句困难 |
| 身份无法判断 | `UNK` | 只用于作者身份的资料不足或不能定类；文本、图片不使用 |

图片中的“其他或不适用场景”是一个完整场景选项，不等于可以随意把四项都填`NA`。本轮图片拿不准按“待讨论”处理；不要自行增加未提供的选项。

**有较有依据的答案，但仍拿不准：** 先填该答案，标`?`，选原因并写一句说明；有合理的另一答案时一并记录。原因可用“边界难分、上下文不清、证据冲突、材料问题、其他”。文本疑问建议同时留原文（可选）。选不出任何有依据的答案时，再用上表对应的未决状态。

**材料打不开、文字残缺或编号不对应：** 记录编号和问题，告诉负责人后继续下一项，不编造标签，也不自行换材料。下拉选项缺失或与说明冲突时同样报告，不拿别的值顶替。

## 七、怎样提交和讨论

提交前检查四件事：

- 应做的任务已处理，或已报告材料故障；未启用项没有乱填。
- 疑问标记和简短说明齐全；原文证据可选，建议为主导属性和标了疑问的阳性项补上。
- 没有改变原文、图片或编号，没有看另一人的答案。
- 这是自己的首次独立答案，没有覆盖此前提交。

通过各自账号提交。负责人先保存并锁定两份首次答案——“锁定”就是留住当时版本，之后不能悄悄改成一致。两份答案都保存后，再看分歧、对照原文或图片讨论；有争议的判断由负责人按既定安排处理。

**讨论结果另存，原始答案保留。** 首批答案不会仅因要用于模型训练就自动成为金标。改规则后，旧标签是否还能训练由负责人按字段和版本核对；不兼容标签不补成0，也不由编码员自行改旧答案。 规则有变化时，负责人将同一说明发给两人，并明确哪些旧材料需要重做。第一次讨论主要用来改进说明；不能用已经共同讨论过的答案来证明两人原本就判断一致。

### 研究负责人另做一次检查：标签有没有留下重要差异

**先确定观察哪些方面，结果出来后再概括目的地形象。** 首轮试编码除检查两人是否判断一致，还要检查编码能否支持研究结论。这项工作由研究负责人在首次答案保存后完成，编码员不增加逐帖形象命名、额外标签或说明表。

负责人利用同一批材料，依次核对：

1. 原文中重要的形象特点，现有标签是否保留了线索；两人答案相同的材料也要看。
2. 遗漏是否影响比较创作者的建构策略，而非只是无关细节。
3. 拟写的结论能否回到编码结果和原文找到依据；依据不足时收窄表述，确需修改标签时按既有规则修订并重查受影响材料。

复盘用现有记录简记“材料位置—观察到的配合—对应研究问题—现有编码能否覆盖／是否必要”，不要求编码员新增开放编码或图文关系表。机构偏正面、个人可能附带建议只是预期；负责人同样检查反例和相似材料。非必要新特征可以不纳入，缺少某特征就无法回答核心问题时，则须正式修订规则并处理受影响材料，不能只在总结中命名后直接统计。

图片把文字具体化可以叫广义互补，但当前只观察有证据的内容对应；先看是否是同一对象、同一属性，再讨论正负是否相反。图片没拍到某项瑕疵不等于否定文字；现有四个图片答案也不直接测量视觉情感或信息增量。

例如，“营造氛围”不直接区分浪漫、热闹或松弛；主导评价也不代表全部评价。不要根据宽泛标签直接给整篇帖子或青岛命名一种形象。具体步骤、虚构例子和处理办法见[编码簿第1.5节](../data-dictionary/编码簿_青岛旅游UGC编码框架.md#image-summary-coverage)。

负责人先收集首轮判断和覆盖检查的反馈，再讨论剩余三项研究取舍；这些问题不增加本轮填写任务。三轨怎样汇合、图文对应能支持什么解释，见[编码簿第1.6节](../data-dictionary/编码簿_青岛旅游UGC编码框架.md#track-roles-post-linkage)；当前讨论顺序见[总备忘录第七节](../planning/研究问题与待办总备忘录.md#research-discussion-current)。
