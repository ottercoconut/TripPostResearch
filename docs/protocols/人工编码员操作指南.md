# 人工编码员操作指南｜试编码审阅稿

> 更新日期：2026年10月4日｜说明版本：v2.4（待审阅）
> 本文覆盖文本、作者身份和图片三类任务。先供研究负责人审阅；发放前需补齐文末的信息。
> 对齐边界：文本任务以编码表v3.20.0的固定客观片段、主导评价和证据要求为准；身份任务以2026年10月4日`role-institution-20261004`及采集阶段时间口径`role-time-collection-20261004`为准；图片仅覆盖本轮V7／V8四字段。

## 一、我们要做什么

我们研究不同创作者怎样通过旅游帖子呈现青岛，例如：提供出行信息、介绍地方文化，或描写景色与感受。

**文本是主要依据，身份用于分组，图片用于补充和对照。** 同一篇帖子的文字和图片可以通过帖子编号`postid`对应。你仍按各自任务的材料独立判断；负责人会在分析时把结果放到同一篇帖子下，比较不同创作者怎样用文字和图片呈现目的地，不需要你额外填写图文关系标签。

**编码，就是阅读材料后，按照统一规则选择标签。** 例如，把“门票很贵”记录为价格方面的负面评价。你不需要写程序，也不需要计算权重或汇总比例，这些由程序完成。

**试编码，就是先做一批材料，检查说明是否清楚、不同人能否按同样的办法判断。** 两人先独立作答，保存首次答案后再讨论。讨论前不互看答案，不用AI代填，也不自行上网补找材料。

## 二、每批处理哪些材料

| 任务 | 本轮安排 | 你要做什么 |
|---|---|---|
| 文本 | 每批50篇完整帖子，每篇带有已经分好的全部片段；片段数另行统计 | 先读全文，再逐段填写。50篇不等于50个片段 |
| 作者身份 | 按分配的作者资料判断，不另设50名配额 | 同一账号、同一批固定资料只判断一次，重复发帖不重复填写身份 |
| 图片 | 首轮30张，先做15张，保存答案并讨论后，再做另外15张 | 两人看相同图片，每张只回答四个问题 |

50篇是逐批积累训练材料的安排。初期随机抽取，后期根据模型负责人的反馈补充材料；编码员不自行挑选或替换样本。每轮仍先保存两人的独立答案，再处理分歧。

**试编码答案不会自动成为训练标准答案。** 标准答案有时称为“金标”，指经过人工核对、解决分歧并最终确认的答案。规则变了，负责人还要说明哪些旧答案需要重新检查；存在未解决问题的记录先不进入正式训练材料。

三类任务的数量分别计算。30张图片不表示要编码这50篇帖子的全部配图；身份资料也不展示给正在做文本任务的编码员。你只处理自己收到的任务。

## 三、文本怎样填写

### 第一步：读完整帖，填写帖子信息

先了解整篇在讲什么，再按页面要求填写：

- **明确商业披露**：原文明确写了广告、赞助、合作、受邀体验等，才选“有”。只出现品牌、购买建议或夸赞，不足以判断合作；选“没有”也不证明实际上不存在合作。
- **帖子信息**：平台、图片数量等已填写的信息保持原样；需要你判断的目的地类型等，按全文选择。

### 第二步：逐段回答四类问题

“固定片段”指系统提前分好的句子或短段。不要自行拆分、合并或修改编号；即使一句中有“但、不过”或多个评价，也按给定片段填写。认为切分影响判断时，注明“切分问题”。

| 页面中的编号 | 用普通话理解 | 填写范围 |
|---|---|---|
| V3 内容策略 | 作者用什么方式表达？如提供实用信息、解释知识、描写体验或邀请互动 | 看整个片段，可同时选中多个符合条件的策略 |
| V4 旅游资源 | 写到了什么？如海景、建筑、美食、住宿或活动 | 看整个片段，可同时记录多类资源 |
| V5 语言功能与情感 | 在陈述事实、作评价还是提建议？评价是什么方向、程度怎样？ | 事实、评价、建议可共存；评价类别、方向和强度围绕下文选出的主导评价填写 |
| V6 目的地属性 | 在评价或建议哪一方面？如价格、服务、卫生、交通便利 | 每段只记录一个主导属性 |

“大类／小类”也叫“父类／子类”。例如“消费、服务与设施”是大类，“价格与性价比”是其小类。页面要求填写两级时，两级都要判断。

### 第三步：分清“写到了什么”和“在评价什么”

下面均为虚构教学例子，只列相关判断，不是实际样本答案：

| 原文 | 资源：写到了什么 | 属性与评价：在评价什么 |
|---|---|---|
| “这家酒店每晚300元。” | 住宿 | 只是说明价格，没有价格好坏评价；属性不适用 |
| “这家酒店太贵了。” | 住宿 | 价格与性价比，负面评价 |
| “这家酒店服务很周到。” | 住宿 | 服务态度与专业性，正面评价 |

看到“酒店”不能直接选设施体验，看到金额也不能直接选价格评价。先判断是否有针对目的地属性的评价或建议；没有时，“是否涉及属性”填0，其余属性项按规定填“不适用”。

### 第四步：选出一个主导评价

**主导评价**指按下面顺序选出的、这一段用于记录属性和情感的主要评价。它只限制V6属性及V5的评价类别、方向、强度；其他策略、资源和语言功能仍看整个片段。

1. **转折后优先**：有“但、不过”等，而且后面确实在评价目的地属性，取后面的评价。
2. **表达更强的优先**：没有转折、且强度差别明确时，取表达更强的一项。
3. **同样强时取先出现的**：各项强度明确相同时，取先出现的评价。

| 虚构片段 | 主导属性 | 为什么这样选 |
|---|---|---|
| “景色很美，但厕所很脏。” | 环境与食品卫生 | 转折后的评价优先；景色仍可在资源中记录，但不另填景色评价 |
| “服务一般，隔音简直差到离谱。” | 设施完备与使用体验 | 隔音评价更强烈 |
| “位置方便，早餐也不错。” | 交通与可达性 | 强度相当，取先出现的评价 |

以上顺序无法明确解决时，自行选择最有依据的主导评价，标`?`、写一句理由、保留原文，并记录合理的另一候选属性。例如，“风景很漂亮，但是娃有点闹腾”中的后半句不是目的地评价，不能机械地按转折后优先。完全无法作出有依据的选择时，按第六节记录“待讨论”。

选定后，V6只把对应的一个小类及其大类填1，其余填0；有明确属性但现有小类都不适用时选“其他属性”，不同时选具名小类。“其他”不表示拿不准。

**情感方向与强度也只针对这个主导属性：**

- 方向按实际情况选正面、负面、正负都有或中性。中性是明确没有褒贬，不等于没评价。
- 正面、负面强度各填一次：0＝没出现该方向；1＝一般表达；2＝明确强烈表达。同方向有多个表达时取最高程度，重复说几次不自动升为2。
- 同一主导属性正负都有，就两边都记。例如，“这家店服务周到，另一家服务敷衍”，服务是同一属性，两边都是一般表达时，正面1、负面1，方向选正负都有。不新增具体店铺记录。
- 评价类别按主导评价单选；哪些类别适用，查本批标签说明。不满足某项填写条件时，用规定的“不适用”，不强行填中性或0。

帖子层的属性集合和情感汇总由程序完成，不再人工填一遍。

### 第五步：留意三种容易混淆的情况

| 容易混淆的地方 | 怎么区分（均为虚构例句） |
|---|---|
| 实用信息与普通事实 | “门票80元”可供别人出行参考，两者都算；“我12点到达”只是自己的经过，不因此标实用参数 |
| 情感描写与简短评价 | “太美了”是评价，不单凭这句话标情感渲染；“红瓦绿树，尽收眼底，很漂亮”有具体画面，两者都算 |
| 操作指导与建议 | “坐地铁后步行200米到入口”有可照做的步骤，但没有劝导措辞；“必去”是建议，但没有操作步骤。“早上去人少”可作选时间的指导，不按明确建议记录 |

第一人称叙述也可以提供实用信息。知识性的事实可以同时属于知识解释；不能把所有事实都标成出行信息。邀请“评论、收藏、转发”等才属于相应互动号召，普通旅行建议不自动算互动。

### 第六步：只摘录需要的原文

- **V6选出主导属性时，必须留一处能支持该判断的原文。** 若同时记录正负方向，证据须覆盖两边。
- **V3、V4、V5的其他选中标签，只有标了疑问时才必须摘录；正常判断可不摘录。** 同一句能支持多个判断时可以共用，不必重复找不同句子。
- 复制最短但意思完整的原文；否定词、程度词和转折会改变意思时一并保留，不改写。
- 不手算文字位置、不写程序格式。摘录或定位入口由负责人发放前说明。

## 四、作者身份怎样填写

这里的KOL型、KOC型是本研究的分组名称，不直接证明作者真的影响了他人或发生过消费。判断只看提供的账号资料，不看其目标帖子用了哪些策略。

**身份按采集阶段判断。** 两人统一使用负责人选定采集阶段留存的账号资料，不追溯每篇帖子发表时的身份，也不另查今天的主页。例如，2025年的帖子所对应账号，在选定2026年采集资料中有8,000粉且明确自称旅行博主，就按采集阶段判KOL型；这不代表它2025年已经是KOL型。此例为虚构教学材料。

同一账号有多份资料时，使用负责人统一指定的一份，不挑粉丝最多的版本，也不混用不同阶段的资料。采集阶段身份确定后，同一轮后续批次继续使用；不因今天主页变了而改答案。

**先确认资料能用：** 账号对应正确，用户名、认证等资料的来源及实际日期或可确认的采集阶段清楚，属于负责人指定的本批资料。先看机构身份，再对个人账号看粉丝和创作者定位。

| 判断顺序 | 结果 |
|---|---|
| 认证明确表明机构身份，或者用户名明确表明账号是机构 | KOL型：`KOL_TYPE`；保留所用认证或用户名证据，注明“机构路径”，不看粉丝门槛 |
| 主体仍不清、所用主体资料不能用，或证据冲突 | 无法判断：`UNK`，写明原因 |
| 明确为非机构多人共用账号 | 不适用：`NA` |
| 个人账号的粉丝缺失、取整跨门槛或时间不适用 | 无法判断：`UNK`，不猜判 |
| 合格个人账号：小红书少于5,000粉／知乎少于10,000粉 | KOC型：`KOC_TYPE`；记规模路径，不必另判消费经验 |
| 个人账号达到上述门槛，已有简介或含义清楚的认证明确表明相关创作者定位 | KOL型：`KOL_TYPE`；留下定位证据与来源 |
| 个人账号达到门槛，但没有明确定位或定位资料不足 | `UNK`；区分“看过但未见”与“资料不足” |

**机构身份看账号本身。** 认证和用户名满足一项即可；“有认证标识”不等于机构认证，未知代码也不能直接使用。用户名须明确表明机构身份，模糊的团队名、地名或单独“官方”二字不够。博主签约MCN、与机构合作或在机构任职，仍按个人账号判断；简介中的机构背景不替代认证或用户名条件。

**机构不需要达到粉丝门槛。** 机构资料合格时，即使低粉或粉丝缺失，也可归KOL型；不用另判个人创作者定位。用户名证据不等于账号已获平台认证。

**创作者定位**用于个人路径，指账号明确说明自己以相关内容创作者身份活动，例如简介自称旅行博主、探店博主。自称不等于平台已认证。“想成为博主”、预备役、单独合作联系方式、来源未核实的博主标签都不足以单独定类。

以下都是虚构教学例子，默认所用资料来源和时间合格：

| 例子 | 怎么填 |
|---|---|
| 用户名“海湾旅行社”，无认证，粉丝200 | KOL型，机构路径，摘录用户名 |
| 用户名是个人昵称，但认证明确为机构账号，粉丝缺失 | KOL型，机构路径，摘录认证原文 |
| 小红书个人博主4,999粉，简介“旅行博主，签约某MCN” | KOC型，个人规模路径；签约不算机构身份 |
| 小红书个人博主5,000粉，简介明确“旅行博主” | KOL型，个人规模＋定位路径 |
| 用户名“海湾旅行”，认证代码含义未知，主体仍不清 | 无法判断，不能仅凭名称猜机构 |

本轮优先小红书，知乎按负责人安排使用；其余平台不自动开展身份判断。兼具型（`HYBRID`）暂不填写，不因博主分享个人经历就判兼具型，也不按专业学历或职业资质重新初判。

保留任务编号、身份结果、必要原文及来源和实际记录时间，在现有理由栏说明所走路径，不额外增加人工表格。机构只需摘录足够支持判断的一项认证或用户名；个人另保留粉丝原值与时间及必要定位证据。机构和个人低粉路径均不补做个人定位判断。不能判断时写明原因。详细情形见[身份操作协议](身份轨试编码操作协议.md)。

## 五、图片怎样填写

只看当前分配的整张图和共同使用的[青岛地标参考清单](../data-dictionary/青岛地标参考清单.md)，可以放大；不裁剪、不拆拼图、不搜索原帖，也不看外部配文或作者资料。图里本来有的文字可以看。本轮两人均为本地人，参考清单只列名称及常用别名；仍要能从画面认出地点，不能只因拍摄地点在清单里就判为标志性场景。

**每张只回答四个问题，每个问题各选一个答案：**

| 问题 | 可选内容及解释 |
|---|---|
| 主要展示什么？（V7） | 自然景观、建筑遗产（也包括现代地标）、人物活动、美食或物产、服务设施 |
| 场景是什么？（V8） | 标志性场景：能用统一参考页确认的地标；日常场景：普通街道、市场或社区；其他或不适用：如食物特写、室内设施 |
| 拍得多近？（V8景别） | 特写：局部细节；中景：主体及近旁环境；全景：大范围空间。这里的“景别”就是画面呈现的范围 |
| 从什么角度拍？（V8视角） | 平视或常规视角；高位俯视：明显从高处向下看；航拍：有显著高空、大范围鸟瞰特征，不要求查拍摄设备 |

先看有无明显突出的主体，再看大致占画面多少，不测量面积。人物很小、只是陪衬时，不因画面有人就选人物；菜品特写选美食，餐厅空间为主体时选服务设施。以建筑为主体且能直接辨认住宿、交通等服务用途时选服务设施；否则按建筑判断。

以下为虚构教学画面：

| 画面描述 | 四个答案 |
|---|---|
| 普通斜侧角度拍一盘海鲜，餐桌只露出一点 | 美食或物产；其他或不适用；特写；平视或常规视角 |
| 参考页可确认的建筑地标是主体，岸上常规高度拍摄，包含大范围海岸 | 建筑遗产；标志性场景；全景；平视或常规视角 |

不认识的建筑不能直接判日常场景；疑似地标而参考页无法确认时，标“待讨论”。高楼向下拍不自动算航拍。地图、文字图和拼图保留任务，各问题分别判断，不能判断的项标“待讨论”，不把所有项一起作废。

本轮不填V9人物细项、V10消费符号、V11可见状态；未启用项保持原样，不填0或“不适用”。正常图片只填四个答案，不逐张写理由、不圈图、不增加图片类型记录。有疑问时用“前景”“右下角”等普通话说明即可。完整选项见[图片上手说明](图片轨试编码上手方案.md)。

## 六、拿不准时怎样处理

“字段”就是页面中一个需要回答的问题。不是每个字段都允许下列所有值，只使用本批说明列出的选项。

| 意思 | 页面可能显示 | 什么时候使用 |
|---|---|---|
| 没有 | `0` | 已看过，问题适用，但没有这个特征；不是没做或不会判 |
| 不适用 | `NA` | 该问题的前提不成立，例如没有属性评价时的后续属性项 |
| 尚未完成 | 答案空白 | 还没有做，不能当作0；未启用项按负责人说明保持原样 |
| 待讨论 | `UNRESOLVED` | 文本或图片试编码中，现有材料和规则无法支持唯一答案；同时标`?`并写一句困难 |
| 身份无法判断 | `UNK` | 只用于作者身份的资料不足或不能定类；文本、图片不使用 |

图片中的“其他或不适用场景”是一个完整场景选项，不等于可以随意把四项都填`NA`。本轮图片拿不准按“待讨论”处理；不要自行增加未提供的选项。

**有较有依据的答案，但仍拿不准：** 先填该答案，标`?`，选原因并写一句说明；有合理的另一答案时一并记录。原因可用“边界难分、上下文不清、证据冲突、材料问题、其他”。文本疑问还要留原文。选不出任何有依据的答案时，再用上表对应的未决状态。

**材料打不开、文字残缺或编号不对应：** 记录编号和问题，告诉负责人后继续下一项，不编造标签，也不自行换材料。下拉选项缺失或与说明冲突时同样报告，不拿别的值顶替。

## 七、怎样提交和讨论

提交前检查四件事：

- 应做的任务已处理，或已报告材料故障；未启用项没有乱填。
- 必须的原文证据、疑问标记和简短说明齐全。
- 没有改变原文、图片或编号，没有看另一人的答案。
- 这是自己的首次独立答案，没有覆盖此前提交。

通过各自账号提交。负责人先保存并锁定两份首次答案——“锁定”就是留住当时版本，之后不能悄悄改成一致。两份答案都保存后，再看分歧、对照原文或图片讨论；有争议的判断由负责人按既定安排处理。

**讨论结果另存，原始答案保留。** 规则有变化时，负责人将同一说明发给两人，并明确哪些旧材料需要重做。第一次讨论主要用来改进说明；不能用已经共同讨论过的答案来证明两人原本就判断一致。

### 研究负责人另做一次检查：标签有没有留下重要差异

**先确定观察哪些方面，结果出来后再概括目的地形象。** 首轮试编码除检查两人是否判断一致，还要检查编码能否支持研究结论。这项工作由研究负责人在首次答案保存后完成，编码员不增加逐帖形象命名、额外标签或说明表。

负责人利用同一批材料，依次核对：

1. 原文中重要的形象特点，现有标签是否保留了线索；两人答案相同的材料也要看。
2. 遗漏是否影响比较创作者的建构策略，而非只是无关细节。
3. 拟写的结论能否回到编码结果和原文找到依据；依据不足时收窄表述，确需修改标签时按既有规则修订并重查受影响材料。

例如，“营造氛围”不直接区分浪漫、热闹或松弛；主导评价也不代表全部评价。不要根据宽泛标签直接给整篇帖子或青岛命名一种形象。具体步骤、虚构例子和处理办法见[编码簿第1.5节](../data-dictionary/编码簿_青岛旅游UGC编码框架.md#image-summary-coverage)。

负责人先收集首轮判断和覆盖检查的反馈，再讨论剩余三项研究取舍；这些问题不增加本轮填写任务。三轨怎样汇合、图文对应能支持什么解释，见[编码簿第1.6节](../data-dictionary/编码簿_青岛旅游UGC编码框架.md#track-roles-post-linkage)；当前讨论顺序见[总备忘录第七节](../planning/研究问题与待办总备忘录.md#research-discussion-current)。
