# 人工编码员操作指南

> **当前使用边界（2026年9月18日）**：通用的人工判断、疑问标记、独立提交和原始答案保留原则继续适用。当前使用数字编码平台，正文中的工作簿/个人文件为旧载体表述；身份例子仅用于历史理解，不生成本轮身份任务或答案。实际启用字段和允许值按核验后的本轮规则快照，未启用不等于NA。平台操作与旧指南同步情况见[总备忘录B06、B15](../planning/研究问题与待办总备忘录.md)。

> 文档状态：`NEEDS_UPDATE`（通用原则可参考；旧载体与身份例子不得作为本轮完整操作说明）
> 内部版本：`v1.2`
> 对齐编码表：整体旧快照为`v3.16.0`；2026年9月22日新增的V4／V6边界说明已核对`v3.18.0`，不代表全文完成对齐
> 更新日期：2026年9月22日

这份指南写给第一次参加本项目的编码员。你不需要先理解论文、统计或模型，只要按固定顺序阅读材料、填写标签和保存个人原始文件。

## 一、先记住八条规则

1. 只使用发给你的个人工作簿，不看另一名编码员的答案。
2. 每个字段都要自己判断；程序不会提示、补值或纠错。
3. 空白表示“还没做”，不表示`0`。
4. `0`表示“这个字段适用，而且检查后没有发现”；`NA`表示“前置条件不成立，所以不适用”；`UNK`表示“本来应该判断，但材料不足”；三者不能混用。
5. 多标签字段可以同时出现多个`1`；父类和子类都要分别判断。
6. 正常判断只填标签值，不需要填写置信度。
7. 如果某个字段确实拿不准，在它旁边的“疑问标记”列填`?`，再选一个原因并写一句说明。
8. 两份个人原始文件都锁定后，才讨论分歧和疑问；锁定前不要交换答案。

## 二、你会看到哪些值

| 值 | 最直白的意思 | 例子 |
|---|---|---|
| `1` | 看到了符合标签的证据 | 片段明确推荐“值得去” |
| `0` | 这个字段适用，但检查后没有看到 | 片段在评价景点，但没有评价交通 |
| `NA` | 这个字段不适用 | V6中`asp_applicable=0`时，其余属性字段不适用 |
| `UNK` | 应该判断，但现有材料不够 | 作者身份材料不足，无法确定最终角色；须以该字段允许的值为准 |
| `UNRESOLVED` | 共同校准时，现行规则本身无法给出唯一答案 | 同一句同时符合两个互斥类别，而编码簿没有裁决规则 |
| 空白 | 还没有完成 | 不能把空白当作任何正式值 |

`UNRESOLVED`只用于共同校准，盲试标开始前必须解决。填写它时必须同时标`?`并写一句说明。

## 三、疑问标记怎么用

疑问标记只是编码员之间锁定后复核的路标，不是研究变量，也不进入论文、Krippendorff's alpha、模型训练或模型输出。

### 判断清楚时

- 填写标签值。
- “疑问标记”“疑问原因”“替代值”“疑问说明”都留空。

### 确实拿不准

1. 仍然先填写当前最可辩护的标签值；如果规则完全无法解决，才填`UNRESOLVED`。
2. 在该字段的`review_flag`列填`?`。
3. 从下面五个原因中选一个：

| 原因代码 | 什么时候用 |
|---|---|
| `BOUNDARY` | 两个标签边界太接近 |
| `CONTEXT` | 必须依赖上下文才能判断 |
| `CONFLICT` | 不同证据互相冲突 |
| `EVIDENCE_MISSING` | 应有材料缺失或看不清 |
| `OTHER` | 以上原因都不合适 |

4. 有合理替代值时填在`alternative_values`，多个值用`|`连接；没有就留空。
5. 用一句话说明难点，不写长篇分析。

示例：当前最可辩护值填`SAT`，疑问标记填`?`，原因填`BOUNDARY`，替代值填`ADM`，说明写“既有明确满意，也有强烈惊叹，主导亚类难以唯一判断。”

客观导入字段和结构性`NA`不要标`?`。正常字段不要为了显得谨慎而全部标问号。

## 四、文本任务怎么做

文本任务按“整篇帖子 → 固定片段”的顺序完成。

### 第一步：做整篇帖子字段

1. 阅读整篇帖子。
2. 完成V1明确商业披露：只有正文明确写出广告、赞助、合作、受邀体验或推广时才记`1`；品牌出现或营销语气不够。
3. 完成V2帖子级字段。系统已经预填的客观信息不要修改；需要人工判断的目的地类型按整篇帖子判断。

### 第二步：逐个`seg_id`做V3—V6

对每个固定片段依次完成：

1. V3内容策略：这段话怎么呈现内容。多个策略可以同时为`1`，父类和子类都要填。
2. V4旅游资源：这段话实际提到了什么资源。事件类还要继续判断事件子类。
3. V5语言功能与情感：信息、评价、建议可以同时存在；再按前置条件判断情感方向和正负强度。
4. V6目的地属性：先判断是否在评价或建议某个属性；若`asp_applicable=0`，其余V6属性字段填`NA`。

不要修改`seg_id`，也不要自行拆分或合并片段。若切分明显有问题，照常完成能完成的字段，再登记`UNITIZATION_PROBLEM`。

#### V4与V6怎么区分：资源对象与评价属性

本说明解释[编码表V4与V6现有规则](../data-dictionary/编码表.md)，不新增标签或改变适用条件。

| 对照项 | V4 目的地资源 | V6 目的地属性指向 |
|---|---|---|
| 要问的问题 | 片段呈现了哪类旅游资源？ | 片段在评价或建议目的地的什么属性？ |
| 判断对象 | 景观、古迹、美食、酒店、活动等资源 | 品质、价格、服务、设施体验、交通便利等属性 |
| 是否需要评价或建议 | 不需要；事实性资源描述也可编码 | 需要，且明确指向目的地属性；先人工判断`asp_applicable` |
| 是否记录褒贬 | 不记录 | 不记录；由同一评价原子片段的V5记录方向与强度 |

按以下顺序检查，不能用一个维度替另一个维度填写：

1. 依据原文判断V4资源类别，不从价格、服务等属性词反推必然存在某个资源类别。
2. 判断是否有明确指向目的地属性的评价或建议。只有事实提及价格、交通或设施时，`asp_applicable=0`，其余V6字段均为`NA`。
3. V6适用时，分别填写属性父类、子类和其他项；按同一固定片段的V5记录评价方向。父子关系与跨维度关系只用于复核，不自动补值。

以下句子为边界教学例，只列本例相关判断，不是完整字段答案：

| 原句 | V4资源判断 | V6属性判断 | V5相关判断 |
|---|---|---|---|
| 这家酒店每晚300元。 | 建筑设施（住宿） | 仅陈述价格；`asp_applicable=0`，其余V6字段`NA` | 信息性陈述；无评价／建议，情感方向`NA` |
| 这家酒店太贵了。 | 建筑设施（住宿） | 适用；消费、服务与设施父类及价格与性价比`asp_pri=1` | 评价性表达，方向为负面 |
| 这家酒店服务很周到。 | 建筑设施（住宿） | 适用；消费、服务与设施父类及服务态度与专业性`asp_ser=1` | 评价性表达，方向为正面 |
| 这份鲅鱼水饺太贵了。 | 饮食文化 | 适用；消费、服务与设施父类及价格与性价比`asp_pri=1` | 评价性表达，方向为负面 |

同一种资源可以被评价不同属性；同一种属性也可以用于不同资源。看到“酒店”不能直接填V6设施体验，看到“价格”不能直接认定存在价格评价。先读完整语义，再独立判断两个维度。

### 第三步：摘录文本证据

V3—V6的实质性阳性判断，原则上复制一段能够支持判断的最短原文。否定、程度或转折会改变意思时，要一起复制。

- 只复制原文，不改写。
- 不需要手算JSON或字符位置。
- 同一句原文在片段里重复出现时，才填写重复证据起点。
- `0`、`UNK`、`NA`和整体排除项不要为了填满表格而伪造证据。

## 五、作者身份任务怎么做

**修订稿、未开放正式任务。** 身份规则已按2026年9月23日决定更新为`role-pilot-v0.4.1-draft`，人数门槛已定（小红书5,000、知乎10,000），身份验证待完成；不使用旧工作簿发包。具体边界与教学检查见[身份轨操作协议](身份轨试编码操作协议.md)和[编码表V0](../data-dictionary/编码表.md)。

专业背景足以支持EA，不要求额外持续专业分析；无背景可由持续专业分析支持。低粉可直接进入KOC规模路径，不据此填写CE阳性；达到平台门槛后，EA=1且CE=0为KOL，EA=0且CE=1为经验路径KOC，两轴为1则HYBRID。高粉不是KOL充分条件，低粉专业作者仍为KOC并保留EA=1。

先记录必要组件及未测状态，再使用合格粉丝快照与统一门槛判断角色和路径；粉丝不得回写组件。EA／CE未测与已测未知分开，高粉必要维度未知则角色未定；主体／粉丝／时间缺失不能猜判。机构和多人账号不适用，内容任务仍看不到身份资料。正式启用前保持未测，不批量填UNK。

身份按作者证据窗口判断一次，不逐片段重复填写。只看既有证据，不补搜资料、不看模型建议，疑问沿用现有单一主表机制。

## 六、图片任务怎么做

图片轨启动后，以单张图片为单位完成V7—V11：

1. V7判断主要可见主体。
2. V8判断场景、景别和视角。
3. V9判断人物数量和人景互动。
4. V10判断品牌、住宿、餐饮和交通消费符号。
5. V11只判断画面中直接可见的设施、卫生、秩序、环境、危险源和防护状态，不推断服务质量、满意度或风险概率。

同一状态轴的正负证据可以同时出现。无相关对象或状态轴没有触发时填`NA`；对象和状态可见、但某个标签不成立时填`0`。确实看不清或规则无法解决时按编码簿使用`UNK`或共同校准期的`UNRESOLVED`，并标`?`说明。

## 七、每批交表前检查

- [ ] 没有查看另一名编码员的答案。
- [ ] 应填写的标签值没有空白。
- [ ] 没有把空白、`0`、`NA`、`UNK`和`UNRESOLVED`混用。
- [ ] 多标签的父类和子类都分别判断了。
- [ ] 所有`UNRESOLVED`都标了`?`并写了原因和一句说明。
- [ ] 其他标`?`的字段也都有原因和一句说明。
- [ ] 没有给客观字段或结构性`NA`加疑问标记。
- [ ] 文本阳性标签按要求摘录了最短充分证据。
- [ ] 没有修改系统字段、原文、`seg_id`或证据材料。
- [ ] 保存的是自己的个人原始文件，没有覆盖旧文件或另一人的文件。

## 八、锁定后怎样校准

1. 负责人先锁定两份个人原始文件并记录文件哈希。
2. 计算一致性时比较全部应编码字段，不只比较标过`?`的字段。
3. 校准讨论优先看实际分歧，再看双方各自的疑问标记。
4. 能用现行规则解决的，记录裁决理由；规则本身有缺口的，进入问题清单。
5. 共同校准允许修改规则，但不计算正式信度。
6. 规则冻结后，用全新样本独立盲试标；首轮完成前继续不交换答案。
7. 金标由完整人工编码、人工裁决和锁定形成；人工期没有系统参与。人工退出后，程序才用于非金标样本。

旧轮次已有的1—5级置信度记录继续作为历史过程资料保存，不删除、不换算成问号，也不与新轮次合并统计。

## 九、遇到问题先查哪里

1. 先看工作簿中的“标签速查”或“标签说明”。
2. 再查[`编码簿`](../data-dictionary/编码簿_青岛旅游UGC编码框架.md)中的对应标签。
3. 仍无法解决时按本指南标`?`；规则无法唯一决定时填`UNRESOLVED`。
4. 不自己发明新标签，不私下改变字段定义。

如本指南与其他材料冲突，以[`编码表`](../data-dictionary/编码表.md) v3.16.0为准。
