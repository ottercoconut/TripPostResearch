## 1. 给工程人员的直接答复

需要的是**可关联到帖文的作者资料快照**，主要包括：平台与作者ID、用户名／页面显示名原文、粉丝数及原始显示、作者资料获取时间、简介与认证原文、个人／机构账号线索、已有历史帖文及其来源。请先检查这些材料是否已经抓取、只是尚未导出；无法从现有留存恢复的部分再列出缺口。

目前不能说“只有小红书、知乎能做，其他平台不能做”。旧切片的标准列中，五个平台都有粉丝数字，小红书、知乎另有主页链接和部分简介；B站、抖音、微博的主页链接、简介和认证字段没有非空记录。9月28日另在8月24日原始快照的嵌套JSON中找到小红书职业标签、认证类型代码及粉丝原始显示，具体见2.1节，不能再把这些字段统一当成尚未抓取。最新库仍未定位，资料存在也不等于身份规则已验证。

**本次先交接材料字段，不让爬虫直接给KOL／KOC／兼具型打标签。** 最新研究意见已取消“专业性作为初判标准”，专业背景只用于“初判兼具型→KOL”的后置裁决；去掉专业性之后的KOL与兼具型初判条件尚待明确。编码表v3.19.1中的旧EA／CE矩阵不能作为这次工程自动分类的依据。持续专业分析也不再作为本次初判必采项。

9月28日用户指出，判断／建议与个人经历都可能出现在KOL与KOC中；这两项表达的身份判据用途已撤回。不得据其存在、频次或占比直接生成作者角色。新发现的职业标签同样不等于专业性或KOL：其自选／认证性质、字段含义和研究用途须分别核对。

粉丝人数线仍为小红书5,000、知乎10,000；等于门槛进入达到门槛分支。其他三个平台尚未制定身份人数线，不套用上述数字。数值冻结不等于身份算法已冻结。

## 3. 需要哪些字段

下表是建议交换字段。允许工程端保留现有命名，但须给出映射；“必备”指结构和状态必须能表达，**不要求把缺失值补造为有值**。建议分为作者快照表、帖文证据表及来源清单；可用现有SQLite、JSON或CSV导出，无须为此重建系统。

不设置“每人必须新抓N条”“必须抓满30天”的任务。持续性及材料时间窗尚未最终冻结，旧3日期／30天检查不能变成补抓配额。身份依据与被比较的V3—V6内容是否重叠，由研究端在证据包中标明；工程端保留帖文ID和来源，支持后续隔离检查即可。

### 3.3 哪些不是爬虫字段

当前机构认证／用户名判断、个人定位和最终身份由研究端按协议人工记录，不要求工程人员凭关键词自动生成。机构路径使用已有理由／证据位置保存判据，不另建人工分类任务。旧“经验分享条件、相关专业背景裁决、兼具型后置转判”等记录设计仅作历史，不作为本轮字段要求；不得复用EA／CE字段承载当前定位或机构判断。

低粉进入KOC规模路径仍须先满足个人旅游UGC纳入及有效粉丝快照条件；不要求因此强行补做经验判断，更不能自动填“有消费经验”。旧V0、EA／CE及原始编码记录不批量转换。点赞、评论、播放、受众画像、粉丝名单和关注关系不列为本次身份资料交接必需字段。

## 4. 工程交付与验收方式

1. **先返回现有资料清单。** 指明最新数据库／导出位置、时间、哈希和字段映射，说明是否另有作者表、抓取响应或日志。先恢复已留存材料，再确定真正缺口。
2. **按平台给出覆盖报告。** 至少包括去重作者数、各字段有值／缺失及原因、粉丝精度与时间可用情况、作者—帖文关联失败数。对照本说明的旧切片结果，但不沿用为最新数字。
3. **提供可复核的派生资料包。** 私有包保留作者与证据关联、版本和来源；公共仓库只存规范、去敏示例与聚合报告。源库只读，不覆盖原始快照；旧数值冲突保留各自时间与来源，不简单取最大数。
4. **将不能从已有资料恢复的字段单列。** 标记“现有可导出／现有留存可恢复／需新增采集／平台可得性未知”。本轮不启动新增采集；若确需补采，先回到研究范围决定，不能将本说明理解成已批准的爬取任务。
5. **通过材料验收后再接分类。** 当前只可实现字段保存、映射、缺失／精度检查和聚合审计；当前分类和采集阶段口径已定；实际阶段及资料版本、材料验收和人工验证未完成前，不发放正式身份任务，不训练身份模型。

待确认项及关闭依据只在总备忘录B02／B06／B15持续更新。本文交付不代表数字平台已修改、最新库已审计或工程人员已收到消息。
