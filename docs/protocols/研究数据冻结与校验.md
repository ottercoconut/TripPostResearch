# 研究数据冻结与校验

> 状态：`research-data-20260912`已退役。操作人认为原协议把冻结写成不可解除，防御性过强；167条无法恢复实名的帖子要从各层删除。派生库已经去掉这些帖并恢复其余作者实名，但那只是 `DERIVED_NOT_FROZEN` 副本。原位删除由 `scripts/cleaning_retire_freeze.py` 执行。命令成功后，Git 登记改为 `RETIRED`，原 manifest SHA 保留为历史。2026年11月5日已在本机运行，登记为 `RETIRED`。
>
> 本协议只定义本地数据保全，不改变编码表、标签、模型、阈值或人工终审要求。操作人可以授权对这一冻结做原位纠错。

## 四层身份不能混用

| 层 | 内容与身份 | 后续规则 |
| --- | --- | --- |
| 原始抓取集 | 独立内容SQLite和全部已下载正文图片，保留两种topic值 | 上游工作库继续可写，归档本身不扩充 |
| 研究输入 | 已用于推理的`topic_relevant=1`快照及原manifest | 与原始归档主题子集逐列、逐行核对，不重新选择人口 |
| 清洗候选 | 全部post的三段动作、空白审核模板、完整批次输入/输出/向量/回执 | 文件冻结不等于人工通过；不原位改标签、回填片段或重跑覆盖 |
| 最终研究集 | 人工审查后的正式keep成员及独立发布manifest | 当前未形成；以后用新产物、新版本另行发布和冻结 |

原始归档复制`web_posts`、`web_post_images`及必要外键父表、迁移记录和详情豁免关系，保留全列原值与ID。它不是采集业务库的完整备份，不复制账号、调度、发现记忆等控制面。源连接使用只读URI、query_only和单一读事务，包含已提交WAL；主文件前后哈希仅是观察值，事务内容由逐表全行摘要绑定。上游工作库与原图片不改权限、不停止抓取、不删记录。

## 文件保全与存储限制

- 原图片以APFS `clonefile`生成独立inode的写时复制副本，不使用硬链接；副本必须匹配快照中的SHA-256。缺失、摘要不符、符号链接、路径越界或克隆不支持均停止，不回退到超大普通复制。
- 数据库中的`local_path`保持不变；离线解析使用`raw-crawl-<date>/media-root / web_post_images.local_path`，不再依赖上游媒体路径。
- 既有研究输入、候选目录、完成轮次及明确绑定的环境证据原位保护，保持旧manifest引用有效。共享编码器、外部历史依赖和未来`final-kept.sqlite`不在保护范围。
- 全文件私有清单记录`path / size_bytes / sha256`；拒绝SQLite旁文件、硬链接、特殊文件及重叠根。文件为`0400`，目录为`0500`，均设macOS `uchg`，清单与manifest本身也保护。
- `uchg`防误写但不是硬件WORM，所有者可以主动撤销。APFS同盘克隆不是异地/灾难恢复备份，本次不声称已解决磁盘损坏或丢失风险。

## 执行与只读验证

入口`scripts/cleaning_freeze_research_data.py`依次调用内容快照、媒体克隆、清洗验收、文件保护与登记模块。准备要求干净且已提交代码，绑定代码SHA和配置SHA；只读重验全部批次、回传向量及引用，不调用模型。

新冻结的准备命令（只运行一次，不对现有ID重做）：

```bash
.venv/bin/python scripts/cleaning_freeze_research_data.py prepare \
  --config configs/cleaning-data-freeze-20260912.json \
  --source-db <SOURCE_SQLITE> --source-root <COLLECTOR_ROOT>
```

`prepare`返回`PREPARED_NOT_YET_FROZEN`和manifest SHA，不能据此报告完成。使用该SHA执行`seal`：

```bash
.venv/bin/python scripts/cleaning_freeze_research_data.py seal \
  --manifest <FREEZE_MANIFEST> --expected-sha256 <MANIFEST_SHA256>
```

`seal`先验全部字节，再保护资产及元数据，再次验字节与保护。全部通过才向`governance/research-data-freezes.json`追加无UGC登记；匹配当前输入与候选时，更新私有`current-freeze.json`与两个可变指针的`data_freeze`字段。清洗状态仍为`CANDIDATES_READY_AWAITING_HUMAN_REVIEW`，恢复推理授权置false。指针不是冻结资产或唯一可信摘要来源。

日常消费前从已审阅的Git登记读取完整SHA，执行只读校验：

```bash
.venv/bin/python scripts/cleaning_freeze_research_data.py verify \
  --manifest <FREEZE_MANIFEST> --expected-sha256 <GIT_REGISTERED_MANIFEST_SHA256>
```

验证不依赖活跃采集库；额外、缺失、改写文件、未合并WAL及保护被撤销均失败。私有manifest的`file_count`不含manifest和清单这两个元数据文件，二者另行校验和保护。Git仅保存程序、配置、汇总、摘要与协议，SQLite、审核CSV、UGC、图片、向量和私有逐文件清单不入Git。

## 失败、人工审查与未来版本

准备失败不登记FROZEN，已生成内容保留供调查，重做用新ID和目录。seal中断可对同一manifest/SHA重试，已有保护幂等保留。seal本身不解除保护、不删帖。同ID不同SHA拒绝登记。原始主题子集与旧输入任何全列不一致均阻止封存，不能把新抓取内容混入已完成推理。

`research-data-20260912`的解除是单独入口，不是seal的副作用，也不是缓存清理。操作人授权后运行：

```bash
.venv/bin/python scripts/cleaning_retire_freeze.py \
  --workspace <仓库根> \
  --manifest data/processed/research-freezes/research-data-20260912/freeze-manifest.json \
  --expected-sha256 <退役前manifest的SHA-256> \
  --post-ids <{"ids":[source_post_id, ...]} 的JSON文件> \
  --replacement raw=<派生raw库> \
  --replacement topic=<派生topic库> \
  --replacement candidates=<派生候选库> \
  --replacement-manifest raw=<revision-manifest.json> \
  --replacement-manifest topic=<revision-manifest.json> \
  --replacement-manifest candidates=<revision-manifest.json> \
  --media-db <仍含目标帖图片路径与正文的只读库> \
  --backup-root <冻结根之外的备份目录> \
  --reason "<退役原因>" \
  --confirm-retire research-data-20260912
```

`--dry-run`只打印计划和计数，不写备份、不改权限、不改原件。写操作的 `--confirm-retire`必须等于 manifest 的 `freeze_id`。命令先校验 manifest 哈希；三个替换清单的状态必须是 `DERIVED_NOT_FROZEN`，其中的输出 SHA 必须与替换文件一致。备份按相对路径复制将被改写或删除的文件，写出 `backup-index.json`（路径、大小、SHA-256），校验通过后才清除 `roots`内文件和目录的 `uchg`，把文件改为 `0600`、目录改为 `0700`。然后用替换文件覆盖 `raw-crawl.sqlite`、`topic-relevant-20260911.sqlite`、`cleaning-candidates.sqlite`，再按文件类型删除目标帖。中途失败可以重跑：已完成的备份不会被后来的内容覆盖。

成功后 `governance/research-data-freezes.json` 中该条 `status` 为 `RETIRED`，并写入 `retired_at_utc`、`retirement_reason` 和删除帖数；原 manifest SHA 保留。`current-freeze.json`、`current-source.json`、`current-cleaning.json` 的冻结引用同步，数据库 SHA 和计数按新文件更新。`verify`见到 `RETIRED` 或 manifest 的 `retired` 块时直接报告已退役，不再按冻结核验字节和保护。要重新封存必须使用新的冻结 ID。

人工审核仍可从空白模板制作独立、可写的工作副本，记录模板SHA、任务ID和审核轮次；私有身份映射独立保管。管理端需区分候选和人工决定层。本次退役不自动开展人工审核、内容编码、片段回填或正式keep发布。

以后若再要纠错，可以授权原位修改，也可以另建数据版本。两种做法都要写明原因。不得把这次退役后的目录重新叫作原来的冻结。内部数据保全不构成第三方UGC/图片公开授权，公开发布仍须通过[发布检查表](../../governance/release-checklist.md)。

## 作者身份派生修订

微博、抖音、知乎历史行曾把 `author_platform_id` 换成 `sha256(str(id).strip())` 的十六进制前 16 位，并把 `author_display_name` 收成脱敏昵称：长度不超过 1 为 `*`，长度为 2 是首字加 `*`，更长则是首字、`***` 与尾字。上游身份库恢复平台原值后，当时的冻结库仍保留旧值。派生修订本身不改冻结文件，不复用冻结 ID，不写入 `governance/research-data-freezes.json`，也不改 `current-*.json`。产物状态保持 `DERIVED_NOT_FROZEN`。操作人随后决定退役 `research-data-20260912`：用下面的派生库替换冻结根里的三份数据库，并删除无法恢复实名的帖子。这一步只走上一节的 `cleaning_retire_freeze.py`。

`scripts/cleaning_derive_author_identity_revision.py` 只读打开来源（`mode=ro&immutable=1`）和身份库（`mode=ro`）。复制使用 `shutil.copyfile`，避免把来源的 `0400` 和 macOS `uchg` 继承到工作副本；副本先改为 `0600`，核对字节与来源一致后，在一个事务内按 `(platform_key, platform_post_id)` 处理仍是旧哈希且昵称为脱敏形态的三平台行。只替换 `author_display_name`、`author_platform_id`，`author_json` 的 `creator_hash` 与 `nickname`，以及 `raw_sample_json` 的 `creator_hash`；微博和抖音另替换 `nickname`，知乎替换 `user_nickname` 并删除残留 `nickname`。`updated_at`、`author_profile_url`、其余列和其余表保持来源原值。身份库没有同帖，或同帖仍是旧哈希和脱敏形态时，默认留下这些行；传入 `--drop-unresolved` 时改为连同关联行删除。新 ID 的哈希与本行旧哈希不一致、JSON 不能按对象解析，或下面任一校验失败时，删除暂存且不产出输出。

校验在副本上完成：`PRAGMA quick_check`、`foreign_key_check`；只读挂上来源后，除 `web_posts` 外各表双向 `EXCEPT` 为空且行数相同；`web_posts` 行数相同，上述四列以外的列相同；JSON 差异只出现在允许的键；每个改动行重算哈希通过；`journal_mode=DELETE` 且没有旁文件。通过后把暂存文件原子改名为输出并设为 `0400`，不设置 `uchg`。manifest 记录修订 ID、原因、`DERIVED_NOT_FROZEN`、时间、代码 commit、来源/身份库/输出的路径与 SHA-256 与大小、分平台 `rows`/`replaced`/`renamed`/`still_masked`/`absent` 和校验结果，不含昵称或平台用户 ID。未替换帖把 `platform_key`、`platform_post_id` 和 `source_post_id`（`web_posts.id`）写入 manifest 同目录的 `unresolved-posts.json`。

`--drop-unresolved` 在上述替换的同一事务内删除 `absent` 和 `still_masked` 行，并删除 `web_post_images`、`post_detail_repair_waivers` 里 `web_post_id` 指向这些帖的行。保留行的 `id` 与非作者列不改。提交后执行 `VACUUM`，再做校验，避免被删正文留在空闲页。不传该参数时不删除、不重建文件，校验和删除计数字段保持上一段。开启后 manifest 增加 `drop_unresolved: true`、`dropped_posts`、`dropped_images`、`dropped_waivers`。校验改为：`web_posts` 行数等于来源减去删除数；保留行的非作者列与来源相同；两张关联表等于来源去掉被删帖的关联行；其余表双向 `EXCEPT` 为空且行数相同；微博、抖音、知乎不再有旧哈希加脱敏昵称的行；完整性、外键和改动行重算哈希仍须通过。

清洗候选和切分库用 `scripts/cleaning_derive_post_exclusion.py`。它读取一个或多个 `unresolved-posts.json`，按可重复的 `--table-column table:column` 只删除命中行，例如 `cleaning_candidates:source_post_id` 与 `text_segments:source_post_id`。安全约束与上面相同：来源 `mode=ro&immutable=1`，`shutil.copyfile` 复制，拒绝旁文件和已存在的输出，运行前后核对来源权限、标志和字节，失败不留产物，输出 `0400`，不设置 `uchg`，不写 `governance/research-data-freezes.json` 和 `current-*.json`。保留行的 `decision`、簇字段和其他列不改。`exact_representative_id` 或其他引用字段指向被删帖时，只记入 manifest 的 `dangling_references`，不改值。`round_metadata` 等未指定的表不改，manifest 写明其中的计数可能仍是删除前的值。删除后 `VACUUM`，并执行 `quick_check` 与 `foreign_key_check`。

```bash
.venv/bin/python scripts/cleaning_derive_author_identity_revision.py \
  --source <FROZEN_SQLITE> \
  --identity-db <IDENTITY_SQLITE> \
  --output <DERIVED_SQLITE> \
  --manifest <DERIVED_MANIFEST> \
  --revision-id <REVISION_ID> \
  --reason "<修订原因>"
```

需要同时去掉无法恢复实名的帖子时，在上面的命令末尾加上 `--drop-unresolved`。

```bash
.venv/bin/python scripts/cleaning_derive_post_exclusion.py \
  --source <CANDIDATES_OR_SEGMENTS_SQLITE> \
  --exclusions <UNRESOLVED_POSTS_JSON> \
  --table-column cleaning_candidates:source_post_id \
  --output <DERIVED_SQLITE> \
  --manifest <DERIVED_MANIFEST> \
  --revision-id <REVISION_ID> \
  --reason "<修订原因>"
```

来源若带 `-wal`、`-shm` 或 `-journal`，输出或 manifest 已存在，或输出与来源、身份库、排除清单同路径，命令直接拒绝。派生产物不是新的冻结版本。把它们写回 `research-data-20260912` 的原路径，只通过 `cleaning_retire_freeze.py`，并且该次运行会把这一身份标成 `RETIRED`，而不是再 seal 成同一个冻结 ID。以后若要重新冻结，另建 ID，再走 prepare/seal。
