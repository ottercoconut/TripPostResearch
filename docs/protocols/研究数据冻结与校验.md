# 研究数据冻结与校验

> 状态：`research-data-20260912`已完成封存；具体数据身份以Git登记、全量字节校验和保护检查为准。
>
> 本协议只定义本地数据保全，不改变编码表、标签、模型、阈值或人工终审要求。

## 四层身份不能混用

| 层 | 内容与身份 | 后续规则 |
| --- | --- | --- |
| 原始抓取集 | 独立内容SQLite和全部已下载正文图片，保留两种topic值 | 上游工作库继续可写，归档本身不扩充 |
| 研究输入 | 已用于推理的`topic_relevant=1`快照及原manifest | 与原始归档主题子集逐列、逐行核对，不重新选择人口 |
| 清洗候选 | 全部post的三段动作、空白审核模板、完整批次输入/输出/向量/回执 | 文件冻结不等于人工通过；不原位改标签、回填片段或重跑覆盖 |
| 最终研究集 | 人工审查后的正式keep成员及独立发布manifest | 当前未形成；以后用新产物、新版本另行发布和冻结 |

原始归档复制`web_posts`、`web_post_images`及必要外键父表、迁移记录和详情豁免关系，保留全列原值与ID。它不是采集业务库的完整备份，不复制账号、调度、发现记忆等控制面。源连接使用只读URI、query_only和单一读事务，包含已提交WAL；主文件前后哈希仅是观察值，事务内容由逐表全行摘要绑定。上游工作库与原图片不改权限、不停止抓取、不删记录。

## 文件保全与存储限制

- 原图片以APFS `clonefile`生成独立inode的写时复制副本，不使用硬链接；副本必须匹配快照中的SHA-256。缺失、摘要不符、符号链接、路径越界或克隆不支持均停止，不回退到超大普通复制。
- 数据库中的`local_path`保持不变；离线解析使用`raw-crawl-<date>/media-root / web_post_images.local_path`，不再依赖上游媒体路径。
- 既有研究输入、候选目录、完成轮次及明确绑定的环境证据原位保护，保持旧manifest引用有效。共享编码器、外部历史依赖和未来`final-kept.sqlite`不在保护范围。
- 全文件私有清单记录`path / size_bytes / sha256`；拒绝SQLite旁文件、硬链接、特殊文件及重叠根。文件为`0400`，目录为`0500`，均设macOS `uchg`，清单与manifest本身也保护。
- `uchg`防误写但不是硬件WORM，所有者可以主动撤销。APFS同盘克隆不是异地/灾难恢复备份，本次不声称已解决磁盘损坏或丢失风险。

## 执行与只读验证

入口`scripts/cleaning_freeze_research_data.py`依次调用内容快照、媒体克隆、清洗验收、文件保护与登记模块。准备要求干净且已提交代码，绑定代码SHA和配置SHA；只读重验全部批次、回传向量及引用，不调用模型。

新冻结的准备命令（只运行一次，不对现有ID重做）：

```bash
.venv/bin/python scripts/cleaning_freeze_research_data.py prepare \
  --config configs/cleaning-data-freeze-20260912.json \
  --source-db <SOURCE_SQLITE> --source-root <COLLECTOR_ROOT>
```

`prepare`返回`PREPARED_NOT_YET_FROZEN`和manifest SHA，不能据此报告完成。使用该SHA执行`seal`：

```bash
.venv/bin/python scripts/cleaning_freeze_research_data.py seal \
  --manifest <FREEZE_MANIFEST> --expected-sha256 <MANIFEST_SHA256>
```

`seal`先验全部字节，再保护资产及元数据，再次验字节与保护。全部通过才向`governance/research-data-freezes.json`追加无UGC登记；匹配当前输入与候选时，更新私有`current-freeze.json`与两个可变指针的`data_freeze`字段。清洗状态仍为`CANDIDATES_READY_AWAITING_HUMAN_REVIEW`，恢复推理授权置false。指针不是冻结资产或唯一可信摘要来源。

日常消费前从已审阅的Git登记读取完整SHA，执行只读校验：

```bash
.venv/bin/python scripts/cleaning_freeze_research_data.py verify \
  --manifest <FREEZE_MANIFEST> --expected-sha256 <GIT_REGISTERED_MANIFEST_SHA256>
```

验证不依赖活跃采集库；额外、缺失、改写文件、未合并WAL及保护被撤销均失败。私有manifest的`file_count`不含manifest和清单这两个元数据文件，二者另行校验和保护。Git仅保存程序、配置、汇总、摘要与协议，SQLite、审核CSV、UGC、图片、向量和私有逐文件清单不入Git。

## 失败、人工审查与未来版本

准备失败不登记FROZEN，已生成内容保留供调查，重做用新ID和目录。seal中断可对同一manifest/SHA重试，已有保护幂等保留，无自动解冻或删除入口。同ID不同SHA拒绝登记。原始主题子集与旧输入任何全列不一致均阻止封存，不能把新抓取内容混入已完成推理。

人工审核从冻结空白模板制作独立、可写的工作副本，记录模板SHA、任务ID和审核轮次；私有身份映射独立保管，不原位填写冻结CSV或候选库。管理端需区分只读候选和人工决定层，本次不自动开展人工审核、内容编码、片段回填或正式keep发布。

后续纠错保留原冻结记录，以新数据版本及明确修订原因派生新产物，不改原候选后复用原ID。内部冻结不构成第三方UGC/图片公开授权，公开发布仍须通过[发布检查表](../../governance/release-checklist.md)。

## 作者身份派生修订

微博、抖音、知乎历史行曾把 `author_platform_id` 换成 `sha256(str(id).strip())` 的十六进制前 16 位，并把 `author_display_name` 收成脱敏昵称：长度不超过 1 为 `*`，长度为 2 是首字加 `*`，更长则是首字、`***` 与尾字。上游身份库恢复平台原值后，研究冻结库仍保留旧值。这类纠错不改原冻结文件，不复用原冻结 ID，不写入 `governance/research-data-freezes.json`，也不改 `current-*.json`。

`scripts/cleaning_derive_author_identity_revision.py` 只读打开来源（`mode=ro&immutable=1`）和身份库（`mode=ro`）。复制使用 `shutil.copyfile`，避免把来源的 `0400` 和 macOS `uchg` 继承到工作副本；副本先改为 `0600`，核对字节与来源一致后，在一个事务内按 `(platform_key, platform_post_id)` 处理仍是旧哈希且昵称为脱敏形态的三平台行。只替换 `author_display_name`、`author_platform_id`，`author_json` 的 `creator_hash` 与 `nickname`，以及 `raw_sample_json` 的 `creator_hash`；微博和抖音另替换 `nickname`，知乎替换 `user_nickname` 并删除残留 `nickname`。`updated_at`、`author_profile_url`、其余列和其余表保持来源原值。身份库没有同帖，或同帖仍是旧哈希和脱敏形态时不改。新 ID 的哈希与本行旧哈希不一致、JSON 不能按对象解析，或下面任一校验失败时，删除暂存且不产出输出。

校验在副本上完成：`PRAGMA quick_check`、`foreign_key_check`；只读挂上来源后，除 `web_posts` 外各表双向 `EXCEPT` 为空且行数相同；`web_posts` 行数相同，上述四列以外的列相同；JSON 差异只出现在允许的键；每个改动行重算哈希通过；`journal_mode=DELETE` 且没有旁文件。通过后把暂存文件原子改名为输出并设为 `0400`，不设置 `uchg`。manifest 记录修订 ID、原因、`DERIVED_NOT_FROZEN`、时间、代码 commit、来源/身份库/输出的路径与 SHA-256 与大小、分平台 `rows`/`replaced`/`renamed`/`still_masked`/`absent` 和校验结果，不含昵称或平台用户 ID。未替换帖只把 `platform_key` 与 `platform_post_id` 写入 manifest 同目录的 `unresolved-posts.json`。

```bash
.venv/bin/python scripts/cleaning_derive_author_identity_revision.py \
  --source <FROZEN_SQLITE> \
  --identity-db <IDENTITY_SQLITE> \
  --output <DERIVED_SQLITE> \
  --manifest <DERIVED_MANIFEST> \
  --revision-id <REVISION_ID> \
  --reason "<修订原因>"
```

来源若带 `-wal` 或 `-shm`，输出或 manifest 已存在，或输出与来源、身份库同路径，命令直接拒绝。派生产物不是新的冻结版本；是否另行封存仍按本协议的 prepare/seal 决定。
