## 1. 先用一分钟了解你要做什么

我们研究旅游帖子中的视觉内容。你的任务是看图片，用统一选项回答“主要展示什么”“场景是什么”“拍得有多近”“从什么角度拍”。这叫图片编码，不需要写程序，也不需要先读懂论文。

本轮只填四个问题：V7视觉主体，以及V8的场景语境、景别、视角。每张图独立判断，做完一张再做下一张。整包有30张，每人都做同一批材料，各自保存答案。

**流程：看说明 → 独立完成第一批15张 → 分别交表 → 负责人保存原始答案 → 集中讨论 → 按统一说明完成第二批15张。**

你不需要把图片另分为“照片、封面、地图、拼图”等类型；也不填写作者身份分类。平台等已有信息由负责人预填。这里不额外增加图片类型字段，不据此改变其他轨道的研究分组。

V9人物呈现、V10消费符号本轮不填；V11可见对象状态待专家评审形成操作说明后另发任务。负责人应隐藏或锁定未启用列，标明“本轮不填”。未启用不等于NA，不需要填0或猜答案。

### 开始前拿到这些材料

- 自己的答案工作簿、第一批图片及任务编号范围。
- 本方案和共同使用的[青岛地标参考清单](../data-dictionary/青岛地标参考清单.md)。
- 交表位置、截止时间和负责人联系方式。

每人只使用自己的答案文件。交表前不看另一人的答案、不讨论具体标签。材料问题可问负责人；规则澄清由负责人同时发给两人。

只看分配的当前图片和共同参考页。可以放大查看，不自行裁剪、拆拼图、修图、搜索原帖或用AI生成答案。图中本来存在的文字可以看，不借外部配文和作者资料推断画面。

## 2. V7主要展示什么

V7每张图选一个主体。表格使用中文选项时直接选择；只接受代码时用下面的对应代码。不要在答案格中填写解释。

| 选项 | 代码 | 普通话理解 |
|---|---|---|
| 自然景观 | VS-NAT | 海、山、天空、植被等自然元素是主体 |
| 建筑遗产 | VS-ARC | 建筑外观、古迹或城市地标是主体，也包括现代地标 |
| 人物活动 | VS-PEO | 人物本身或其活动是主体 |
| 美食或物产 | VS-FOD | 食物、饮品或地方特产是主体 |
| 服务设施 | VS-FAC | 住宿、交通或旅游服务空间和设施是主体 |

### 按这个顺序判断

先看整幅图。明确的特写或突出的前景主体优先；没有明显突出主体时，按大致面积判断，不测量像素。如果突出程度和面积指向不同对象，且看完仍不能确定，标疑问，不自行规定哪个类别永远优先。

**建筑与服务设施：** 先确认建筑或设施是否为主要主体。画面能直接识别住宿、交通或旅游服务用途时选服务设施；否则，以建筑外观为主体时选建筑。酒店大堂、客房、游船是设施；普通建筑立面、古迹或城市地标按建筑判断。背景里的酒店招牌不会让一张人物特写变成设施图。

**美食与服务设施：** 菜品、饮品是主体时选美食；餐厅空间、柜台或就餐设施是主体时选服务设施。桌上有一道菜，不代表整张餐厅全景都属于美食。

**人物与景观：** 人物很小、只是风景陪衬时按景观判断；人物近景或人物活动明显成为画面中心时选人物。不能因为画面有人就选人物。

这些是本轮用于检验的补充边界。发现规则与图片对不上，按第4节记录；负责人负责统一修订，编码员不自行改规则。

## 3. V8依次回答三个问题

三个问题相互独立。例如同一张图可以同时是“标志性场景、全景、航拍”。不要把这三个答案合成一个选项。

### 第一个问题 场景是什么

| 选项和代码 | 怎么判断 |
|---|---|
| 标志性场景 SC-ICO | 画面能通过统一参考页的特征确认是目的地地标或代表性景点 |
| 日常场景 SC-STR | 明确呈现普通街道、市场、社区或市井生活 |
| 其他或不适用 SC-OTH | 美食特写、室内设施，或不能归入前两类的画面 |

先快速查看共同参考页，不自行上网查地名。不认识一处建筑，不能直接把它判为日常场景。如果疑似地标但参考页无法确认，填UNRESOLVED并标?，简写“地标无法确认”；负责人集中核对并向两人补充同一说明。单纯室内或食物特写可正常选SC-OTH，不必标疑问。

### 第二个问题 拍得有多近

| 选项和代码 | 怎么判断 |
|---|---|
| 特写 SS-CLO | 主要展示局部细节，例如一盘菜、脸部或建筑局部 |
| 中景 SS-MID | 主要主体及其近旁环境清晰可见 |
| 全景 SS-PAN | 展示大范围空间，主体融入环境或环境占主要画面 |

看整幅图，不只看有没有远处背景。三者实在分不开时，保留疑问，不需要估算拍摄距离。

### 第三个问题 从什么角度拍

| 选项和代码 | 怎么判断 |
|---|---|
| 平视或常规视角 VP-GRD | 接近普通观看高度，没有明确高处俯看的表现 |
| 高位俯视 VP-HIG | 明显从上向下看，但没有足够的显著高空鸟瞰特征 |
| 航拍 VP-AER | 清楚呈现显著高空、大范围鸟瞰特征；不要求核实拍摄设备 |

高楼向下拍不自动算航拍；看到大片海面也不自动算航拍。高位与航拍仍有两种解释时标?。无法辨认任何拍摄视角的文字图、示意图等，使用未决状态，不强行填平视。

## 4. 不好判断的图片怎样处理

正常图片只填四个答案，不写理由、不逐项打置信度，也不填写图片类型或排除登记表。

**有较有依据的答案，但仍有疑问：** 先选该答案，在对应字段标?，写一句困难。**现有选项无法给出可辩护的答案：** 该字段填UNRESOLVED，同时标?并写短句。UNRESOLVED的意思是“这次还没有解决”，不是新增的正式图片类别。

本轮工作表应明确允许四个字段使用这个临时值。如果下拉框没有该值，联系负责人统一修复，不用其他类别顶替。标签格空白表示还没完成；疑问栏空白表示没有主动疑问。

| 遇到什么 | 你怎么做 |
|---|---|
| 地图、纯文字或复杂拼图 | 保留该任务；逐字段判断，不能判断的字段填UNRESOLVED并标?；能判断的字段照常填 |
| 两个主体无法取舍 | V7标疑问，简写“人物与建筑无法取舍” |
| 某个图像特征看不清 | 先放大；仍不能判断时仅给受影响字段标疑问 |
| 图片突然打不开或编号不对应 | 告诉负责人图片编号，继续下一张；不自行换图，不为技术故障编造标签 |

同类问题反复出现时，可重复用“选项不适用”“地标无法确认”“高位或航拍”这样的短句。只需让负责人知道哪张图、哪个字段有问题，不需要重复长篇解释。多个字段可在本行共用一条说明，但要写出涉及的字段名。

整幅图片就是判断材料。本轮不要求逐张摘录证据、不圈画区域、不生成坐标或填写JSON；只有确实需要解释疑问时，写“右下角”“前景”等普通位置描述。

负责人会在讨论后统一处理这些问题。编码员保留原图和编号，不删任务、不替补、不为凑齐类别强行判断。

## 5. 用四个例子练习填写

以下是虚构画面描述，用于示范填写方式，不是实际样本答案。真实编码以看到的图片为准。

### 例子一 菜品特写

画面主要是一盘海鲜，餐桌只露出很小一部分，从普通斜侧角度拍摄，没有地标环境。

填写：V7选美食VS-FOD；场景选其他SC-OTH；景别选特写SS-CLO；视角选常规VP-GRD。四项均有依据，疑问栏留空。不判断好不好吃或价格高低。

### 例子二 海边地标全景

画面以统一参考页可确认的建筑地标为主要主体，包含大范围海岸环境；从岸上常规高度拍摄，远处人物很小。

填写：V7选建筑VS-ARC；场景选标志性SC-ICO；景别选全景SS-PAN；视角选常规VP-GRD。画面有人，不等于人物是主要主体。

### 例子三 酒店大堂

画面中酒店接待台、休息区及空间布局清楚，大堂占据整幅画面，从入口普通高度拍摄。

填写：V7选设施VS-FAC；场景选其他SC-OTH；景别选全景SS-PAN；视角选常规VP-GRD。全景也可以是室内大范围空间，不只用于室外风景。

### 例子四 两种主体一样突出

拼图中左边是人物近景，右边是餐厅空间，两部分大小相近，没有明确主次。

V7填UNRESOLVED并标?，说明“人物与设施无主次”。V8三个字段分别判断；如果整幅拼图也无法归为一个景别，只给景别使用未决状态。不要因为V7未决，就把整张图的所有答案都设为未决；也不要自行拆成两张图。

这些例子只演示规则。第一批讨论后，负责人可从已经讨论的图片中选少量实例，补成共同例图页；第二批答案不提前展示。

## 6. 交表与讨论

### 交表前检查一次

- 本批图片都已处理，V7和V8四个启用字段都有答案，或已报告技术故障。
- 每个UNRESOLVED都有?和简短说明；正常答案不必写理由。
- 图片编号、已有材料与版本没有被修改，没有看另一人的答案。
- V9、V10和V11的未启用列保持原样，没有自行填0或NA。

将自己的文件另存为一个新的提交副本，交到指定位置。命名示例：图片_第1批_编码员A_20260907_首次提交.xlsx。不要覆盖以前交过的文件。

同时发一条短消息即可：“编码员A，图片第1批，已处理15张；打不开的编号：无。”如有技术故障，换成实际编号。无需逐张计时、填写独立疑问表或汇总排除原因。

### 负责人保存两份原始答案后再讨论

负责人先保存A、B两个独立原始文件，之后才展示差异。讨论只看不同答案和已有疑问，不要求逐张朗读全部判断理由。

每个问题按“看原图 → 指出困难 → 对照规则 → 写清解决办法”的顺序处理。能解决的用一句话更新共同说明；涉及反复出现的概念边界或实质规则修改，按项目既有裁决安排交第三人处理。

编码员不把原始答案改成一致。负责人另行保存讨论结果，第二批开始前同时发出统一说明。暂时没解决的问题继续保留，不要求编码员自行补查或反复解释。

V11由研究团队组织专家评审，编码员等收到专门说明和启用通知后再开始。其后是否使用本轮图片由负责人安排，不自动增加本轮工作。

## 7. 负责人怎样准备这30张

本节由研究负责人执行。编码员只负责看图、填值和标疑问。

| 材料组成 | 数量 | 准备办法 |
|---|---|---|
| 常规材料 | 25张 | 小红书、知乎、B站、抖音、微博各5张；在可用帖子中随机选取，尽量不同作者、不同帖子 |
| 边界材料 | 5张 | 从现有材料中补入主体竞争、建筑或设施、高位或航拍等情况；不强求五平台各一张 |
| 第一批 | 15张 | 每平台2张常规图，共10张，加5张边界图 |
| 第二批 | 15张 | 每平台剩余3张常规图，在第一批讨论后按统一说明独立填写 |

**统一取图：** 本轮每帖取首张静态视觉材料；图文帖取首图，视频帖取可稳定复现的封面，不进行视频抽帧。这是取图位置规则，不要求人工另分图片类型。负责人发包前须记录本轮来源、取图办法及版本，避免编码员自由选择。

**先做技术检查：** 图片须可打开、编号一一对应，两个编码员获得相同图片。下载或读取失败由负责人处理，在可用帖子中补足；保留工具已有日志或简要技术记录，不让编码员逐张登记。不能以“没有下载到”概括该平台所有图片。

**保留难图：** 纯文字、地图和复杂拼图不因难编码而直接删除或替补，也不新增图片类型列。选项不适用由编码员在现有疑问栏反映。本轮不据此产生正式平台差异结果。

**准备最少的辅助材料：** 一份本方案、一份供两人共用的[青岛地标参考清单](../data-dictionary/青岛地标参考清单.md)、各自独立的答案记录。按2026年10月1日用户决定，两位编码员均为本地人，本轮参考页只列名称及常用别名，不要求配图或逐项写辨认特征，也不要求自行搜索。仍须从当前画面认出相应地点；清单中有该名称，不代表在该地点拍摄的所有图片都属于标志性场景。拿不准时沿用本方案的疑问处理。实际样本答案不在独立填写前展示。

负责人在已有批次清单中保留图片编号、平台、来源关联、抽样种子和文件哈希；常规与边界抽取方式由负责人记录，编码员无需填写。2026年10月1日用户确认材料和平台准备无问题，共用名称清单已整理；本次文档更新未生成图片包或实际编码答案。

## 8. 负责人怎样控制工作量与规则版本

本轮30张的目的，是检查V7和V8能否按说明操作。原计划60张共同校准并不作为这次操作试验的默认工作量；30张完成不代表整个视觉轨已经校准完成。

先完成两批。若仍有反复出现且无法解决的某一种边界，只针对该问题追加5—10张，不重新扩充全部类型，也不预先安排追加量。只补充不改变判断边界的说明时，原始答案照常保留；实质改变选项、纳入标准或判断边界时，由负责人登记影响范围并决定哪些任务需要重做。

**本轮过程记录保持最少：** 编码员正常只填四个值；疑问才用?加短句。负责人沿用现有问题清单，只记图片编号、字段、主要分歧和处理结论；无需新增图片类型表、排除登记表或每图计时表。

本方案以v3.16.0的V7、V8字段和代码为基础，新增了本轮主体优先顺序、服务用途边界、地标共同参考页及四字段临时未决值的操作要求。这些补充属于本次讨论确定的试验规则，不能仅凭基础版本号就声称与旧文件完全一致。发包前，负责人须将其同步到工作表允许值与本轮规则快照；涉及正式编码表定义或值域变化时，按现有版本流程同步最高标准、编码簿和指南。

发包清单须明确“本轮只启用V7和V8”。V9、V10保留后续任务安排，V11等待专家评审形成统一说明。本轮不安排正式信度计算和图文对应分析，也不宣布这些后续问题已经解决。
