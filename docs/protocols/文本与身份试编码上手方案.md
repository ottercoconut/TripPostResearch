## 1. 先用一分钟了解你要做什么

我们要把旅游帖子中的内容，以及作者资料中能够观察到的特征，按统一规则记入表格。这项工作叫“编码”。你不需要写程序，也不需要先读懂论文。

你会做两种任务：

| 任务 | 你阅读什么 | 你回答什么 |
|---|---|---|
| 文本任务 | 一篇帖子的文字，以及已经分好的句子或短段 | 作者怎样表达？提到了什么？是在介绍、评价还是建议？具体评价了哪方面？ |
| 作者身份任务 | 同一个账号的固定主页资料和历史内容 | 这些材料能支持怎样的作者角色判断？哪些地方仍然无法确定？ |

这次先小批试做，再讨论遇到的困难，用来检查说明是否清楚、材料是否够用。发现规则有问题是有用的反馈，不需要为了“交出正确答案”而猜研究者想看到什么。

**整个过程：读说明 → 各自填写同一批材料 → 分别交表 → 负责人保存原始答案 → 一起讨论 → 再做下一批。**

## 2. 开始前，拿到自己的材料

负责人应分别发给编码员A和B：

1. 本方案。
2. 自己的文本工作簿和本批任务范围。
3. 自己的作者身份工作簿，以及与之对应的作者证据包；身份批次开始时再发。
4. [编码簿](../data-dictionary/编码簿_青岛旅游UGC编码框架.md)，供遇到具体标签时查阅。
5. 交表位置、负责人联系方式、截止时间，以及本批允许使用的材料清单。

先检查工作簿注明的编码表版本是否为 **v3.16.0**，能否看到“有疑问填?”或含义相同的列。若表格仍要求逐项填1—5级置信度，或只有空表、没有对应材料，先联系负责人处理。

每人只打开自己的答案文件。可以询问负责人“材料打不开”“这一列在哪里”等操作问题；本批交表并保存前，不与另一位编码员讨论具体标签。负责人若要澄清规则，应把同一条说明同时发给两个人。

只使用发下来的材料，不自行搜索作者主页、补找帖子或用AI生成答案。文件只保存在负责人指定的位置。

## 3. 先认清表格里的三类内容

| 表格内容 | 你怎么处理 |
|---|---|
| 已有材料：原文、任务编号、帖子编号、片段编号、版本、允许填写的值 | 阅读和核对，保持原样；发现错误告诉负责人 |
| 需要判断的内容：标签值、对应的原文证据或证据编号 | 按规则填写；需要人工判断的父类和子类都要填 |
| 疑问记录：问号、原因、简短说明、备选答案 | 只有拿不准时才填写；没有疑问就留空 |

“字段”就是一个需要回答的问题。“父类”是大类，“子类”是它下面的具体类别。例如，“自然旅游资源”是大类，“水域风光”是具体类别。表格同时要求它们时，两项都由你判断，不能只填小类、把大类空着。

文本工作簿可能是一条判断占一行：同一段原文会重复出现多行，因为每行问的问题不同。请看“中文标签”和“允许填写的值”，不要把重复显示的原文当成重复任务删掉。另一些表格把同一片段的多个问题排在一行，填写原则相同。

### 常见答案是什么意思

| 答案 | 意思 | 注意 |
|---|---|---|
| `1` | 有符合标签定义的证据 | 多个可共现标签可以同时为1 |
| `0` | 这个问题适用，检查后没有发现该特征 | 不表示“没来得及看”或“资料不够” |
| `NA` | 前面的条件没成立，这个问题不适用 | 例如没有目的地属性评价或建议时，其余属性标签按规则填NA |
| `UNK` | 这个问题应该判断，但材料不足以作出判断 | 只在该字段允许时使用 |
| `UNRESOLVED` | 试编码时，规则本身不能支持唯一答案 | 文本共同校准按允许值使用，同时标?并说明；不要写入未允许此值的身份字段 |
| 标签值空白 | 还没有完成 | 与“疑问标记列空白”不同；后者表示没有主动疑问 |

不是所有字段都能填以上全部答案。单选题按工作表给出的选项填写；不要把中文解释随意写进只接受代码的标签格，也不要自行增加“其他”“不确定”等选项。

## 4. 文本任务：完整做完一篇，再做下一篇

### 第一步：先读完整帖子

先了解它在讲什么，再完成整篇帖子的问题：

- 是否明确写了广告、赞助、合作、受邀体验或推广等商业披露。出现品牌名、语气像广告，本身不够。
- 完成工作表要求人工判断的帖子信息，例如目的地类型。已有的客观信息保持原样。

不要根据作者名、粉丝量或你对该作者的印象判断文本。

### 第二步：对每个固定片段回答四组问题

“片段”就是已经分好的句子或短段，编号通常显示为`seg_id`。先读当前片段，必要时回看整篇文字理解指代，再依次判断：

| 顺序 | 表中编号 | 用普通话理解这个问题 | 怎么填 |
|---|---|---|---|
| 1 | V3 内容策略 | 作者用什么方式讲这件事？ | 对照信息提供、知识解释、情感渲染、互动等定义，逐项判断大类和小类 |
| 2 | V4 旅游资源 | 文字实际提到了什么？ | 如海景、建筑、饮食、活动；符合多个标签时可同时填写，事件类继续判断具体事件子类 |
| 3 | V5 语言与情感 | 是介绍事实、表达评价，还是提出建议？态度和强度怎样？ | 信息、评价、建议可以共现；再按条件填写评价亚类、方向和正负强度 |
| 4 | V6 属性指向 | 具体在评价或建议哪方面？ | 先判断是否适用，再看景观品质、价格、服务、交通、卫生等属性 |

旅游资源和属性指向是两件事：提到地铁站，可以是资源信息；说“换乘很方便”，才是在评价交通便利性。不能因为出现价格、交通或卫生相关词，就直接认定存在属性评价。

V5要特别注意：

- 没有评价或建议时，不能为了填满表格而给出正负态度；按规则填写情感可判定状态和NA。
- “无法判定”不等于“中性”。中性用于确实表达无褒贬立场的评价或建议。
- 正面强度和负面强度分别判断。`0`是没有该方向，`1`是一般强度，`2`是有明确强烈表达；不是1—5级置信度评分。
- 普通评价可能容易判断正负，却难以选出“赞赏”“满意”等亚类。先查定义，仍无法唯一判断时记录具体疑问，不必硬选最像的一个。

V6先填“是否适用”。若不适用，其余V6属性字段按规则填`NA`；若适用，再对各属性逐项填`1`或`0`。

### 第三步：复制支持判断的原文

对实质性的阳性判断，原则上复制一段能说明理由的最短原文，放入对应证据位置。可以用同一段证据支持有关联的大类和小类。

例如原文是“并没有想象中那么干净”，不能只复制“干净”，因为这样会丢掉否定。证据保留原字句，不改成自己的总结。记录`0`、`UNK`、`NA`或整体排除项时，不要编造局部证据来填满表格。

不用写程序、JSON或手算字符位置。若同样的证据在片段中出现多次，按表中说明标明位置；不会定位时联系负责人，不随便填一个数字。

### 一个练习例子

以下均为虚构教学文字，不来自待编码样本；这里只演示部分字段，不代表该片段全部字段已完成。

> 原文：“门票80元。”

| 正在回答的问题 | 示例填写 | 为什么 |
|---|---|---|
| 有没有信息性陈述？ | `1` | 给出了一个可判断真假的价格信息 |
| 有没有评价？ | `0` | 没有说贵、便宜或值得 |
| 有没有建议？ | `0` | 没有建议读者采取行动 |
| 情感方向是否可判定？ | `0` | 这里没有评价或建议；情感方向及两项强度填NA |
| 有没有适用的目的地属性评价或建议？ | `0` | 提到票价不等于评价价格；其余V6字段填NA |

你是在记录作者表达了什么，不需要上网核对实际票价。

### 发现片段切得不合适怎么办

例如“景色很美，但厕所很脏”仍被放在同一个片段里，涉及不同属性和相反方向。不要自己拆成两行，也不要直接用一个“混合情感”掩盖问题。

保持原文和编号不变，先完成能判断的字段，登记“切分问题”（`UNITIZATION_PROBLEM`），写“景色与厕所卫生应分别判断，现有片段混在一起”。受影响字段按允许的未决状态及疑问规则处理。负责人统一解决，后续两人使用同一份片段材料。

## 5. 作者身份任务：按当前执行协议判断

按[身份轨试编码操作协议](身份轨试编码操作协议.md)的`role-positioning-20260930`执行：核对主体及有效粉丝快照，低于小红书5,000／知乎10,000门槛走KOC规模路径；达到门槛且有明确相关创作者定位判KOL。定位未见或材料不足记`UNK`并说明；机构／多人账号记`NA`。兼具型保留但本轮不赋值，不再使用EA／CE初判矩阵。

定位依据使用已有简介及含义清楚的创作者认证。愿望、预备役、单独合作联系方式或来源未核实的标签不能独立满足条件；不根据目标帖策略和个人经历判断身份。具体顺序、证据记录和例子统一查身份协议。

本轮为更新执行文档，未自动发放身份任务或恢复旧25／50名配额。负责人安排材料与记录载体后按协议开展小批试编码；正式标签及模型仍需独立验证。旧Word、Excel和组件字段不能代替新规则记录。

## 6. 拿不准时，用一句话留下问题

先区分两种情况：有一个相对有依据的答案，就先填该答案并标`?`；材料缺失或规则不能解决，则使用该字段允许的未知或未决状态，并记录需要复核的原因。

| 你遇到的问题 | 文本表中的原因选项 | 一句说明示例 |
|---|---|---|
| 两个标签边界不清 | `BOUNDARY` | “这里的‘可以去’是在介绍选择，还是提出建议？” |
| 需要借前后文才能理解 | `CONTEXT` | “本句只说‘很方便’，交通对象在上一句。” |
| 材料之间有矛盾 | `CONFLICT` | “两条资料对账号的运营主体描述不同。” |
| 应有资料缺失 | `EVIDENCE_MISSING` | “只有一篇历史帖，无法判断重复消费经历。” |
| 其他问题 | `OTHER` | 直接写清具体困难 |

文本表：在对应字段标`?`，选择原因，写一句说明；有合理备选答案时再填备选值，没有就留空。

身份表：在对应判断旁标`?`，在本行“疑问说明”中写出**字段名或中文问题＋困难**。若几项都有疑问，分别用短句说明，不只写“资料不足”。身份表没有文本表的独立原因列时，不用自己加列。

正常判断不用标问号。客观导入字段和结构性`NA`不标问号；若怀疑这些材料或前置条件有错误，单独报告负责人。问号不能代替标签值。

## 7. 交表与讨论

### 交表前，自己检查一次

- 本批分配的所有帖子、片段或作者都已经处理；需要填写的标签没有遗漏。
- 父类和子类分别填写，条件不适用时按规则填写NA。
- 每个问号都有简短说明；文本问号有原因，文本UNRESOLVED有问号。
- 已按规则记录原文证据或作者证据编号。
- 原文、编号、版本和材料没有被改动，没有看另一人的答案。

将自己的文件保存为一个新的提交副本，按负责人指定的位置交回。命名示例：`文本_第1批_编码员A_20260906_首次提交.xlsx`。该名称仅是个人交表副本示例，不要求重命名项目固定模板。

同时发给负责人一条简短记录：

> 编码员A；文本第1批；完成__篇／__片段；阅读及填写__分钟，查规则__分钟；未完成或打不开的任务编号：__。

身份任务把篇数、片段数换成作者数。记录实际工作时间即可，不把中途休息算进去，也不需要为每个字段计时。

### 两人交表后再讨论

负责人先把两份原始文件保存成不再覆盖的版本，这就是“锁定”。之后才能查看彼此答案。

讨论按“哪一处原文或哪条证据 → 两人各自怎样理解规则 → 规则能否解决”的顺序进行。先看实际分歧，再看双方疑问；没有问号的字段也可能存在分歧。

不要直接把原始答案改成一致。讨论结果由负责人另行记录。涉及最终角色、反复出现的概念边界或规则修改的分歧，按现行规范交第三人裁决；暂时没有裁决结果时保留未决，不强行达成一致。

这轮共同试做不计算正式信度。规则确定后，负责人会另发没有讨论过的新材料，两人独立完成，那一轮才检验不同编码员能否稳定使用规则。

## 8. 负责人执行页：怎样把第一轮安排起来

本节由负责人使用，编码员不用承担抽样、文件哈希、统计和版本管理工作。文本安排继续按其自身条件推进；身份按当前协议准备材料、落实记录载体并安排小批试编码；本次文档更新本身不发放任务。

### 发材料前完成四件事

1. **确认两份表可实际填写。** 用v3.16.0契约准备A、B各自的材料和空白答案；明确版本、批次、任务范围及提交位置。不要把历史v3.13.0双任务包整体改名后直接发出，也不要把本方案当作已经生成任务包的证明。
2. **文本先核对片段。** 检查首批长句中的属性、方向切换，确认两人获得同一组固定片段。需要修订切分时先完成统一处理并保留原快照，再发受影响批次。
3. **身份使用既有材料安排试编码。** 按身份协议核查主体、粉丝、原始显示和时间证据，覆盖低粉、高粉且定位明确、高粉但定位未见／不清及缺失／跨界案例。人数门槛已定，负责人落实材料与记录载体后安排小批试编码；独立验证前不发放正式身份任务。旧25名及每名最多5篇不自动恢复，不按期望角色凑组。
4. **确认问题和裁决由谁处理。** 明确负责人，以及现行规范要求的第三人裁决安排；若尚未落实，可以先小批发现问题，但不能把未裁决内容宣布为正式金标。材料读取问题由负责人处理，不让编码员自行补搜。图片任务本次不发。

最低材料可用门只决定能否进入身份试点；实际角色须按规模与创作者定位规则判断，不能因材料存在就预填身份。

### 推荐分批顺序

以下是上手安排，按真实耗时调整；不是每人每天必须完成的定额。

| 阶段 | 建议安排 | 本阶段交付 |
|---|---|---|
| 入门讲解 | 约20—30分钟，使用本方案虚构例句演示查标签、填值、摘证据、标疑问 | 两人能各自找到并填写相应位置；不展示待独立判断样本的参考答案 |
| 文本首批 | 从计划内材料选3—5篇，尽量合计约30—50个片段；达不到篇数与片段数同时满足时，以实际可完成的片段量控制首批 | 两份独立答案、个人用时、主要困难 |
| 首批讨论 | 两份文件锁定后安排约30—45分钟，优先处理信息／建议边界、评价亚类和切分问题 | 一份问题记录和下一批生效说明；没解决的问题继续保留 |
| 身份准备 | 核对既有材料与当前执行规则，不自动启动旧首批；后续校准量根据边界覆盖和实际耗时论证 | 来源、时间及字段缺口，阈值待验证事项 |
| 文本分批继续 | 根据真实耗时安排余量，完成25篇文本共同校准；不等待身份轨 | 全部原始记录、疑问与分歧、规则修订记录 |

首批就是总校准任务的一部分，不另加一套样本配额。文本工作量按片段看，不能只按帖子篇数估计。若一天无法完成，记录实际进度并接着做，不通过省略字段赶量。

负责人讨论时可沿用现有问题清单，仅记录：任务／片段编号、字段、双方理由、问题属于规则还是材料、处理结果、哪些任务需要重做。保留每批规则快照、原始文件和哈希；不要给编码员增加一份重复填写的行政表。

### 什么时候进入下一阶段

共同校准要产出可执行的判断规则和明确的材料处理办法。文本规则冻结后按原计划另取80篇新文本盲试；V0须完成分平台门槛与材料验证，再安排未讨论作者的独立验证，旧50名不自动恢复。逐字段检查信度、类别支持与系统分歧；共同讨论过的答案不能冒充独立信度。

上述安排不承诺金标已足够启动模型训练。先用真实人工速度判断产能，再安排正式标注；不得把代码测试通过、模板能打开或AI试填结果当作人工试编码通过。
