## 1. 使用什么材料

身份辅助比较目的地形象建构策略。观察单位为“平台账号×选定采集阶段”，同一阶段同一账号只判一次，关联其研究期帖子；不逐篇追溯发帖时身份。规则适用于小红书、知乎、抖音、微博、B站，实际任务仍以负责人发放的材料为准。身份任务覆盖文本样本作者与图片样本发布账号，合并去重后统一判定，结果两轨共用。

**发放顺序：先文本、后身份（2026年10月10日确定）。** 同一组编码员在本批文本及图片任务的首次答案提交并锁定后，才领取身份任务；文本、图片任务中不显示身份资料，已提交的内容答案不因随后看到身份资料而修改。身份材料未齐时不要求文本或图片等待。

**定向边界账号（2026年10月10日确定）：** 试编码另由研究负责人从研究库中定向选取约10个边界账号，与随机关联的账号混合发放，编码员不被告知哪些是定向账号。优先覆盖：低粉或缺粉机构、仅用户名成立的机构、仅认证成立的机构、签约MCN的个人、高粉但定位未见的个人、低粉但定位明确的个人、定位与粉丝分别缺失的个人、主体模糊或资料冲突的账号，并尽量分布到不同平台。定向账号在记录中单独标记，只用于检验规则是否清楚，不计入身份分布、组别人数或组间比较，也不作为抽样代表性证据。

两人使用负责人统一选定的已有账号资料，包括用户名、认证、简介、主体线索、粉丝原值、来源及实际记录时间或可确认的采集阶段。不补采实时主页，不用目标帖的策略、情感、经历或互动量判身份；内容编码员不查看身份证据。

采用采集阶段身份，资料可以晚于帖子发布时间。负责人统一指定阶段及同一账号多份资料的选用口径；不挑较大粉丝值、不混用阶段、不随今天主页变化更新身份。保留实际时间；只能确认阶段时如实记录，不用帖子日期、导出日期或编码日期冒充资料日期。

## 2. 按这个顺序判断

### 第一步：判断账号主体

认证或用户名明确表明机构主体，任一成立即可；机构包括文旅部门、景区、媒体及企业自身账号，不设粉丝门槛。只凭名称认定不写成已获平台认证。签约MCN、合作或任职不使个人变为机构；模糊名称、单独“官方”字样或未知认证代码不足以猜判。主体不清、冲突与明确非机构多人共用分别记录，不依据目标帖内容或粉丝量反推主体。

### 第二步：所有个人账号都判断公开定位

所有可确认个人账号都判断相关公开定位，粉丝数独立记录，不再以低于门槛直接认定“普通个人”。`creator_positioning`填写`CLEAR`（明确相关定位）、`NOT_SEEN`（资料充分且核查未见）、`UNK`（资料不足或冲突）；已确认机构或非机构多人共用账号用`NA`，未判断留空。主体未明时定位记`UNK`并留原因。明确提供户外攻略、旅行路线等内容可支持定位，不要求逐字自称“博主”；单纯旅游爱好、合作联系方式或未知来源职业标签不足以独立支持。粉丝真实0保留，缺失不补0，粉丝缺失不抹去可判定位。

| 情形（自拟例子） | 定位记录 |
|---|---|
| 简介明确“户外攻略与旅行路线分享”，700粉 | `CLEAR`；另记700粉 |
| 简介“旅行博主”，4,999或5,000粉 | 都是`CLEAR`；各保留原数值 |
| 可用资料已核查，仅写“喜欢旅游，记录生活” | `NOT_SEEN`；不意味着现实中不是创作者 |
| 简介显示“来源未提供”，不能确认实际为空 | `UNK`；写明资料缺口 |
| 简介明确“旅行UP主”，粉丝缺失 | `CLEAR`；规模缺失另记 |

`CLEAR`保留充分原文证据；`NOT_SEEN`记录实际核查的资料范围；`UNK`记录缺口或冲突。来源明确显示简介为空且其他应提供资料已核查，可判`NOT_SEEN`；数据库空值或未提取不能当作明确未见。自述与平台认证分别记录，多个兴趣不自动否定明确的相关内容定位。

### 第三步：记录粉丝原值

记录`follower_count`、原始显示、精度、来源和实际日期／阶段。“万”等按单位换算，不做百位取整，不取多个阶段最大值；缺失和真实0分开。记录顺序不表示界面已实现粉丝遮蔽。

### 第四步：保存独立记录，不强填最终角色

主体、`creator_positioning`和粉丝数分别保存。新版最终比较分组尚未确定，不填写或自动派生新的`creator_role_manual`／`creator_role`，也不以`UNK`／`NA`代替“分析分组尚未确定”。不把定位塞入EA／CE或旧角色字段。若平台仍在低粉时隐藏定位、强制选择旧角色，须先按工程交接说明承接新版任务；不得仅修改版本号继续发放。

机构内部子类仍是已确认但尚未启用的辅助设计，判据见[编码表](../data-dictionary/编码表.md#institutional-subtypes-20261021)；此次不自动增设子类任务。

## 3. 旧门槛与旧答案如何处理

小红书5,000、知乎10,000、抖音2,600、微博4,600、B站500保留为历史规则及来源，不再决定新版定位或“普通个人”身份。没有采用新的数值门槛；规模是否分档、分几组或连续分析，留待正式比较方案确定。既有计算及来源见[修订决定](../decisions/2026-09-23-粉丝规模参与身份界定修订决定.md)和[探索notebook](../../notebooks/01_follower_thresholds_ugc_20261008.ipynb)。

旧`KOC_TYPE`不能自动映射成`NOT_SEEN`；旧`KOL_INDIV_TYPE`也须核查其证据与资料版本后才能补充`CLEAR`。旧双人答案、裁决、任务版本及原始数值保留，以新版规则另存重审记录，不覆盖源库或原始答案。

## 4. 保存、讨论与后续处理

保存作者任务与证据窗口、主体、定位、粉丝原值、证据／原因、来源、实际日期或阶段及规则版本；可识别材料留在受限记录。两人独立作答并锁定原始答案，讨论裁决另存。每个字段可判性独立记录，不因粉丝缺失把整位作者都归未知。

随机账号用于了解可判情况；约10个定向边界账号只检查规则，不计入总体身份分布或组间比较。校准后独立验证使用未讨论账号。正式比较前确定分组及缺失处理，结合分平台独立账号数与资料支持，不以获得显著差异为目的调整分组。规则确认不等于平台上线、金标、信度或模型验收；研究与工程待办统一见[总备忘录B02／B06／B08／B15](../planning/研究问题与待办总备忘录.md)。
