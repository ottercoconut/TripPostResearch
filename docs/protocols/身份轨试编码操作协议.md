## 1. 使用什么材料

身份用于辅助比较目的地形象建构策略，不单独追求完整的现实身份画像。一项任务对应“平台账号×选定采集阶段”，同一阶段的同一账号只判一次，并关联其纳入研究期的帖子；不逐篇追溯发帖时身份。既有证据窗口记录用于标明本批选定采集资料。

只用负责人提供的已有账号资料：用户名（页面显示名）、认证原文及其含义、主体信息、作者简介、已有粉丝原值、实际资料记录时间和来源编号。不自行搜索实时主页、补采帖子或用模型生成答案；不根据目标帖的建议、经历、情感、互动量判身份。内容编码员不查看身份资料。

现阶段使用小红书材料；知乎在材料及平台条件具备时补充。其余平台继续内容编码，本规则不为其新增身份门槛。负责人须提供选定采集阶段、同一作者多份资料的统一选用口径及可保存下列记录的载体；不能把文档更新当作平台功能已完成。

### 身份代表什么时候？

**统一按采集阶段身份判断。** 使用负责人选定采集阶段留存的账号资料，即使帖子早于这些资料，也可按本轮身份分组；结果不表示账号发帖时已经属于这一类。旧“资料必须早于或接近帖子发布时间”的条件不再执行。

两人使用同一份选定资料，同一轮多批次不随实时主页变化更新身份。个人粉丝和定位、机构名称和认证均使用指定阶段的已有资料，不自行拼接其他阶段版本，不选择较大的粉丝数。多版本选用由负责人统一说明，编码员不自行决定。

保留实际记录时间及采集阶段；精确日期缺失但已有来源记录能确认阶段时，照实注明，不伪造日期。必要资料连阶段归属也无法确认时，才按材料不足处理；不能用帖子发布日期、导出日期或今天的编码日期冒充采集日期。实际阶段起止及具体资料版本由负责人发放前补齐，本说明不编造日期。

## 2. 按这个顺序判断

### 第一步：确认主体与材料

确认帖子符合本研究的旅游内容纳入条件，账号关联、资料来源及实际日期或可确认的采集阶段明确，所用资料属于本批选定阶段。机构账号不因主体性质而排除。尚未领取或尚未做的任务保持未测，不批量填`UNK`。

先核对认证和用户名，满足以下任一条件即认定为机构账号：

- **认证明确表明账号为机构。** 必须能读出机构身份；泛认证标识、个人职业认证或含义未知的认证代码不算。
- **用户名明确表明账号为机构。** 例如虚构名称“海湾市文化和旅游局”“海湾旅行社”。不要求同时具有认证；仅有模糊的团队称呼、地名或“官方”字样不足以说明机构身份。

**机构账号直接记机构型KOL`KOL_INST_TYPE`，不受粉丝数量限制，也不另判个人创作者定位。** 粉丝缺失、取整跨门槛或粉丝快照不适用，不阻止依据合格的机构资料归类；已有粉丝仍按实际情况保留，缺失不补0。机构认证／用户名本身的来源、时间不合格或证据相互冲突时，记`UNK`并说明。

博主签约MCN、与机构合作或在机构任职，不使其个人账号成为机构账号；简介自述机构背景也不能代替上述两个条件。未满足机构条件但可确认是个人账号时，继续个人路径；主体仍不清记`UNK`，不强行归个人。明确为非机构多人共用账号时，沿用`NA`，不因有团队就判机构。

### 第二步：个人账号看是否达到门槛

只对个人账号核对粉丝数的来源、精度和时间。缺失不当0，关注数不当粉丝数；取整范围跨门槛或时间不符合本批规则时记`UNK`。采集阶段粉丝可用于本轮分组，但不得写成发帖时粉丝数；不另找实时数值替换选定资料。

| 平台 | 低于门槛 | 达到门槛 |
|---|---|---|
| 小红书 | 少于5,000 | 5,000及以上 |
| 知乎 | 少于10,000 | 10,000及以上 |

主体与快照合格且低于门槛，直接记`KOC_TYPE`，进入路径记`SCALE`；不要求再判断创作者定位，也不据此填写“有消费经验”。低粉作者即使自称博主，仍走这条规模路径。

### 第三步：对达到门槛的个人作者，判断创作者定位

看已有简介或含义清楚的创作者认证，是否明确表示账号以旅游及目的地体验相关的内容创作者身份对外活动。

- 明确自称旅行博主、探店博主、签约旅行家等，可以作为公开定位证据。完整阅读上下文；自述只证明公开定位，不写成已经平台认证。
- “想成为博主”“预备役”等不算；“未签约”不能当签约证据，无关业务的签约也不算。
- 只有合作联系方式、合作意向不够。
- 平台职业标签可以辅助；来源性质未核实的标签、含义未知的认证代码不能单独定类。
- 不要求专业学历或资质，不判断EA／CE／SC；不从目标帖有没有建议、个人经历或情感描写推导身份。

### 第四步：填写结果

| 已核对的情况 | 身份结果 | 记录要求 |
|---|---|---|
| 合格认证或用户名明确表明机构身份 | `KOL_INST_TYPE` | 摘录所用认证或用户名及来源、记录时间；不要求粉丝门槛或个人定位 |
| 个人旅游UGC及粉丝快照合格，低于门槛 | `KOC_TYPE` | 规模路径`SCALE`；定位可记未评估 |
| 个人账号达到门槛，有明确相关创作者定位 | `KOL_INDIV_TYPE` | 摘录定位证据，注明自述或认证及来源 |
| 个人账号达到门槛，已核查但未见明确定位 | `UNK` | 写“已核查未见”，不自动归KOC或兼具型 |
| 个人账号达到门槛，定位资料缺失、语境不清或来源冲突 | `UNK` | 说明资料不足或冲突，不与“已核查未见”混同 |
| 主体不清、必要主体资料不合格，或个人路径的粉丝资料不能用 | `UNK` | 写明阻止判断的原因；机构路径不套用粉丝缺失规则 |
| 明确为非机构多人共用账号 | `NA` | 未满足机构条件，也不适用单一个人路径 |

**兼具型暂不赋值。** 保留`HYBRID`类别及旧记录，但目前没有新的可执行初判标准。不能因为“博主同时分享个人旅行经历”或资料模糊就填兼具型；不使用旧EA／CE矩阵补判。专业背景后置转判也暂不执行。当前不新增`ORDINARY`判断路径，高粉但定位未见按上表处理。

## 3. 保存什么，怎样处理分歧

每项任务记录：作者任务编号和证据窗口、所用证据摘录及来源和实际记录时间、判断理由、最终身份及未决原因、分类规则ID和时间规则ID。机构型KOL只需保存足以支持判断的认证或用户名原文；两者不必同时提供。机构型与个人型直接由身份选项区分，不另写路径，也不新增一套人工表格；`KOL_TYPE`只在分析阶段合并生成。用户名证据只证明按本研究规则认定为机构，不写成“已获平台认证”。

个人路径另保留粉丝原值与实际快照时间、平台门槛、必要的定位判断及理由。定位判断分为“明确／已核查未见／无法判断／未评估”；不把缺失写成阴性。机构路径和个人低粉路径均不用补做个人定位判断；机构缺粉丝不影响身份，但保留资料缺失状态。所有原始可识别资料按原有受限材料规则保存，不进入公开导出。

编码员各自作答，拿不准时标`?`并写一句原因。两份原始答案保存后再讨论，裁决另存，不覆盖原始答案。平台若缺少定位或来源记录位置，先由负责人落实本批记录载体，不能把定位判断塞进旧EA／CE字段。

身份是本研究的操作分组：机构型KOL为明确的机构发布者，个人型KOL为达到规模门槛且定位明确的个人创作者，两者与KOC型三组分别报告。机构路径依据正式发布者身份，不表示机构天然具有较强影响力；KOC规模路径不证明真实消费或同伴取向。两者都不证明实际意见影响力。本文比较的是采集阶段不同类型账号所发布的研究期内容，不说明它们发帖时已具同样身份。共同校准不等于独立信度验证。

## 4. 对照示例

以下均为虚构示例，默认主体、账号和快照条件合格：

| 情形 | 填写 |
|---|---|
| 小红书4,999粉，简介“旅行博主” | `KOC_TYPE`，规模路径 |
| 小红书5,000粉，简介明确“旅行博主” | `KOL_INDIV_TYPE`，保留简介自述证据 |
| 知乎10,000粉，简介仅“商务合作请联系……” | `UNK`，只有合作意向不足 |
| 高粉，简介“想成为旅行博主” | `UNK`，愿望不算明确定位 |
| 高粉，只有来源性质未核实的“旅行博主”标签 | `UNK`，该标签不足以独立判断 |
| 高粉旅行博主，同时发布个人旅行经历 | 符合定位条件则`KOL_INDIV_TYPE`，不据经历转为兼具型 |
| 认证明确为景区机构账号，粉丝300 | `KOL_INST_TYPE`，不看粉丝门槛 |
| 无认证，用户名“海湾旅行社”，粉丝缺失 | `KOL_INST_TYPE`，摘录用户名；不写成已认证 |
| 用户名是个人昵称，认证明确为机构账号，粉丝显示不清 | `KOL_INST_TYPE`，摘录认证原文 |
| 小红书个人博主4,999粉，简介“旅行博主，签约某MCN” | `KOC_TYPE`，个人规模路径；签约不使账号成为机构 |
| 小红书个人账号5,000粉，简介“旅行博主，在某景区任职” | `KOL_INDIV_TYPE`，不是机构型KOL |
| 用户名“海湾旅行”，只有含义未知的认证代码，主体仍不清 | `UNK`；名称及代码均不足以说明机构身份 |
| 个人在2025年发帖，选定2026年采集资料显示小红书8,000粉且简介“旅行博主” | 按2026年采集阶段归`KOL_INDIV_TYPE`；不推断2025年发帖时身份 |
| 用户名与认证的主体信息明确冲突 | `UNK`，记录冲突后讨论，不自行选取其中一项 |
