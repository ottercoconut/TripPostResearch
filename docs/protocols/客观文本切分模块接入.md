## 规则及工程修复

规则仍为`objective-structure-0.5`，见[客观文本片段切分规则](../methods/客观文本片段切分规则.md)。
只按标点、换行、列表和显式格式切分，不按观点、评价属性或情感方向增加边界。
[2026-09-08冻结记录](../decisions/客观文本片段切分冻结记录.md)保留原独立50条验证及
300条历史回归证据，不改写成本次新语料的人工准确率。

迁入来源是原实验引擎，SHA-256为
`6a4c66ed1453e79c0f6af95db5504abcac8fdc50a14504223163aab643ce6f74`。
新模块对300条历史输入的正文投影及边界结果逐条对照，差异为0；其中包含锁后
50条验证输入。原实验目录不改动，正式模块不依赖它才能运行。

直接迁入版本在新语料中发现8条完整性失败，旧引擎在同样输入上也会失败。
原因是标点后的ZWNJ/ZWJ/变体选择符，或空格与附加符组成完整字素，候选边界
或空白修剪切进了字素。工程实现补齐R09字素保护：候选边界移至字素末端，
修剪保留完整的非纯空白字素，不改写正文，不引入语义拆分。

修复实现ID为`objective-structure-0.5-grapheme-safe-1`，与规则ID分开记录。
完整性检查使用显式异常，优化模式`python -O`不能关闭。300条历史样本仍保持
原输出；新人口中原先成功的10,906条逐字段保持一致，8条原失败记录现在成功。

## 模块与调用

源码位于[`segmentation/`](../../src/tourism_ugc_study/segmentation/)。公开入口仅依赖
标准库和固定版本regex，不加载清洗、机器学习、数据库或Admin；此依赖说明仅限旧`segment_body/segment_text`入口，新语义入口需要embedding依赖：

| 文件 | 职责 |
| --- | --- |
| `api.py`、`contracts.py` | 纯函数接口与不可变内存结果 |
| `engine.py`、`projection.py`、`integrity.py` | 客观边界、Delta提取及共享原文完整性校验 |
| `config.py`、`source.py` | 输入配置及配对研究库只读查询 |
| `artifacts.py`、`batch.py` | 私有运行文件与批处理调度 |
| `storage.py` | 唯一片段表、稳定身份与索引查询 |
| `import_validation.py`、`importer.py` | 来源/投影验收与事务性导入 |
| `database_audit.py` | 单表全量复核及固定种子抽查材料 |

```python
from tourism_ugc_study.segmentation import segment_body, segment_text

result = segment_body("甲。乙！")  # 原始content_text，可为Delta JSON或None
for part in result.text_segments or ():
    assert part.raw_text == result.source_text[part.start:part.end]

result = segment_text("甲。乙！")  # 已提取正文，不再次解析JSON外观
```

`seg_id`从1连续编号，start/end是可读投影S的Unicode码点零基左闭右开区间，
不是字节、UTF-16或源JSON位置。title不拼入正文；普通正文不做模型规范化；
Delta只拼接文本insert，已声明非文本嵌入仅计数。源body和S分别保留摘要。

`completed`表示执行和无损检查成功，允许带格式提示；空白正文成功输出空元组。
源NULL有独立标记。损坏Delta或完整性失败返回`failed`及`text_segments=None`，
不能伪装为空数组成功。类型错误抛TypeError。内存字段与下述数据库字段由持久化层映射。

## 唯一片段表

本机基线文件为`data/processed/text-segments-20260928/text-segments.sqlite`，大小79,482,880字节
（约75.8 MiB），库内只有`text_segments`一张表，不建帖子表或批次表。
`data/processed/current-text-segmentation.json`保存本机发布包路径、批次和清单摘要；
其`admin_segment_reader_integrated=false`是9月28日入库时旧状态，不能作为今天未接入的证据。
Admin不读取此指针，实际消费目录由`TRIPPOST_ADMIN_RESEARCH_SEGMENTATION_DIR`指定。

| 字段 | 含义 |
| --- | --- |
| `segment_id` | 片段主键，SHA-256(`batch_id:source_post_id:seg_no`)，同批次重建保持稳定 |
| `source_post_id` | 来源快照的`web_posts.id`，同一帖子可对应多行片段 |
| `seg_no` | 帖内序号，从1连续递增；对应切分接口的`seg_id` |
| `text` | 片段原文，对应`raw_text` |
| `start`、`end` | 可读正文S的Unicode码点左闭右开位置，不是原始Delta JSON偏移 |
| `batch_id` | 原成功运行manifest精确字节的SHA-256，绑定语料、规则与实现 |

表使用SQLite STRICT及主键、非空、范围约束。
`UNIQUE(batch_id, source_post_id, seg_no)`同时提供按帖子顺序读取的联合索引。
`source_post_id`是跨数据库逻辑关联，SQLite不设跨库外键，由导入和全量验收逐帖核对。
一个发布包只接受一个批次；切分规则或来源变化应生成新包，不覆盖已有引用。
新包继续沿用同名同结构`text_segments`，不是每个算法建立一张新表。表索引可以容纳多批次，
但现行Research全库验收和Admin inventory要求一个活动批次，不能直接向现有包追加另一批次。
算法替换的适配工作见总备忘录B05；已被任务引用的包与片段身份保留。

包内`manifest.json`保存公共版本与哈希，`source-run-manifest.json`保留原切分清单，
`input-config.json`绑定来源，`post-evidence.jsonl`仅保留身份、摘要、投影信息和诊断。
不在每行复制帖子正文或算法版本。空正文成员在manifest记录，不伪造片段行；当前无空成员。
后续标注应引用稳定`segment_id`，不要直接修改已验收片段正文使其与源文位置失配。

```python
from contextlib import closing
from pathlib import Path
import json
from tourism_ugc_study.segmentation.storage import open_segment_database, get_post_segments

bundle = Path("data/processed/text-segments-20260928")
manifest = json.loads((bundle / "manifest.json").read_text())
with closing(open_segment_database(bundle / "text-segments.sqlite")) as connection:
    parts = get_post_segments(connection, manifest["batch_id"], source_post_id)
```

## 随机抽查与性能

`results/text-segmentation-database-audit-20260928/`保留抽查记录：固定种子20260928，
按源post ID排序后做无放回简单随机抽样50篇，不按长度、平台或诊断过滤，合计911段。
助手逐篇阅读全部片段并填写`review.json`，结合全量原文/顺序/偏移/字素核验，
未发现新增存储缺陷或违反当前客观规则的边界。17篇带已有诊断。

已记录的使用边界包括：长引文整体保护、纯符号或FEFF可独立成段、品牌内强标点可
触发边界、原换行可拆开自然句。它们不是数据库损坏，也不能直接当作合格语义编码单元。
本次是助手工程抽查，没有人工金标准，不报告为新的准确率或总体零错误证明。
程序生成的`selection.json`保留抽样时pending状态，最终结论以绑定其摘要的`review.json`为准。

同目录`benchmark.py`及`performance.json`记录本机1000次/类操作实测；写入只在随后删除的
临时数据库副本中执行。单连接热缓存下，按帖读取中位0.015 ms、p95 0.051 ms；
单片段主键查询中位0.0068 ms；逐次commit的增/改/删中位约0.245/0.169/0.195 ms。
查询计划确认使用联合索引。这些是本机SQLite操作延迟，不代表管理端接口或并发吞吐。
