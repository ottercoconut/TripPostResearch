## 1. 目标与输入

对一批研究帖子的完整可读正文进行语义切分，继续输出已有七字段`text_segments`，供Admin选材和固定编码使用。优先考虑中文UGC语义效果与科研可复现性。2026年10月12日用户明确粒度目标：每段尽量表达一个可独立编码的意思；同一景点内部，体验、交通、价格、建议等发生明确内容转折时也可拆开。相互依赖的说明仍可合并，不把属性变化、句号或固定字数作为必切条件。同日团队复核校正了“独立”的含义：完整、连贯的地点介绍、组成列表和连续推荐块本身可作为编码单位，不能因每个子条目也能单独编码就要求拆开。日期、章节或叙述任务转换可提供边界证据；介绍接着谈体验并不自动构成转换。复核时，同一对象的介绍与评价被分在相邻片段也不自动构成缺陷：只有对象指向、限定条件或实际编码判断因此不清楚时，才作为待处理边界问题。切分不预测编码标签、情感或作者身份。

来源由显式研究输入配置绑定（仓库入口为`configs/text-segmentation-research.json`）：只读配对成员库、候选manifest和正文快照，选择`decision=keep`；这不改变`human_final_review_status=pending`。输入人口、长度分布、库hash和旧结果基线见B05及来源manifest。本机与NAS结果具有不同来源身份，发布前须核对Admin实际使用的配对来源。

文本编码实验沿用网站随机抽取的实际批次及入选清单；旧切法与embedding切法对照时使用同批原文，不另挑材料或重抽。本文的81帖开发／调参样本及锁参后独立抽查各有工程用途，均不能替代或覆盖网站实际编码批次；网站抽样、任务发放及提交核验归B06。

`--members`只筛选运行帖子，来源核验仍读取完整配对数据库。远端开发可改用明确导出的`--frozen-input`三文件包：原字节样本`manifest.json/cases.jsonl`及新增`input-manifest.json`。导出先核验本地配对来源；远端实际输入身份是包，完整来源仅以`parent_source_identity`引用，不能声称在远端核验过全库。单独复制样本或截取SQLite不能替代此导出契约。

```text
只读整帖 → 正文投影 → 候选单元及原文位置 → 单元向量／已验证缓存
        → 连贯度与depth → 语义边界 → 长度约束与无损校验
        → 私有运行包 → 七字段单表候选包 → Admin验收与切换
```

## 2. 复用与裁剪

复用Research的正文投影、来源校验、Unicode位置及单表契约；依据TextTiling的左右窗口、余弦连贯度和谷值深度思想独立实现边界算法。参考上游为`ql-link/LinkRag`提交`558968d814e8b8838f9296bdab62e1af36ab875e`，交接依据为相邻`LinkRag-chunking/PROVENANCE.json`。

适配删除“未超长就透传”和“装不下才找语义切点”门控：含两个及以上候选单元的短帖也参与向量评分，先选语义边界，再处理长度。使用最小段长保护，不迁入短段默认向前合并器。

## 4. 原文与候选单元

1. 复用纯文本／Delta投影，不拼标题、不去重、不改写正文空白或Unicode。位置始终相对可读正文S，采用Unicode码点零基左闭右开区间。
2. 句末`。！？；!?;`及CRLF／CR／LF／U+2028／U+2029产生候选边界；连续句末符号和紧随闭引号／闭括号归前一个单元，CRLF整体处理。切点必须位于`regex \X`字素边界。轻量http(s) URL识别保护区间内ASCII `!?;`，区间截止于空白、尖括号、引号或中文句末符号；超长URL仍按长度规则处理。
3. `.`不作为常规边界；逗号、顿号、冒号只用于超长单元细分。列表只识别换行，不推断层级；转折词不直接触发边界。
4. 只trim整簇均属于`integrity.WHITE`的首尾字素，FEFF及带非WHITE组合符的簇保留。除WHITE外均为Unicode `P*`的候选在细分前优先并入前邻，无前邻则并入后邻；emoji不享有额外合并例外。
5. 超过`unit_max_tokens`的单元先逐一重计弱边界，取最靠后且不超限的原文前缀；无可行点则按token offset提出切点，退到完整字素并重计，必要时逐字素后退。每轮cursor严格前进。不得`decode(tokens)`重建正文，也不得假设BPE前缀计数单调而直接二分。
6. 单字素超过单元预算时，只要完整模型输入及最终段长均未超限，即保留并记录`unit_oversized_grapheme`；超模型输入上限报`unrepresentable_grapheme`，超最终段长报`unsplittable_segment_limit`，两者同时超限优先前者。不能拆坏字素或截断；不可信offset明确失败，不用字符数替代。
7. 不将候选单元预装成目标段长。单元顺序覆盖全部非WHITE字符，允许空白间隙；最终片段可以合并多个单元。

使用模型同revision的tokenizer。Qwen原生NFC normalizer保持并记入身份，**存储正文不规范化**；token offset触及组合字素的一部分时扩到原文字素包络，再核对顺序和覆盖，仅作为切点建议。窗口预算可累计单元正文token数，最终段长必须重新计数完整原文子串。模型输入上限另按模板及tokenizer实际特殊token行为计数，不手工追加EOS。

## 5. 当前算法

唯一配置为`configs/text-segmentation-semantic-8b-coherent.json`，配置类为`CoherentSemanticConfig`。当前算法为**1.2分层规则**：规则身份`semantic-coherent-ugc-1.2`，实现身份`semantic-coherent-ugc-1.2-layers-2`，分区器`meaning-layers-2`，配置指纹`da650a7d215cb550e59a7df0b8d0013bbfdc8d99f6332ffaa0770ae7c74045e5`。1.2是在1.1（2026年10月14日冻结，Git标记`segmentation-coherent-1.1`）基础上，按10月15日独立抽查发现的问题修复标签行否决规则，见§5.2；其余规则与参数不变。1.0、1.1只留在Git历史，当前代码不兼容、不再生成或导入旧版本结果。配置解析要求显式当前身份；研究生成和正式导入还必须匹配登记的完整配置指纹。没有旧规则回退或按帖子ID、地点名单、编码标签的特判。

| 参数 | 当前值 |
| --- | ---: |
| `unit_max_tokens` | 64 |
| `window_tokens` | 32 |
| `absolute_cohesion_threshold` | 0.55 |
| `depth_floor` | 0.05 |
| `depth_std_factor` | 0.5 |

### 5.1 连贯度与depth

N为单元数，M=N−1为gap数。逐单元向量验证后L2归一化。对gap i，两侧分别收集最近单元，累计正文token数达到`window_tokens`或遇到帖首尾即停；每侧至少一单元。各侧向量取算术均值，再计算余弦`c_i`。纯计算使用CPU float64，有限余弦夹到[-1,1]；窗口均值范数≤1e-12或非有限时报`invalid_window_vector`。首版不平滑。

从c_i向两侧沿`next >= current - epsilon`继续扫描，到不满足条件或端点停止；L_i、R_i为各侧已访问区间（含c_i）的最大值。实现以两次线性递推计算：

```text
d_i = max(0, L_i - c_i) + max(0, R_i - c_i)
T_depth = max(depth_floor, mean(d) + depth_std_factor * population_std(d))
```

c曲线从左到右组成最大连续近等平台，组内`max(c)−min(c)≤epsilon`；平台外存在的邻值须大于`平台min(c)+epsilon`，才算低谷。端点允许单侧低谷；整曲线只有一个平台时仍保留一个代表。代表gap取平台下标中点向下取整。

候选满足`d_i≥T_depth`或`c_i≤absolute_cohesion_threshold`才可切。先按d降序、再按c升序分组，每层组内极差≤epsilon，最后按原文位置升序排序；避免非传递的两两近似比较。1.1起不设全局最短段字符门槛：正文中间的短段（小标题、单句感受）可以独立成段，必要语义关系由§5.2的禁止切规则保护；只有无文字碎段和过短的首末段按§5.3合并。全量统计中Qwen3-Embedding-8B的相邻窗口余弦集中在0.75–0.92，`absolute_cohesion_threshold=0.55`实际几乎不触发，保留该参数仅为兼容，不作为效果依据。

### 5.2 分层规则

N为单元化完成后的候选数。N=0成功返回空片段；N=1完整保留；两者不请求逐帖向量。N≥2全部参与评分，两个单元时depth为0但仍可按绝对连贯度提名；三个单元允许端点单侧谷。向量来自模型或已验证缓存，参与评分不等于实际forward次数。

评分之后由分层分区器统一选择最终切点，优先级为**禁止切＞换天必切＞长度兜底＞灰色地带**。切分的目标是贴近人读帖时的分段直觉，供片段级编码使用，不是独立研究结论。

| 层级 | 规则 | 实现要点 |
| --- | --- | --- |
| A 禁止切 | 句子中间（逗号、顿号、冒号续接及无标点长句内部）；同一行内的配对括号内（跨行配对多为引号错配，不保护）；题头与其首说明；不带内容的纯标签小标题之后（如“交通🅿️”，“地址：某路”这类标签带值的行除外）；尾部话题标签、链接与账号，含句末同一行的标签；后句以强依赖词开头（否则、不然、不如、相比之下、相比、相较、比起、即便、即使、哪怕、因此、所以、因而、而且、并且、况且、但如果、可如果）；前句是尚未给出结论的条件（以如果、假如、要是、只要、除非、若是、倘若开头，无分句标点且未以句末标点结束）；后句是独立成行的括号说明（括号编号题头除外） | 一票否决，模型、小标题和长度都不能推翻。弱转折（但是、不过、可是、然后、还、也、而）不在此列 |
| B 换天必切 | 叙述中的日程题头：Day2、第二天、D2或行首日期，须带当日正文 | 未被A否决即切开；带箭头的路线目录行和连续的日程目录不触发 |
| C 灰色地带 | 小标题、编号条目、连贯块（完整介绍、组成列表、同日推荐、目录）起点 | 该gap的depth>epsilon（语义曲线有任何下降）即切，不要求过`T_depth`；连贯块只作trace证据，不再阻止切分 |
| C 灰色地带 | 其余自然句末／行末 | 语义谷值过`T_depth`或绝对阈值即切；门票、交通、开放时间等紧凑信息与弱转折均由此判断 |

**标签行上移（1.2）：** 模型或结构提名的切点若只因“纯标签小标题之后”被否决，说明分界其实在标签行之前——人会让“⭐️景点必去打卡”这类标签随后文，而不是丢掉这个分界。此时若标签行以人一眼能认出的题头标记开头（emoji或符号、【或[等开方括号、“三、”“12.”等编号、键帽数字、Day／第X天），切点上移到标签行（含紧邻的连续标签行）之前的换行处；以普通文字、列表符号（-、·等）或#开头的行不上移，因为原有的标签行判断较宽，会把以emoji结尾的普通句子和清单条目也算进来，上移会切进句子或清单中间（首轮重放抽查60个新增切点中有10个属于此类）。若那里本身被禁止切（如上一行以冒号结尾）或标签行在帖首，则放弃。原提名是换天题头时，上移后的切点同样按换天必切处理。原位置另有其他禁止切理由时不上移。trace中原位置记`shifted_before_label_heading`，目标位置记`selected_before_label_heading`。

识别依据原文结构与显式词面，不因整帖出现“推荐”就保护全文；隐含比较、跨多句的条件和未标记的话题转换仍无法由规则覆盖，是已知限制。

### 5.3 长度兜底、碎段合并与解释

`max_segment_tokens=512`是长度兜底的触发线，不是目标长度。只有已选切点之间的意思段超过512 token时才补切：先在上限内的允许位置中选择，等级为换行＞句末＞无标点长文中以空白分隔的位置，同级取depth最大、再取c更低、再取更靠后者；上限内没有允许位置时，向后取第一个允许位置，该段记为`length_exception`；直到段尾都没有允许位置时整段保留并记为异常。长度从不推翻A层规则、不截断原文，也不再因无解使整帖失败。空白分隔位置不供语义或小标题选择，只在长度兜底时使用；逗号续接始终否决。

所有切点定下后做最后一步碎段合并，只撤销切点、不新增或移动切点：没有任何文字或数字的片段（单个emoji、箭头、分隔线、零宽字符或占位符）并入前段，位于帖首时并入后段；首段、末段非空白字符少于`edge_segment_nonspace_chars=16`时分别并入后段、前段。换天切点从不撤销，合并后超过512 token的也不合并，因此长度切点和长度异常不变。正文中间的短段不处理。2026年10月14日全量重放比较了两种做法：恢复1.0的全局16字门槛会吞掉约440个正文中间的有效短段，并把“第二天：……”这类换天题头粘到前一天末尾；只合并首末段与无文字碎段则保留中间短段，合并后的段落抽样自然，故采用后者。

`semantic-trace.jsonl`的`meaning`保存初始评分决策、原语义／结构／长度边界、逐gap理由（如`selected_day_transition`、`selected_structure_with_semantic_dip`、`rejected_structure_without_semantic_dip`、`before_dependent_connective`、`after_open_condition`、`before_parenthetical_note`、`selected_length_fallback`、`merged_short_first_segment`、`merged_short_last_segment`、`merged_wordless_segment`）、连贯块证据、`length_exceptions`及无法表达的结构起点。最终`semantic_boundaries`只计算语义／结构切点的并集；`length_boundaries`只计算额外长度切点，两者互斥，合计为非空结果的段数减一。

所有片段为原文连续子串、编号连续、字素安全，非WHITE字符恰好覆盖一次。单元内部没有gap、隐式上下文未被识别仍是算法边界，不能把规则变化或段数变化当作总体质量证明。候选评估与已知限制见B05；修改规则或参数须另行记录依据及验证，不能覆盖1.0冻结记录。

## 6. 模型输入与资源监督

当前模型为`Qwen/Qwen3-Embedding-8B`，revision固定为`1d8ad4ca9b3dd8059ad90a75d4983776a23d44af`，完整维度4096，CUDA／BF16／batch=1。资产准备与运行分离；CLI只读取已核验的本地模型及tokenizer资产，文件摘要、依赖版本及实际设备写入运行身份。不量化、不截短向量、不静默换设备或精度。早期模型比较与Mac验证只见B05及Git历史。

模型输入固定为`Instruct: Retrieve semantically similar text\nQuery:{原文单元}`，其中`\n`为换行。模型与tokenizer同revision；原生特殊token、左padding、末有效token pooling、FP32 L2归一化、`eval()`、`inference_mode()`、eager attention和`use_cache=False`。每条含模板的实际输入上限256 tokens，关闭截断、不手工追加EOS。CUDA固定padding至256，身份必须包含`padding_strategy=max_length`和`padding_max_length=256`。模板和tokenizer规范化不改写存储原文或offset。

真实运行经独立worker监督。`--resource-policy PATH`必须显式提供四字段JSON：`rss_bytes`、`additional_swap_bytes`、`cuda_device_uuid`、`cuda_memory_bytes`。内存预算为正整数字节，新增swap预算为非负整数字节，0表示不允许增长；UUID为完整单卡`GPU-…`。预算依据实际主机可用资源确定，无Linux默认值；同时核对系统盘、数据盘剩余空间并为结果、缓存和回传留余量。

worker只看指定GPU，逻辑设备为`cuda:0`。父进程每2秒采样RSS、系统全局swap和该卡显存；worker另存Torch allocated／reserved峰值。系统与整卡读数不能归为模型独占，分配器峰值不能冒充整卡峰值。超预算、观测失效或超时均停止worker，不发布半包。

| 入口 | 默认时间预算 |
| --- | --- |
| `text_embedding_probe.py` | 加载300秒、单次推理120秒、整轮600秒 |
| `text_segment_research.py` | 加载300秒、合成预检120秒、完整单帖1,800秒、整轮14,400秒 |

研究入口可显式设置加载／单帖／整轮预算并记录，单帖预算覆盖该帖全部forward。批次开始前对两条合成输入预检，调用数另记`preflight_model_call_count`；预检通过不证明完整语料容量。

更换执行环境后，先完成目标硬件的CUDA合成验证。BF16须有原生支持，实际参数设备及dtype与声明一致；通过`--numerical-tolerances`在运行前提供`repeat`、`batch`、`norm`三个有限正数。重复推理及batch=1/2比较绕过缓存，另查缓存重排／损坏拒绝与超长输入forward前拒绝；不得在失败后自动放宽容差。数值门判断工程一致性，不评价中文主题切分效果。

## 7. 缓存、失败与复现

缓存为`results/`下私有文件，不建业务表。命名空间绑定实际模型／tokenizer资产SHA、revision、模板与特殊token、pooling、归一化、维度、设备、精度、batch大小、CUDA padding策略及长度、线程数、attention及依赖版本；条目key为精确模型输入UTF-8摘要。设备身份含CUDA设备UUID，换一张卡（即使同型号）即为新命名空间，正式运行须在新卡上重新编码；只有切分规则变化而单元不变时，同一张卡上的重跑和CPU只读重放才能复用缓存；这种情况下正式运行可用只读缓存模式在无显卡机器上完成（见下文）。目录0700、文件0600，float32 `.npy`禁止pickle，临时目录核验后原子rename。

命中仍核对摘要、数量、顺序、维度、有限值及范数>1e-12；重复输入复用向量，输出按原序还原。`cache_hit_count/cache_miss_count`按输入位置累计，provider调用数按真实forward累计。损坏或已有冲突内容拒绝复用，不静默覆盖。采用单进程单写者；并发运行使用不同目录。

| 情况 | 当前处理 |
| --- | --- |
| 投影失败、不可表示字素、单帖边界／长度错误 | 逐帖`failed`，片段为None；其余帖可继续，失败批不可导入 |
| 模型／tokenizer／缓存契约错误（`EmbeddingError`）、OOM、I/O错误 | 异常向上结束attempt，不降为逐帖成功 |
| 正文来源、执行快照或模型身份运行中变化 | 拒绝发布运行包 |
| 评分后未选边界 | 正常`scored_keep` |
| 用户中断／进程异常 | 尽可能留下attempt终态；无完整manifest视为不完整 |
| 全量入库时单帖超过2,000段 | 导入校验拒绝；开发批次仍须统计并解释该情况 |

`text_segment_research.py`在输出目录旁创建`<输出名>.attempt.json`与`<输出名>.runtime/`，留存阶段、资源采样、私有日志及实际执行的源码快照；worker从该快照运行，父进程完成资源和终态核验后才发布完整run目录。attempt是运行证据，不是可续跑的逐帖checkpoint。异常清理本次临时包，保留有效缓存；重跑使用新输出路径、同来源及显式配置，重新生成完整结果。控制台仅显示异常类型，稳定原因码在attempt，可能包含原文的完整traceback仅在私有日志中。

只读缓存模式：`text_segment_research.py --cache-only-from 来源运行目录 --cache-dir 缓存目录`沿用来源运行（须为完整成功的正式全量）记录的模型身份，CPU上只加载同revision的tokenizer，并核对其资产摘要、原生规范化与依赖版本均与记录身份一致；不加载权重、不做合成预检，向量只从只读缓存读取，缺任何一条即整轮失败，绝不补算。该模式不经显卡资源监督worker，源码快照写在运行包内并在发布前复验。运行清单`vector_source`记录`mode=cache_only`及来源运行清单的路径和SHA；普通运行记为`mode=model`。导入门要求只读缓存运行的`model_call_count`与`preflight_model_call_count`均为0、缓存命中数等于参与单元数。适用前提是候选单元未变；单元有变则必须在有卡机器上普通运行。

`text_embedding_probe.py`仅处理合成输入，证据保存在其输出目录内的`summary.json`及设备子目录；不生成研究run或旁置attempt。CUDA分支另外绑定并执行完整源码快照，记录模型配置、合成输入摘要和数值容差。

同向量、同配置的边界必须逐项重放一致；跨平台CPU float64评分末位差的限定验收见第9节，不放宽切点或模型数值门。模型重复／batch／设备比较另存实际向量，记录数值差及边界是否变化；不能以缓存命中代替重复推理。模型数值门、固定向量算法验证、真实语义效果分别判断。正式运行保留模型资产、实际代码与配置、输入manifest、向量缓存和trace，不能仅凭`HEAD+dirty`说明运行实现。 冻结包的逐文件大小与SHA均从最终待打包字节重算，总字节须等于逐项和，不能继承父包大小；历史清单发现元数据错误时保留原字节，另以绑定原清单SHA的校正记录说明。

## 8. 单表与运行身份

表结构继续使用`storage.SCHEMA`：STRICT表`text_segments`，字段及顺序为`segment_id, source_post_id, seg_no, text, start, end, batch_id`，保留主键、CHECK及`UNIQUE(batch_id,source_post_id,seg_no)`。验收检查列、STRICT、索引和约束行为，拒绝额外业务表。`source_post_id`对应冻结来源`web_posts.id`；位置仍相对可读正文。

一个发布包只含一个活动batch。每轮在新目录建立同结构数据库文件，不按算法另建表、不追加第二batch、不原位删除旧行：

```text
batch_id = SHA256(完成运行manifest的精确字节)
segment_id = SHA256(f"{batch_id}:{post_id}:{seg_no}".encode("ascii"))
```

旧答案不能按post与seg_no转移给新片段。运行身份为`semantic-text-segmentation-run`，生成、导入及发布包复验只接受当前冻结配置；旧客观运行、旧语义身份及未知身份均拒绝。显式成员运行使用`scope=development`，即使恰好包含所有成员也不能入正式包；离线输入自动固定全部包成员，始终为development。只有配对库输入且无成员筛选才是`scope=full_corpus`。

发布包仍为五文件：`text-segments.sqlite`、`manifest.json`、`input-config.json`、`source-run-manifest.json`、`post-evidence.jsonl`。仅成员完整、无failed且来源／结果校验通过的全量run可导入；成功构建后整目录rename。同run重复导入返回`already_imported`并复验，另一batch写同目录拒绝。包schema保持1；Admin启动不依赖模型或向量缓存。

五文件校验可重建原结果JSONL摘要，**不等于重算了语义边界**；语义重放仍需要另外保留的trace、向量和代码。

## 9. 全量核验与独立抽查

当前已完成算法基线冻结，按同源正式全量运行 → 全量无损与单表校验 → 独立抽查 → 用户查看推进。Admin发布另按第12节执行。不得因再次阅读本文重新调参、重抽开发集或覆盖历史证据。

全部keep成员须且仅须出现一次，逐帖核验投影、原文子串、非空白覆盖、字素端点、token硬上限、连续序号及来源摘要。记录失败原因、分层段数和长度分布、语义／结构来源与长度切点。真实逐帖处理耗时`processing_seconds`、缓存重放耗时`boundary_seconds`及完整运行总耗时分别记录；RSS和系统swap不分摊为某层或参数组的独占内存。

同向量重放须核对片段、跨度、decision类型／候选／选择／理由／边界及完整meaning证据。仅初始和最终gap的`cohesion/depth`允许CPU float64绝对差≤1e-12，无相对容差，须为有限浮点数，并记录实际漂移；边界或其他字段变化仍失败。缓存缺失、损坏或向量摘要不符时停止，不补推理。参数比较工具仅用于另行开展的当前算法开发，不是本次全量执行步骤，也不能核验退役算法运行。

独立抽查从同源人口排除全部开发、压力及调参帖，简单随机抽50帖，初次种子`20261012`。排除集合、剩余人口和抽样顺序均留摘要；不足50时失败，不回填开发帖。B05登记的81帖全部排除，后续实际查看并用于调参的帖子也须加入。若独立样本推动改参，该批转为开发材料，记录新种子另抽，不覆盖旧清单。

助手逐篇阅读全文及片段，判断欠切与碎切。按10月12日用户明确的口径，碎切（本轮过切判断）的唯一判据是切分损害原意：断点割裂必要语义关系，使上下段相对原文可能产生含义变化，或使语义无法判定。段落短、段数多、需要回看前文、同一对象分段或编码重复均不单独构成碎切；允许明确的相邻上下文承接，原文自身的歧义不直接归因于切分。发现问题时，须在`affected_spans/explanation`中指出断点、原意及切分造成的具体语义变化或无法判定之处。完整地点介绍与连续推荐可作为整体，多个属性、景点或正负评价共处一段不自动判错。合理的多种边界保留允许范围，无法确定者记录`uncertain`。复核记录包括`post_id, sample_role, config_id, technical_pass, assistant_judgment, issue_codes, affected_spans, explanation, suggested_change, reviewer_kind, review_time`；`reviewer_kind=assistant`，判断为`usable/needs_change/uncertain`。这是助手参考判断，不是人工金标准或总体准确率。本次澄清不修改冻结算法、参数或历史评估记录；若按新口径复评，另留结果与依据。

全量发布前须技术不变量通过、无未解释failed、独立样本逐篇复核完成。`needs_change/uncertain`保留具体证据及建议，由修订重测或用户接受局限形成结论；助手汇总代表性正反例与未解问题供用户查看。参数或策略变化后不能沿用旧抽查结论，算法已冻结也不等于全量质量已通过。

## 11. 当前CLI

项目使用CPython 3.13.5，所有Python命令通过`.venv/bin/python`执行。下列`SOURCE_CONFIG`须指向本次已核实与Admin实际来源一致的配对库配置；`RESOURCE_POLICY`为目标GPU主机的四字段资源策略；`RUN_ID`每次取新值，失败重跑也不可覆盖旧目录。下载、传输和磁盘检查在运行前完成。模型配置固定使用仓库当前文件。

如目标环境尚无对应数值验收，先执行合成验证。`TOLERANCES_JSON`须替换为运行前已确定的BF16容差JSON，不在失败后放宽；已有同环境证据不重复运行。

```bash
.venv/bin/python scripts/text_embedding_probe.py \
  --algorithm-config configs/text-segmentation-semantic-8b-coherent.json \
  --resource-policy RESOURCE_POLICY --numerical-tolerances TOLERANCES_JSON \
  --output results/semantic-cuda-smoke-RUN_ID
```

正式全量必须读取配对数据库，不传`--members`或`--frozen-input`：

```bash
.venv/bin/python scripts/text_segment_research.py \
  --config SOURCE_CONFIG \
  --algorithm-config configs/text-segmentation-semantic-8b-coherent.json \
  --resource-policy RESOURCE_POLICY \
  --cache-dir results/semantic-embedding-cache-RUN_ID \
  --output results/semantic-full-RUN_ID
```

规则修订而候选单元未变时，可在无显卡机器上改用只读缓存模式：去掉`--resource-policy`，加`--cache-only-from results/semantic-full-上一轮RUN_ID`，`--cache-dir`指向上一轮使用的缓存。

无`.git`的远端源码包显式加`--code-version SOURCE_PAYLOAD_ID`；实际执行身份仍由源码快照摘要绑定。可按主机及语料预算显式设置`--load-timeout`、`--post-timeout`、`--total-timeout`。全部成功退出0，单帖失败但完成遍历退出2，契约或运行异常退出1；失败run不能导入。

只有完整全量run通过核验后才构建同结构单表包：

```bash
.venv/bin/python scripts/text_segment_database.py import \
  --run results/semantic-full-RUN_ID \
  --output data/processed/text-segments-semantic-RUN_ID \
  --config SOURCE_CONFIG
.venv/bin/python scripts/text_segment_database.py verify \
  --bundle data/processed/text-segments-semantic-RUN_ID
.venv/bin/python scripts/text_segment_database.py sample \
  --bundle data/processed/text-segments-semantic-RUN_ID \
  --output results/semantic-independent-review-RUN_ID \
  --independent --count 50 --seed 20261012 \
  --exclusion-manifest EXCLUSIONS_JSON
```

`EXCLUSIONS_JSON`为来源绑定排除清单：`{"artifact_kind":"semantic-development-exclusions","input":正式包同源身份对象,"post_ids":[全部开发、压力及调参ID]}`。也可用重复的`--exclude-manifest`传入同源开发／比较manifest；离线包身份不同，不能直接拿来排除。工具记录排除依据，但不会自动知道哪些帖子曾被查看。

开发入口仍可显式传`--members`，或使用`text_segment_development.py --export-frozen-input`导出的三文件包；两者始终生成`scope=development`，不能改名或改scope冒充正式全量。旧算法的manifest不能交给当前配置解析或运行验证；历史材料只用于来源与排除清单追溯。

向量缓存默认在输出旁`.semantic-vector-cache`，不得放入待原子发布的run或runtime目录。常规测试为`.venv/bin/python -m pytest tests/segmentation`，只使用合成正文与固定向量；真实模型和质量复核另留证。

## 12. Admin验收、切换与回退要求

本节为单独的服务交付要求。Research CLI不执行Admin发布；2026年10月15日NAS生产Admin已切换为1.2正式包（过程与回退见B05）。Admin读取`TRIPPOST_ADMIN_RESEARCH_SEGMENTATION_DIR`指向的完整五文件包；Research current指针不是切换开关。

先在隔离Admin库验证：七字段映射、完整正文与Unicode位置、空正文不可选、1—2,000段限制、文件hash及缓存失效、保存前重验、新旧dataset隔离、旧任务拒绝新batch。断开旧外部包后，已冻结任务的正文、片段、答案、比较与导出仍应可用；现有代码若兼容，保留验收证据即可。

通过效果与Admin验收后，在同一变更中同步编码表、编码簿、切分方法及接入协议的具体模型、边界配置与算法／单位来源说明；研究方向已采纳，保留标签和主导评价规则。检查Admin模板及导出说明是否需新版本。旧任务的模板和材料快照不改。

发布依次核对实际环境来源、活动包和任务／答案状态；准备同源候选整包并校验；保存旧路径及配置，在隔离环境演练旧→新→旧→新；按Admin运维流程暂停新选材写入、切换环境变量并重载；复验新活动batch及历史任务。实际故障回退只恢复外部分段包与配置，**保留当前Admin自有库及切换后新增答案**；停留旧包意味着新发布失败，不能记为上线成功。

代码中的旧算法及兼容路径已删除，历史代码与结果通过归档和Git追溯。临时源码包、测试输出和重复中间件按明确路径及替代证据清理；源库、已有任务答案和当前结果复现资产保留。

## 13. 理论依据与证据边界

- [Hearst 1997 TextTiling](https://aclanthology.org/J97-1003/)针对多段长文的子主题边界；[Embedding-enhanced TextTiling](https://arxiv.org/abs/1610.03955)提供语义向量增强连贯度的研究依据，其对话实验不直接证明中文旅游短帖效果。
- 两／三单元的绝对阈值、端点谷、最小段长及本文单元构建是本项目适配，需通过第9节单独实测；不是上游原行为。
- 模型输入依据[Qwen官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-8B)及[官方评估代码](https://github.com/QwenLM/Qwen3-Embedding/blob/main/evaluation/qwen3_embedding_model.py)；资产按固定revision核验，具体本地字节身份由运行manifest记录。

理论可解释、工程测试通过、真实语义效果可用是三类不同结论。本文只定义契约与验收要求，实际完成情况及支持范围统一见B05。
