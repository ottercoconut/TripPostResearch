# 语义文本切分适配与验证方案

> embedding自然语义分段的研究方向已按[编码表](../data-dictionary/编码表.md)的`embedding-semantic-20261011`决定采纳。本文定义具体工程候选的技术契约；模型、边界配置与正式发布仍待验收，不覆盖旧客观活动包。实现范围见第3节；动态进度、运行结果、私有证据路径和剩余事项统一见[总备忘录B05](../planning/研究问题与待办总备忘录.md#b05embedding自然语义分段与工程接入)，工程入口为[总issue #75](https://github.com/ottercoconut/TripPostResearch/issues/75)。

<a id="s01"></a>
## 1. 目标与输入

对一批研究帖子的完整可读正文进行语义切分，继续输出已有七字段`text_segments`，供Admin选材和固定编码使用。优先考虑中文UGC语义效果与科研可复现性；同段包含风景、交通等多个属性可以保留，也可以拆开，效果由实际使用判断。切分不预测编码标签、情感或作者身份。

来源由`configs/text-segmentation-research.json`绑定：只读配对成员库、候选manifest和正文快照，选择`decision=keep`；这不改变`human_final_review_status=pending`。输入人口、长度分布、库hash和旧结果基线见B05及来源manifest。本机与NAS结果具有不同来源身份，发布前须核对Admin实际使用的配对来源。

文本编码实验沿用网站随机抽取的实际批次及入选清单；旧切法与embedding切法对照时使用同批原文，不另挑材料或重抽。本文的81帖开发／调参样本及锁参后独立抽查各有工程用途，均不能替代或覆盖网站实际编码批次；网站抽样、任务发放及提交核验归B06。

`--members`只筛选运行帖子，来源核验仍读取完整配对数据库。远端开发可改用明确导出的`--frozen-input`三文件包：原字节样本`manifest.json/cases.jsonl`及新增`input-manifest.json`。导出先核验本地配对来源；远端实际输入身份是包，完整来源仅以`parent_source_identity`引用，不能声称在远端核验过全库。单独复制样本或截取SQLite不能替代此导出契约。

```text
只读整帖 → 正文投影 → 候选单元及原文位置 → 单元向量／已验证缓存
        → 连贯度与depth → 语义边界 → 长度约束与无损校验
        → 私有运行包 → 七字段单表候选包 → Admin验收与切换
```

## 2. 复用与裁剪

复用Research的正文投影、来源校验、Unicode位置及单表契约；依据TextTiling的左右窗口、余弦连贯度和谷值深度思想独立实现边界算法。参考上游为`ql-link/LinkRag`提交`558968d814e8b8838f9296bdab62e1af36ab875e`，交接依据为相邻`LinkRag-chunking/PROVENANCE.json`。

适配删除“未超长就透传”和“装不下才找语义切点”门控：含两个及以上候选单元的短帖也参与向量评分，先选语义边界，再处理长度。使用最小段长保护，不迁入短段默认向前合并器。

不迁入Markdown解析、标题层级、图表／代码保护实体、派生块、描述增强、overlap、最终片段向量化、检索／生成服务和MQ。普通正文中的相应字符仍原样保留。首版为同步本地provider和批处理，失败后利用有效文件缓存重建运行，不建设断点作业系统。

当前源码未复制上游实现；如后续需要复制，先核对上游许可并保留声明。上游mock测试只说明交接代码的测试范围，不作为本项目验收证据。

`TokenCounter.count(text)`只计正文，`input_count(text)`计实际模型输入，`offsets(text)`提供原文码点区间，`max_input_tokens`为本轮模型输入上限。`choose_boundaries`再次核对候选跨度及token数；N≤1允许`vectors=None`，N≥2要求每单元一行有效向量。

`TextSegment.seg_id`是单帖从1开始的整数，入库映射为`seg_no`；数据库`segment_id`是64个十六进制字符的SHA-256摘要。`GapScore.index`、`semantic_boundaries`与`length_boundaries`都是**零基gap序号，不是原文位置**；`selected`表示最终由语义或长度规则选中。

`SegmentationResult.reason_code`保留投影含义。语义诊断另记：

```text
decision: empty | single_unit | scored_keep | scored_split | length_split | failed
unit_count, candidate_gap_count, embedded_unit_count, cache_hit_count, model_call_count
selected_boundary_count, semantic_boundary_count, length_boundary_count
reason_codes, model_identity_sha256, vector_content_sha256
```

逐帖摘要写入`posts.jsonl`；单元跨度、gap的c/d及理由写入`semantic-trace.jsonl`，用post与正文hash关联，manifest绑定文件SHA。阈值可由配置和depth列表重算。`post-evidence.jsonl`保留入库后还原原结果JSONL所需摘要；向量缓存和trace另作为私有重放资产保存。

工具存在不等于真实语料已通过验收。具体CLI见第11节；真实运行、语义复核、跨模型适配和正式发布的状态仅在B05维护。

## 4. 原文与候选单元

1. 复用纯文本／Delta投影，不拼标题、不去重、不改写正文空白或Unicode。位置始终相对可读正文S，采用Unicode码点零基左闭右开区间。
2. 句末`。！？；!?;`及CRLF／CR／LF／U+2028／U+2029产生候选边界；连续句末符号和紧随闭引号／闭括号归前一个单元，CRLF整体处理。切点必须位于`regex \X`字素边界。轻量http(s) URL识别保护区间内ASCII `!?;`，区间截止于空白、尖括号、引号或中文句末符号；超长URL仍按长度规则处理。
3. `.`不作为常规边界；逗号、顿号、冒号只用于超长单元细分。列表只识别换行，不推断层级；转折词不直接触发边界。
4. 只trim整簇均属于`integrity.WHITE`的首尾字素，FEFF及带非WHITE组合符的簇保留。除WHITE外均为Unicode `P*`的候选在细分前优先并入前邻，无前邻则并入后邻；emoji不享有额外合并例外。
5. 超过`unit_max_tokens`的单元先逐一重计弱边界，取最靠后且不超限的原文前缀；无可行点则按token offset提出切点，退到完整字素并重计，必要时逐字素后退。每轮cursor严格前进。不得`decode(tokens)`重建正文，也不得假设BPE前缀计数单调而直接二分。
6. 单字素超过单元预算时，只要完整模型输入及最终段长均未超限，即保留并记录`unit_oversized_grapheme`；超模型输入上限报`unrepresentable_grapheme`，超最终段长报`unsplittable_segment_limit`，两者同时超限优先前者。不能拆坏字素或截断；不可信offset明确失败，不用字符数替代。
7. 不将候选单元预装成目标段长。单元顺序覆盖全部非WHITE字符，允许空白间隙；最终片段可以合并多个单元。

使用模型同revision的tokenizer。Qwen原生NFC normalizer保持并记入身份，**存储正文不规范化**；token offset触及组合字素的一部分时扩到原文字素包络，再核对顺序和覆盖，仅作为切点建议。窗口预算可累计单元正文token数，最终段长必须重新计数完整原文子串。模型输入上限另按模板及tokenizer实际特殊token行为计数，不手工追加EOS。

## 5. 语义边界与经验参数

### 5.1 连贯度与depth

N为单元数，M=N−1为gap数。逐单元向量验证后L2归一化。对gap i，两侧分别收集最近单元，累计正文token数达到`window_tokens`或遇到帖首尾即停；每侧至少一单元。各侧向量取算术均值，再计算余弦`c_i`。纯计算使用CPU float64，有限余弦夹到[-1,1]；窗口均值范数≤1e-12或非有限时报`invalid_window_vector`。首版不平滑。

从c_i向两侧沿`next >= current - epsilon`继续扫描，到不满足条件或端点停止；L_i、R_i为各侧已访问区间（含c_i）的最大值。实现以两次线性递推计算：

```text
d_i = max(0, L_i - c_i) + max(0, R_i - c_i)
T_depth = max(depth_floor, mean(d) + depth_std_factor * population_std(d))
```

c曲线从左到右组成最大连续近等平台，组内`max(c)−min(c)≤epsilon`；平台外存在的邻值须大于`平台min(c)+epsilon`，才算低谷。端点允许单侧低谷；整曲线只有一个平台时仍保留一个代表。代表gap取平台下标中点向下取整。

候选满足`d_i≥T_depth`或`c_i≤absolute_cohesion_threshold`才可切。先按d降序、再按c升序分组，每层组内极差≤epsilon，最后按原文位置升序排序；避免非传递的两两近似比较。依序尝试候选，利用已选左右边界检查新增两段，任一侧少于`min_segment_nonspace_chars`则抑制并记录原因。非空白计数沿用WHITE，不按编码属性判断。

### 5.2 短帖分支

N指纯标点归邻、超长细分完成后的候选单元数，不是句子数或正文长度档位。

| 单元数 | 行为 |
| --- | --- |
| N=0 | 成功空结果，`empty`；NULL另保留投影原因 |
| N=1 | 不请求单元向量，完整保留并检查最终长度，`single_unit` |
| N=2 | 两个单元均需向量；d=0，按绝对连贯度与最小长度决定 |
| N=3 | 按同一公式允许端点单侧谷，不另建短帖模型 |
| N≥4 | 常规窗口／谷值规则，无合格边界时`scored_keep` |

N≥2的向量可来自模型或已验证缓存；`embedded_unit_count`表示参与评分，不等于实际forward次数。候选内部没有边界的短帖仍无法识别所有话题变化；绝对阈值使短序列可判，但效果须实测。

### 5.3 硬长度限制

语义切点确定后，对每个区间的完整正文重计token。超`max_segment_tokens`时遍历能使左段不超限的单元边界；若存在左段与当前区间剩余部分均满足最小非空白长度的边界，仅在此子集选择，否则在全部可行边界中选择并记录`short_segment_due_to_limit`。排序沿用d/c容差分组，同组位置优先靠后。循环处理剩余部分；无可行边界则失败，不截断。

长度切点独立记入`length_boundaries`，只要存在即令decision为`length_split`，同时保留已选语义切点。没有长度压力的短整帖允许小于最小段长。最终段不重叠，非WHITE字符恰好覆盖一次，编号连续。

硬长度限制保证可表示的长度与原文完整性，不保证每段的题头、指代或评价对象自足。换行和句末只提供候选位置；策略是否减少上下文破坏须阅读全文比较。实验中提出但未采纳的边界策略只保存在B05及其绑定证据，不改变本节规则。

### 5.4 初值与调参预算

| 字段 | 初值 | 开发比较 |
| --- | ---: | --- |
| `unit_max_tokens` | 64 | 首轮固定；单元策略修改须重新生成候选及向量 |
| `window_tokens` | 64 | 32、64、128 |
| `absolute_cohesion_threshold` | 0.55 | 0.45、0.55、0.65，逐模型判断 |
| `depth_floor` | 0.15 | 首轮固定，有逐例证据再修订 |
| `depth_std_factor` | 0.5 | 首轮固定 |
| `min_segment_nonspace_chars` | 12 | 防碎片保护，不是研究编码单位定义 |
| `max_segment_tokens` | 384 | 硬上限；强制切点单列 |
| `epsilon` | 1e-6 | 数值分组容差，不是跨设备验收阈值 |
| `smoothing` | 0 | 不提供平滑分支 |

这是经验起点，不是已验证最优值。每个模型先看初值，再最多比较9组窗口×绝对阈值；其他参数固定。相同单元及模型身份可重放缓存向量，窗口和阈值不进入缓存key。

## 6. 模型输入与工程smoke

本地工程验证使用0.6B；4B、8B仅为后续比较候选，正式模型未锁定。修订模型选择须留下依据，不能沿用0.6B参数冒充正式调参结果。

| 用途 | 模型及固定revision | 完整维度 |
| --- | --- | ---: |
| 本地验证 | Qwen3-Embedding-0.6B：`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3` | 1024 |
| 比较候选 | Qwen3-Embedding-4B：`5cf2132abc99cad020ac570b19d031efec650f2b` | 2560 |
| 比较候选 | Qwen3-Embedding-8B：`1d8ad4ca9b3dd8059ad90a75d4983776a23d44af` | 4096 |

资产准备与推理分离：显式下载固定revision，核对文件大小和SHA；当前CLI只读本地缓存。依赖由`pyproject.toml`的`semantic`组声明，实际版本写入身份；首轮不引入量化、MLX/GGUF转换或维度截短。4B／8B比较前分别用其真实tokenizer核验同一冻结清单，候选跨度、token数及诊断必须一致，模型身份可不同。不一致时保留失败证据并修订比较设计，不能重写旧清单绕过核验。跨模型必须分别产生真实run及参数比较包，再使用第9节的汇总工具；工具存在不表示候选模型已经实测。

统一模型输入为`Instruct: Retrieve semantically similar text\nQuery:{原文单元}`，其中`\n`为换行。模型与tokenizer同revision，原生特殊token、左padding、不手工加EOS；末有效token pooling、FP32 L2归一化、`eval()`和`inference_mode()`。仓库本机配置为FP32、batch=1、eager attention、`use_cache=False`，关闭截断，每条含模板的实际输入上限256 tokens。模板不写入片段，也不影响原文offset。 CUDA固定左padding到`max_input_tokens`（当前256），避免同文本因伙伴长度不同而改变序列宽度和有效token位置；CPU／MPS保留按批内最长输入padding。实际CUDA身份必须记录`padding_strategy=max_length`与`padding_max_length`，与配置不符或缺失拒绝验收。固定padding不截断输入，也不保证跨batch／硬件逐位一致；仍须通过预先声明的数值和资源门，重新测量其计算代价。

`embedding_probe.run_smoke`默认macOS路径固定先CPU 2条、再MPS 12条合成输入，独立进程依序退出；重复推理和batch=1/2比较均绕过缓存，另测缓存miss、重排hit、损坏拒绝及超长输入在forward前拒绝。每组保存实际身份、向量及调用计数。FP32工程门槛：L2范数偏差≤1e-5；同设备重复的最大逐元素／成对余弦差≤1e-5；batch变化与CPU/MPS差≤1e-4。超差失败，这些门槛不评价主题效果。

macOS smoke与语义研究CLI均由独立进程监督：每2秒采样worker RSS和系统swap；RSS上限8GiB，swap相对整轮起点增量上限512MiB；macOS压力标志1／2／4分别为normal／warning／critical，达到critical停止。退出时复核系统读数和worker报告的最高RSS。系统swap包含其他应用，不能据此归因模型独占资源。Qwen provider在MPS入口设置推荐工作集50%上限。

| 入口 | 默认时间预算 | 适用范围 |
| --- | --- | --- |
| `text_embedding_probe.py` | 加载300秒、单次推理120秒、整轮600秒 | 默认CPU→MPS；显式算法及资源策略启用Linux/CUDA |
| `text_segment_research.py --algorithm-config …` | 加载300秒、合成预检120秒、完整单帖1,800秒、整轮14,400秒 | macOS或显式策略的Linux/CUDA；单帖预算覆盖其全部forward |

研究CLI可显式设置加载／单帖／整轮预算并记录，macOS资源上限保持不变。底层`run_semantic_batch`只负责批处理，不自行提供外部进程保护；真实运行使用上述CLI。Linux/CUDA接口不包含租机、连接、传输或远端调度；目标环境准备与实机验收状态见B05。批次在处理语料前对两条合成输入预检，调用数另记为`preflight_model_call_count`，不计入语料调用数。smoke通过不证明完整语料容量。

Linux／CUDA采用独立的显式资源策略，接口为`--resource-policy PATH`：JSON仅含`rss_bytes`、`additional_swap_bytes`、`cuda_device_uuid`、`cuda_memory_bytes`四个必填字段。RSS和显存预算为正整数字节，新增swap预算为非负整数字节，0表示不允许增长；UUID必须是完整单卡`GPU-…`，不接受设备序号或MIG。数值上限依据实际主机在运行前确定，没有Linux默认值。macOS仍使用上述固定政策，不接受这份Linux策略。worker仅看策略指定的GPU UUID，逻辑设备为`cuda:0`；父进程用同一UUID查询该卡已用／总显存。进程RSS来自`/proc/PID/status`，swap为`/proc/meminfo`可见的系统全局用量；它们不是cgroup专属读数。Linux压力等级记为不适用，不伪造macOS normal。父采样显存峰值与worker的Torch allocated／reserved峰值分别保存，后者只覆盖分配器；Linux的`ru_maxrss`由KiB转为字节。超门或失去采样仍停止worker、不发布半包；停止阈值及本次触发读数均留存。

CUDA合成验证复用显式算法配置中的型号、revision、输入策略、设备及精度，单独运行全部12条合成输入，不要求大模型先在CPU执行。重复、batch=1/2、重复文本、缓存重排／损坏拒绝和超长forward前拒绝均保留；FP32沿用本节固定数值门并禁用TF32。低精度必须在启动前通过`--numerical-tolerances`内联JSON显式声明`repeat`、`batch`、`norm`三个有限正数，记录到本次证据中；不在失败后自动放宽或改精度。实际浮点参数的dtype和设备须与声明一致，BF16须有原生支持。现有macOS默认smoke行为不变。上述接口的实现及目标硬件验收状态见B05；本机测试不能代替Linux／CUDA实机验收。

## 7. 缓存、失败与复现

缓存为`results/`下私有文件，不建业务表。命名空间绑定实际模型／tokenizer资产SHA、revision、模板与特殊token、pooling、归一化、维度、设备、精度、batch大小、CUDA padding策略及长度、线程数、attention及依赖版本；条目key为精确模型输入UTF-8摘要。目录0700、文件0600，float32 `.npy`禁止pickle，临时目录核验后原子rename。

命中仍核对摘要、数量、顺序、维度、有限值及范数>1e-12；重复输入复用向量，输出按原序还原。`cache_hit_count/cache_miss_count`按输入位置累计，provider调用数按真实forward累计。损坏或已有冲突内容拒绝复用，不静默覆盖。首版单进程单写者；并发运行使用不同目录。

| 情况 | 当前处理 |
| --- | --- |
| 投影失败、不可表示字素、单帖边界／长度错误 | 逐帖`failed`，片段为None；其余帖可继续，失败批不可导入 |
| 模型／tokenizer／缓存契约错误（`EmbeddingError`）、OOM、I/O错误 | 异常向上结束attempt，不降为成功或回退旧算法 |
| 正文来源、模块或模型身份运行中变化 | 拒绝发布运行包 |
| 评分后未选边界 | 正常`scored_keep` |
| 用户中断／进程异常 | 尽可能留下attempt终态；无完整manifest视为不完整 |
| 全量入库时单帖超过2,000段 | 导入校验拒绝；开发批次仍须统计并解释该情况 |

`text_segment_research.py`的语义路径在输出目录旁创建`<输出名>.attempt.json`与`<输出名>.runtime/`，留存阶段、资源采样、私有日志及实际执行的源码快照；worker从该快照运行，父进程完成资源和终态核验后才发布完整run目录。attempt是运行证据，不是可续跑的逐帖checkpoint。异常清理本次临时包，保留有效缓存；重跑使用新输出路径、同来源及显式配置，重新生成完整结果。控制台仅显示异常类型，稳定原因码在attempt，可能包含原文的完整traceback仅在私有日志中。

`text_embedding_probe.py`仅处理合成输入，证据保存在其输出目录内的`summary.json`及设备子目录；不生成研究run或旁置attempt。CUDA分支另外绑定并执行完整源码快照，记录模型配置、合成输入摘要和数值容差。

同向量、同配置的边界必须逐项重放一致；跨平台CPU float64评分末位差的限定验收见第9节，不放宽切点或模型数值门。模型重复／batch／设备比较另存实际向量，记录数值差及边界是否变化；不能以缓存命中代替重复推理。模型数值门、固定向量算法验证、真实语义效果分别判断。正式运行保留模型资产、实际代码与配置、输入manifest、向量缓存和trace，不能仅凭`HEAD+dirty`说明运行实现。

<a id="s08"></a>
## 8. 单表与运行身份

表结构继续使用`storage.SCHEMA`：STRICT表`text_segments`，字段及顺序为`segment_id, source_post_id, seg_no, text, start, end, batch_id`，保留主键、CHECK及`UNIQUE(batch_id,source_post_id,seg_no)`。验收检查列、STRICT、索引和约束行为，拒绝额外业务表。`source_post_id`对应冻结来源`web_posts.id`；位置仍相对可读正文。

一个发布包只含一个活动batch。每轮在新目录建立同结构数据库文件，不按算法另建表、不追加第二batch、不原位删除旧行：

```text
batch_id = SHA256(完成运行manifest的精确字节)
segment_id = SHA256(f"{batch_id}:{post_id}:{seg_no}".encode("ascii"))
```

旧答案不能按post与seg_no转移给新片段。新运行身份为`semantic-text-segmentation-run`，旧`objective-text-segmentation-run`仍可验收，未知身份拒绝。显式成员运行使用`scope=development`，即使恰好包含所有成员也不能入正式包；离线输入自动固定全部包成员，始终为development。只有配对库输入且无成员筛选才是`scope=full_corpus`。

发布包仍为五文件：`text-segments.sqlite`、`manifest.json`、`input-config.json`、`source-run-manifest.json`、`post-evidence.jsonl`。仅成员完整、无failed且来源／结果校验通过的全量run可导入；成功构建后整目录rename。同run重复导入返回`already_imported`并复验，另一batch写同目录拒绝。包schema保持1；Admin启动不依赖模型或向量缓存。

五文件校验可重建原结果JSONL摘要，**不等于重算了语义边界**；语义重放仍需要另外保留的trace、向量和代码。

## 9. 开发比较与验收

执行顺序为工程smoke及固定向量验证 → 真实开发批次 → 模型／参数比较 → 冻结候选 → 全量无损校验 → 独立抽查 → 用户查看 → Admin发布验收。开发验证复用B05登记的已冻结81帖成员；阶段完成状态见B05，不因再次阅读本协议重跑或另抽样替换既有证据。

现有采样器用单个`random.Random(20261011)`，按正文码点长度1—100、101—300、301—1,000、1,001+四层依序处理；每层post_id排序后抽20帖。`development_post_ids`按层及ID记录，另加入未被抽中的最长帖（长度并列取较小ID），最终案例按全局post_id排序。当前工具只增加这一压力帖；如需Delta、弱标点长文、重复句、emoji／列表等额外针对性案例，后续扩展显式成员及原因记录，总数最多12篇、去重，并纳入开发排除集合。

同一模型使用`text_segment_compare.py`固定成员、输入策略、单元和向量，按第5节最多9组参数重放。工具先核验真实run与冻结单元，要求初值片段的文本／跨度及decision的结构、类型、候选、选择、理由和边界逐项一致。仅gap的`cohesion/depth`允许跨平台CPU float64绝对差≤1e-12（无相对容差，必须为有限浮点数），并保存逐帖是否精确一致与最大差值；这不用于模型向量、缓存摘要或边界选择。阈值附近若末位差实际改变了选择，仍拒绝比较。比较材料的baseline保留原run的decision，本地参数重放保留实际重新计算的评分，不改写远端trace。缓存缺失、损坏或与原trace向量摘要不符时失败，不发起模型调用。

离线输入的成员、原文和单位沿用原样本，`frozen_units_sha256`按实际包身份重新绑定；原全库身份下的摘要另存为`parent_frozen_units_sha256`。各模型必须复用同一个导出包；旧配对库run不能直接与新包run混成同一比较，可另生成同包身份的缓存基线。回传核验与参数比较须显式提供原离线包、本地配对来源和原样本，逐帖重新核对来源，不以远端的parent声明替代。技术核验仍不代表语义质量通过。

不同型号使用`text_segment_models.py`汇总各自的比较目录与原run。至少需要两个不同`model_id`，同一型号的设备变体不能冒充两个模型；同源成员、开发／压力角色、候选跨度及token数、输入说明和参数预算必须一致。开发运行与比较入口只接受已登记的`rule_version`／`implementation_version`配对；文件摘要合法不能替代规则身份核验，不同边界方法不能混入同一模型效果比较。工具从原run／trace重建可核验计数和统计，将耗时、预检／语料调用数与资源报告绑定回原运行；不重新计算embedding，段token数沿用有文件摘要绑定的原比较观测。输出`manifest.json`、`summary.json`和`post-index.jsonl`，索引指向原模型／配置的案例与待复核文件，不复制已填判断。技术汇总始终保留质量`pending`；4B／8B的选型仍需实际阅读和资源证据；若8B较4B没有稳定改善，优先4B。本轮0.6B作为工程对照，不因费用或段数直接转为正式模型。

工具按四个长度层报告单元数及有候选比例、向量／缓存参与比例、整帖保留率、段数和长度分布、语义／长度切点及失败原因。真实逐帖处理耗时`processing_seconds`与缓存重放的边界计算耗时`boundary_seconds`分开，均不冒充完整运行总耗时；RSS与系统swap属于整轮观察，不分摊为某长度层或某参数组的内存。助手阅读原文后判断过碎、漏切与上下文破坏；生成统计或待复核表不自动得出`usable`。

候选模型与参数冻结、全量候选包验收后，使用数据库sample CLI的`--independent`从排除全部开发／压力／调参帖的剩余人口简单随机抽50帖，初次种子`20261012`。排除清单绑定同一来源，记录排除集合和剩余人口摘要；剩余不足50时失败，不回填开发帖。不得预看独立样本再用于调参；若其问题促使改参，整批转为开发证据，记录新种子另抽，不覆盖旧清单。后来查看并用于调参的全量个案也加入排除集合。

助手复核记录至少包含`post_id, sample_role, config_id, technical_pass, assistant_judgment, issue_codes, affected_spans, explanation, suggested_change, reviewer_kind, review_time`；`reviewer_kind=assistant`，判断为`usable/needs_change/uncertain`。保留完整原文及新旧对照，不称为人工金标准或准确率。

发布前须技术不变量全部通过、无未解释failed、Admin兼容通过、独立样本逐篇复核完成。`needs_change/uncertain`应修订重测或由用户明确接受局限；助手汇总10—15个代表性正反例及全部未解问题交用户查看。参数或策略修改后不能沿用旧抽查结论，50篇也不代表总体准确率保证。

## 10. 关键验证场景

下列是契约断言，具体测试及完成证据分别以`tests/segmentation/`和B05为准；真实模型的主题切点不写成未经实测的正确答案。

| 场景 | 必须验证 |
| --- | --- |
| NULL／空白、一个单元 | 成功空结果／单段；逐帖无向量调用，不混同已评分 |
| 两个足够长单元，指定cos=0.9或0.2 | d=0仍可按绝对阈值分别保留或切开 |
| `好看！方便！` | 最小长度可抑制切分，文字和标点完整 |
| 三单元，mock token数各16、各含至少12个非WHITE码点，向量(1,0)/(0,1)/(0,1) | window=64时c=(0,1/√2)、d=(1/√2,0)，按初值选择首gap |
| 平坦曲线／近等平台 | 单一中点代表、容差分组稳定、无密集随机边界 |
| 重复句、URL、小数、CRLF、闭引号 | offset来自扫描，不用`find`猜重复位置；符合第4节规则 |
| emoji、组合重音、FEFF、单字素超限、长弱标点文本 | 字素不拆、原文不改；超限明确例外或失败，并观察耗时 |
| 合法／损坏Delta | 复用现有投影，损坏结构失败，不补造内容 |
| 缺向量／错维度／NaN／Inf／零向量 | provider或缓存错误终止attempt，无静默回退 |
| 窗口均值相抵为零 | 单帖失败，不以零余弦制造边界 |
| 断电／中断、坏缓存、来源漂移、不同batch写旧目录 | 不发布半包、不静默修复，重跑与旧证据分开 |
| 新旧包切换／回退 | 新旧冻结材料与答案保持各自身份，不能混批追加 |

## 11. 已实现CLI及使用边界

从项目根目录使用`.venv/bin/python`。以下`RUN_ID`替换为新的路径标识，`MEMBERS_ID`替换为B05中已冻结开发样本目录的后缀；失败重跑也必须换`RUN_ID`。下载资产与资源安排在命令之外完成。既有Mac 0.6B smoke无需因阅读本文重跑；更换模型、revision、设备、精度或数值契约时，先完成对应合成验证，再执行开发语料。

```bash
# 固定0.6B受监督smoke，只用合成输入
.venv/bin/python scripts/text_embedding_probe.py \
  --output results/semantic-local-smoke-RUN_ID

# 核验已冻结成员与单元，只运行tokenizer，不重抽81帖
.venv/bin/python scripts/text_segment_development.py \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --output results/semantic-development-unit-check-RUN_ID

# macOS：对同一开发成员运行真实模型，启用独立进程资源监督
.venv/bin/python scripts/text_segment_research.py \
  --config configs/text-segmentation-research.json \
  --algorithm-config configs/text-segmentation-semantic.json \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --cache-dir results/semantic-embedding-cache \
  --output results/semantic-development-run-RUN_ID

# 仅在上述run完整发布后：同一模型3×3参数重放、分层统计及待复核表
.venv/bin/python scripts/text_segment_compare.py \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --run results/semantic-development-run-RUN_ID \
  --cache-dir results/semantic-embedding-cache \
  --resource-report results/semantic-development-run-RUN_ID.attempt.json \
  --output results/semantic-comparison-RUN_ID
```

`text_segment_development.py`仅在首次建立开发集时省略`--members`；本轮已有清单，不重抽。`text_segment_research.py`携带`--members`时重建并逐项核对冻结单元，单元变化即拒绝；省略`--algorithm-config`仍用旧算法。`text_segment_compare.py`一次只接受一个模型的run，`--algorithm-config`可重复提供预登记网格内的子集，省略时比较九组；输出的复核表初始均为`pending`。

Linux/CUDA在已准备好的目标主机运行下列入口。`MODEL_CONFIG`是包含该候选真实revision、`device=cuda`和精度的算法配置文件；`RESOURCE_POLICY`是按第6节确定的该主机资源策略文件，均须替换为实际路径。以下smoke示例适用于FP32；FP16/BF16另加`--numerical-tolerances`，值在运行前确定，不能把FP32已通过结论直接迁用。

```bash
.venv/bin/python scripts/text_embedding_probe.py \
  --algorithm-config MODEL_CONFIG --resource-policy RESOURCE_POLICY \
  --output results/semantic-cuda-smoke-RUN_ID

.venv/bin/python scripts/text_segment_development.py \
  --algorithm-config MODEL_CONFIG \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --output results/semantic-candidate-unit-check-RUN_ID

.venv/bin/python scripts/text_segment_research.py \
  --config configs/text-segmentation-research.json \
  --algorithm-config MODEL_CONFIG --resource-policy RESOURCE_POLICY \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --cache-dir results/semantic-embedding-cache-MODEL_ID \
  --output results/semantic-development-run-RUN_ID
```

三个入口使用同一候选配置；`MODEL_ID`替换为本次模型运行标识。先完成smoke和冻结单元核验，再启动研究批次；之后沿用上方参数比较入口。CLI不负责远端部署，目标主机仍须核对本地资产、依赖与配对只读来源。

若目标主机只使用冻结开发包，改用以下路径。先在本地导出三文件包；远端smoke仍使用上方命令，随后研究入口在正文推理前自动重建并核对包内单位。`--frozen-input`与该运行入口的显式`--config/--members`互斥；`--code-version`仅为无`.git`源码包提供非空来源描述，实际执行身份始终以`code_snapshot.sha256`为准。省略它仍要求Git可用，不会静默回退。

```bash
# 本地：来源核验后导出，不加载embedding权重
.venv/bin/python scripts/text_segment_development.py \
  --export-frozen-input --config configs/text-segmentation-research.json \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --output results/semantic-development-input-INPUT_ID

# Linux/CUDA：仅传入已核验的开发包，不需要配对数据库
.venv/bin/python scripts/text_segment_research.py \
  --frozen-input results/semantic-development-input-INPUT_ID/input-manifest.json \
  --algorithm-config MODEL_CONFIG --resource-policy RESOURCE_POLICY \
  --code-version SOURCE_PAYLOAD_ID \
  --cache-dir results/semantic-embedding-cache-MODEL_ID \
  --output results/semantic-development-run-RUN_ID

# 回传本地：重新核对配对来源、原样本、输入包和运行
.venv/bin/python scripts/text_segment_development.py \
  --verify-run results/semantic-development-run-RUN_ID \
  --frozen-input results/semantic-development-input-INPUT_ID/input-manifest.json \
  --config configs/text-segmentation-research.json \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --output results/semantic-return-verification-RUN_ID

# 本地：只读缓存重放，也会重新核对本地来源
.venv/bin/python scripts/text_segment_compare.py \
  --frozen-input results/semantic-development-input-INPUT_ID/input-manifest.json \
  --config configs/text-segmentation-research.json \
  --members results/semantic-development-MEMBERS_ID/manifest.json \
  --run results/semantic-development-run-RUN_ID \
  --cache-dir results/semantic-embedding-cache-MODEL_ID \
  --resource-report results/semantic-development-run-RUN_ID.attempt.json \
  --output results/semantic-comparison-RUN_ID
```

包和源码目录可迁移，精确文件摘要保持不变。加载、运行和发布前均复验离线输入；文件漂移拒绝发布并保留缓存。`--cache-dir`是派生向量缓存，模型资产仍由父进程与worker一致的HF缓存配置解析。上述命令不包含租机或上传动作。

各候选完成各自真实运行与参数比较后，使用显式配对目录汇总；`MODEL_A`、`MODEL_B`替换为实际运行标识，不重新加载模型或读取源库：

```bash
.venv/bin/python scripts/text_segment_models.py \
  --comparison results/semantic-comparison-MODEL_A results/semantic-development-run-MODEL_A \
  --comparison results/semantic-comparison-MODEL_B results/semantic-development-run-MODEL_B \
  --output results/semantic-model-comparison-RUN_ID
```

正式模型、参数和实际配对来源冻结后，才生成`scope=full_corpus`运行：在配对库输入路径（未传`--frozen-input`）下，语义研究CLI省略`--members`会处理全部keep成员，因此不能在开发阶段随意省略。离线包路径始终为development。现有0.6B配置不代表正式配置；远端执行须先通过第6节的目标硬件验收。以下导入示例要求合格全量run已经存在，不能用开发run改名代替：

```bash
.venv/bin/python scripts/text_segment_database.py import \
  --run results/semantic-full-RUN_ID \
  --output data/processed/text-segments-semantic-RUN_ID \
  --config configs/text-segmentation-research.json
.venv/bin/python scripts/text_segment_database.py verify \
  --bundle data/processed/text-segments-semantic-RUN_ID

# 锁参和全量验收后独立抽50帖，排除开发/压力成员
.venv/bin/python scripts/text_segment_database.py sample \
  --bundle data/processed/text-segments-semantic-RUN_ID \
  --output results/semantic-independent-review-RUN_ID \

  --exclude-manifest results/semantic-development-MEMBERS_ID/manifest.json
```

若另有已查看并用于调参的帖子，抽样前必须补齐排除集合：`--exclude-manifest`可重复接受与正式包具有同一配对库input身份的开发或比较manifest。离线比较包的input身份不同，不能直接用来排除；沿用导出前的原开发样本manifest排除这81帖。额外ID用`--exclusion-manifest`传入`{"artifact_kind":"semantic-development-exclusions","input":原来源身份对象,"post_ids":[...]}`。不得只排除随机80帖而遗漏压力帖或后续调参帖。工具记录抽样框和排除依据，但不会自动知道哪些帖子曾被查看。

向量缓存默认在输出旁`.semantic-vector-cache`，不得放入待原子发布的run或runtime目录。常规测试使用`.venv/bin/python -m pytest tests/segmentation`，采用合成正文及固定／mock向量；真实模型测试和效果复核单独执行。

## 12. Admin验收、切换与回退要求

本节为后续交付要求，当前Research CLI不执行Admin发布。Admin读取`TRIPPOST_ADMIN_RESEARCH_SEGMENTATION_DIR`指向的完整五文件包；Research current指针不是切换开关。

先在隔离Admin库验证：七字段映射、完整正文与Unicode位置、空正文不可选、1—2,000段限制、文件hash及缓存失效、保存前重验、新旧dataset隔离、旧任务拒绝新batch。断开旧外部包后，已冻结任务的正文、片段、答案、比较与导出仍应可用；现有代码若兼容，保留验收证据即可。

通过效果与Admin验收后，在同一变更中同步编码表、编码簿、切分方法及接入协议的具体模型、边界配置与算法／单位来源说明；研究方向已采纳，保留标签和主导评价规则。检查Admin模板及导出说明是否需新版本。旧任务的模板和材料快照不改。

发布依次核对实际环境来源、活动包和任务／答案状态；准备同源候选整包并校验；保存旧路径及配置，在隔离环境演练旧→新→旧→新；按Admin运维流程暂停新选材写入、切换环境变量并重载；复验新活动batch及历史任务。实际故障回退只恢复外部分段包与配置，**保留当前Admin自有库及切换后新增答案**；停留旧包意味着新发布失败，不能记为上线成功。

清理仅在验收与恢复证据齐全后列出具体路径和重建依据。旧算法归档、旧结果、源库、答案及最终模型／向量谱系继续保留，裁剪上游功能不等于删除历史证据。

## 13. 理论依据与证据边界

- [Hearst 1997 TextTiling](https://aclanthology.org/J97-1003/)针对多段长文的子主题边界；[Embedding-enhanced TextTiling](https://arxiv.org/abs/1610.03955)提供语义向量增强连贯度的研究依据，其对话实验不直接证明中文旅游短帖效果。
- 两／三单元的绝对阈值、端点谷、最小段长及本文单元构建是本项目适配，需通过第9节单独实测；不是上游原行为。
- 模型输入依据[Qwen官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)及[官方评估代码](https://github.com/QwenLM/Qwen3-Embedding/blob/main/evaluation/qwen3_embedding_model.py)；资产按固定revision核验，具体本地字节身份由运行manifest记录。
- MPS限制依据[PyTorch接口](https://docs.pytorch.org/docs/stable/generated/torch.mps.set_per_process_memory_fraction.html)；macOS压力标志解释参照[Apple XNU实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_memorystatus_notify.c)及本机SDK。

理论可解释、工程测试通过、真实语义效果可用是三类不同结论。本文只定义契约与验收要求，实际完成情况及支持范围统一见B05。
