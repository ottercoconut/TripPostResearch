# 客观文本片段切分规则

> 冻结规则：objective-structure-0.5；日期：2026年9月8日；状态：已通过客观结构独立验证。证据及适用边界见[冻结记录](../decisions/客观文本片段切分冻结记录.md)。本行是验收后的状态更新，规则正文与实际验证快照一致。
> 用户澄清后，本任务只做客观标点与结构切分，不按观点、评价属性、情感、主题或语义完整程度决定边界。此前0.1—0.3及实验报告保留为历史，其语义不足不再是本任务阻塞。

> 2026-09-27工程进展：规则已迁入独立模块，并按用户指定接入管理端当前10,914条keep语料；R01—R09不变，字素保护修复以独立实现ID记录。下文保留原实验与冻结时点的范围，当前调用和全量结果见[模块接入说明](../protocols/客观文本切分模块接入.md)。

## 1. 范围

2026-09-12数据更新说明：此规则及其历史验收基于旧6,835条keep人口，未自动应用到
新19,255条清洗候选。新冻结候选全部待人工终审，正式keep表为空，本次没有片段
回填；后续部署需绑定新最终成员/源快照及独立运行身份，不复用旧post+seg_id引用。

每个keep post生成有序`text_segments`数组。不同属性和正负评价同段不是错误；不调用模型、不赋编码标签。本规则的判断依据是字符、标点、换行和显式格式，不推断作者意图。

片段通过来源身份、切分版本及seg_id关联编码表，支持回看原post；不表示本轮执行编码表中的评价原子规则。本次不修改编码表，也不以其科研冻结状态阻塞客观算法验收。

## 2. 输入与字段契约

- 成员来自正式keep表，正文来自同一冻结源快照`web_posts.content_text`；源库与keep均只读。
- 固定输入S：普通文本原样使用；Delta JSON复用既有`project_structured_text`，按序拼接文本insert。不使用替换emoji、链接等表面信息的模型规范化文本。已声明非文本嵌入仅计数，未知嵌入/损坏结构失败关闭。
- 保存原body、S、各自SHA-256、投影ID与依赖哈希。坐标相对S；富文本提取后的S不是原JSON连续子串，绝不能把位置称为源JSON偏移。
- title仅作上下文，不重复拼入S；不去重标题、不补OCR、不改错字、全半角、实体、emoji或普通文本换行。
- 数组元素：`seg_id`从1连续编号；`raw_text == S[start:end]`；start/end是Unicode码点零基左闭右开，不是字节或JS UTF-16索引，前端需转换。
- NULL表示未执行/失败，查运行状态区分；[]仅表示成功检查后正文为空白。空正文或源NULL单独记录，不用标题替换。
- 跨版本引用须携带来源快照、post ID、来源版本、切分运行/版本、S哈希；不能只用post+seg_id。

## 3. 客观规则及顺序

### R01 完整token优先保护

HTML实体、显式URL、邮箱、平台表情、缩写和数字结构内部不切。实体分号、URL问号、邮箱点、小数点不作句界。URL与正文粘连或尾标点归属不明保留候选并报`URL_BOUNDARY_AMBIGUOUS`，不猜数字链接末位属于下一个编号。

缩写集合固定为Mr./Mrs./Ms./Dr./Prof./Sr./Jr./St./vs./etc./e.g./i.e.以及多段单字母和姓名首字母形态，不区分大小写；句末歧义保留提示，不运行时扩词。

### R02 句末标点

`。！？；!?;`产生候选句界，连续强标点整组归前段。`，,、：:`不是通用句界。“但、不过、而且”等连接词不触发切分。省略号、连续点、破折号、波浪线、空格不作通用句界。

非连续ASCII点只在后接空白、正文结束、闭合符号，或紧邻左右均为汉字时作候选；token、小数和编号优先保护。`❗❓‼⁉`等emoji不按外观当成感叹号。

### R03 引号与括号

成对处理`“”‘’「」『』""''（）()【】[]《》〈〉`，正确嵌套内部标点和换行整体保护。英语单词内撇号不参与配对；引用内部评价变化不触发切分。

引用内容以句末标点结束时，边界移到闭合符号及紧随强标点之后；下一非空白为逗号/顿号/冒号时保持归属句。括号补充整体保留，外部句界/换行仍可切。错配、未闭合和交叉配对报`UNBALANCED_DELIMITER`，不补字；未闭合开符号不得吞整帖后续。

### R04 换行

保护区间外CRLF、CR、LF、U+2028/U+2029形成边界。空行不产段；非空行即使短或以逗号结尾仍保留。只有确认配对结构可跨行保护，不按诗句或语义猜合并。

### R05 列表

支持行首或明确同系列递增的Day/D编号、带冒号的“第N天”、数字加点/顿号/右括号/冒号、圈号、键帽数字、中文数加顿号。层级数字需有后续短标题冒号证据。

普通叙事中的第二天不因第三天出现而变列表；无冒号中文天数仅行首接受。多位键帽`1️⃣2️⃣`是完整数字；`1️⃣-2️⃣`、`①—③`等范围整体保护。紧邻编号前emoji归新条目，不吞普通前文。

图号、金额、时间、小数及缺可靠系列证据的数字不猜拆，必要时报`LIST_BOUNDARY_AMBIGUOUS`。缺显式格式的粘连栏目保持原样。

### R06 表情

按Unicode字素簇保护组合emoji，不断开变体、肤色或ZWJ。同行强句末后的纯表情尾缀归前段，独立表情行保留成段；平台表情token整体保护。表情不决定语义边界。

### R07 标签

明确成对或单端话题token保护；连续标签块整体保留，不逐标签切，可由空白、顿号、逗号或格式符连接。明确行首/行尾标签块与普通正文分离，普通句内标签不强拆周围句子。

共用井号或单双端混合无法唯一解析时，不确定尾块保留并报`TAG_SYNTAX_AMBIGUOUS`；单个紧贴正文的开放标签歧义报`TAG_BOUNDARY_AMBIGUOUS`。不猜标签名，尾部位置说明不保证另成段。

标签闭合井号前有空白、其后又接另一标签开头时，也按不确定尾块整体保留提示，避免将前半标签留在正文而只切出后半块。

### R08 长短及异常

不按字数硬切、不删除标题、装饰行、重复短句、纯符号或纯标签。超过200码点仅提示`LONG_SEGMENT`，纯符号提示`SYMBOL_ONLY`，不是自动判错。缺明确边界的长行允许一段。

格式字符保留，不删除ZWJ。投影失败不得把JSON当普通正文继续切或冒充空数组，不补抽样本。

### R09 无损与确定性

边界先在S定位，统一裁决后编号。只允许片段两端Unicode White_Space留在间隙：U+0009—000D、0020、0085、00A0、1680、2000—200A、2028、2029、202F、205F、3000；内部空白不变。

每个非空白码点恰好覆盖一次；片段有序不重叠、非空、编号连续；端点在字素边界。同输入、规则与依赖输出必须完全一致，断言失败是执行失败，不能输出半份结果。

## 4. 验收与冻结

每次改规则后，从全部keep排除所有已见样本，随机不放回抽新50条逐条审阅；不按平台、长度、难度剔除或补抽。候选无已确认未解决系统误切后，先锁定规则、程序、投影依赖及运行时，再另抽未见50条验证。

无法唯一判定的格式有保留原文且明确提示的回退，可以带提示接受；不能有无提示系统错误。验证失败则回开发，修改后另抽新50条，不允许修改同一验证集后称通过。

冻结仅表示客观规则及异常处理通过当前验收，不保证所有未来UGC写法，也不是正式标注准确率100%。观点混合不是错误。保存版本、抽样种子、成员、输入输出哈希及审阅。
