## 目的

本审计回答一个有限问题：冻结数据库中，各平台有多少作者具备V0人工角色编码所需的最低身份材料和纵向历史。它不判断作者是不是KOL型或KOC型，也不替代编码员的`evidence_status`。

输出只保留平台级计数、比例、数据库文件名和SHA-256，不导出作者ID、昵称、主页URL、简介、认证原文或正文。源SQLite使用只读模式打开。

## 三个口径

1. **最低材料可用**：作者键稳定，且主页URL、简介或认证值至少一项非空。该口径只决定能否进入小红书/知乎V0抽样框，不要求3个日期和30天跨度，也不预判角色或证据充分性。
2. **纵向历史可用**：至少3个不同来源日期，最早与最晚日期跨度至少30天。
3. **NONE代码材料门**：同时满足前两项。它只表示材料结构允许编码员考虑`EA_NONE/CE_NONE`，不自动生成0、证据充分或最终角色。

## 执行

```bash
.venv/bin/python scripts/annotation_audit_role_platform_coverage.py \
  --database <冻结数据库.sqlite> \
  --output <新的审计manifest.json>
```

输出已存在时命令拒绝覆盖。正式论文只能引用与正式抽样同一冻结数据库哈希的结果。仓库当前旧研究切片可用于验证命令，但不能代替最新数据库审计；拿到最新快照后必须重新运行并把manifest绑定到标注轮次。

## 判读边界

- 五个平台继续进入V1—V6内容分析。
- 当前研究决定仍是小红书和知乎进入V0最低材料抽样框；审计程序不会自动增删平台。
- B站、抖音和微博缺少V0记录时属于当前测量范围之外，不能批量写成`UNK`或`NA`。
- 平台覆盖率只能证明字段可观测性，不能证明KOL型/KOC型分组已可靠。正式比较仍须通过双人信度、证据充分和平台内组别支持门。
