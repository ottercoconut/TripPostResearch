## 一、当前决定

现阶段不把Label Studio作为共同校准或首轮人工编码的前置条件。人工编码直接使用固定Excel文件；每个标签单独成列，主观字段旁保留可选疑问标记列，只有编码员确实拿不准时才填`?`。人工编码期不运行系统校验、自动提示、模型建议或转换；双人编码、信度检验和人工裁决完成并锁定金标后，负责人才能执行离线无损转换，生成规范长表`labels.csv`。

Excel只是人工录入界面，CSV是金标锁定后的规范交换和分析格式；两者都不是理论规范源。字段名、中文列头、值域、适用条件和版本均以编码表v3.16.0为准，父子关系只用于锁定后的离线审计，不自动生成或覆盖任何人工编码。固定Excel模板只承载V1—V11内容任务；V0使用独立纯人工工作簿和证据manifest，EA、CE、SC、证据充分性及最终角色全部由人填写与裁决。

## 二、当前Excel→CSV流程

| 环节 | 输入或动作 | 责任边界 |
|---|---|---|
| 任务准备 | 预填`post_id`、`seg_id`/`img_id`、原文或图像定位信息 | 不修改正式采集数据库 |
| 人工编码 | 在固定Excel中逐字段判断全部标签和状态；拿不准时才在对应字段标`?` | 不手写JSON、offset或问题编号 |
| 条件记录 | 标`?`时填写原因和一句说明；`UNRESOLVED`必须标记；文本阳性标签摘录最短充分证据 | 疑问标记不是效度、信度或模型概率 |
| 人工裁决与锁定 | 第三人逐项复核分歧，形成追加式人工金标 | 不覆盖两份原始编码 |
| 锁定后离线校验 | 检查必填、值域、结构性`NA`、父子冲突和跨字段冲突 | 只报告冲突，不静默改码 |
| 锁定后确定性转换 | 将宽表展开为`labels.csv`并生成证据offset | 转换规则不得推断新标签或回写金标 |
| 决策与升版 | 两名负责人处理规则缺口、是否实质改码及重编码范围 | 实质规则变化须先更新编码表 |

当前固定Excel共承接文本与视觉全部人工字段。文本轨包括V3的5个父类与22个子项、V4的2个父类、10个Layer 2亚类与4个事件子类、V5语言功能/评价亚类/可判定性/方向/双向强度，以及V6的适用性、4个父类、12个子类和其他项；视觉轨包括V7、V8、V9、V10和V11。所有人工标签在模型训练完成后仍分别作为模型输出目标或经批准的视觉任务目标，不能只预测父类或用逻辑OR替代人工字段。V4旧`rs_r_act`例外：它只在分析阶段由`rs_r_rec OR rs_r_evt`汇总，不进入人工模板或模型输出。

## 三、Label Studio何时才值得引入

只有出现下列至少一项真实瓶颈时，才启动Label Studio技术探针：

1. 多轮任务分配和回收已无法用固定Excel及manifest稳定管理；
2. 文本证据需要频繁的多跨度可视化框选，复制引文明显成为主要负担；
3. 图片区域级证据或视频抽帧任务已经冻结，Excel无法可靠表达；
4. 编码员数量增加，需要账号隔离、盲标分配和集中审计；
5. 已有锁定金标和测试集，准备按原研究设计验证模型预标注、主动学习或大规模协作管理。

在此之前引入Label Studio只会增加界面配置、JSON适配、权限隔离、备份恢复和版本维护成本，不解决当前更关键的规则冻结与信度问题。

## 四、若以后引入Label Studio

Label Studio只负责人工录入和证据框选；项目程序继续负责任务准备、格式转换、校验、信度、仲裁和版本追踪。技术探针应先用少量文本与图片验证：

- 全部原子字段及对应疑问标记能否无损导出；
- `0/1/UNK/NA/UNRESOLVED`是否保持原义，空白不会被误写成0；
- 中文、emoji、重复引文和重叠证据的Unicode offset是否可逆；
- A/B编码员是否真正隔离，原始判断能否按稳定ID合并；
- 导出后能否确定性转换为现行`labels.csv`而不丢失字段。

模型建议不得进入共同校准、独立盲试标或锁定测试集。视觉轨在研究人口、V7/V8边界、V11专门规则和独立信度验证完成前，也不得因工具可用而提前进入正式生产。

## 五、当前阻塞边界

工具本身不是当前阻塞。文本轨可按现行规则开始共同试编码；试编码本身正是发现边界问题的环节。进入各轨正式金标生产和主分析前仍需处理：

- `at_eval_subtype`与V4活动/事件边界须在共同校准中验证；只有出现系统性分歧才构成冻结阻塞，不阻塞启动试编码；旧`rs_r_act`记录仍须回到原文重编码；
- 共同校准后仍须用新样本完成独立盲试标并达到逐字段信度门；
- 视觉研究人口、V7/V8唯一裁决规则与V11专门状态规则尚未冻结；
- 当前文本转换脚本默认编码表版本已对齐v3.16.0，但只负责人工结果锁定后的文本格式校验和离线转换，不得用于V0金标或人工阶段的动态提示。正式运行必须显式记录版本、任务manifest和随机种子。
