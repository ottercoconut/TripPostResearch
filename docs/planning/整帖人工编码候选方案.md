## 四、候选人工记录方式

### 4.1 一篇帖子，一份主记录

编码员阅读同一版本的完整帖子，按统一标准判断：

1. V1／V2帖子级字段保持原用途。
2. V3：全文是否出现各项内容策略；符合定义才记录，不因一句话是事实就自动判为实用信息。
3. V4：全文呈现哪些资源；同一资源类别出现多次仍只记录一次出现，不推断其篇幅或重要程度。
4. V5语言功能：全文是否存在事实陈述、评价、建议；符合条件者可共现。评价亚类的单选／多选和整帖汇总仍待确定。
5. 涉及属性评价／建议时，转入该帖的属性记录，将V6属性与V5方向关联。

本文不新增正式字段代码，以上是记录结构建议。编码员仍需依据文本证据，不能凭对账号、目的地或作者动机的印象编码；内容编码不展示身份、粉丝和模型建议。

### 4.2 属性与方向的关联记录

以下为自拟教学例句，不来自真实用户数据，也不是正式金标：

> 酒店位置很好，但隔音太差。附近餐厅价格实惠，不过服务态度不好。

候选表格可以显示为：

| 帖子中的被评价属性 | 出现正面评价 | 出现负面评价 |
|---|---|---|
| 可达性 | 是 | 否 |
| 设施 | 否 | 是 |
| 价格 | 是 | 否 |
| 服务 | 否 | 是 |

这四行是同帖属性汇总，不是四个预先切好的文本片段。V6属性仍为方向中立类别，正负判断来自与该属性对应的V5表达。

**本表只是方向关联示例，不是完整可执行值域。** 正式候选表还需区分：没有相应评价、明确中性、方向无法判断、尚未完成，以及部分评价可判／部分不可判。正负都为“否”不能自动解释为中性；未完成或材料不足不能记作阴性。没有评价／建议时，也不能仅因正文出现价格数字就认定有价格评价。

若同一属性评价了不同对象，例如酒店服务差、餐厅服务好，可以记录本帖“服务正负均出现”；若研究需要区分酒店与餐厅，则必须再保留对象关联。单纯帖子×属性结构不足以支持对象层比较，不预先增加这一工作量。

### 4.3 证据定位与完整切分的区别

可以阅读全文、填写整帖标签，并在需要复核时定位一处或多处依据；这不要求把全文每个字符划入固定片段。位置可由平台生成，编码员不手算offset。

今天尚未决定是否所有阳性项都必须定位证据、同帖不同属性是否各留证据、只有疑难项定位是否足够。本稿不替用户选择；平台也不能因“整帖编码”就自动取消既有证据要求。任何减负幅度都要计入阅读、找证据和返工时间。

### 4.4 帖子表达描述候选（身份判据用途已撤回）

用户随后指出，两类表达均可能出现在KOL与KOC中，不能据此区分作者身份。v0.3.0据此撤回其身份判据用途；下方保留的是可讨论的内容描述定义、状态和例子，不是正式身份字段，也不是已批准新增的内容必填项。是否保留须先核与V3／V5的重合及具体研究用途。若保留，仍可两项独立判断、允许共现，不要求选主导或切分全文。

| 项目 | 建议工作定义 | 不自动命中的情况 |
|---|---|---|
| 面向他人的判断／建议 | 明确针对他人的旅游选择、使用或行动，给出适用性判断、比较或建议；不必出现第二人称代词 | 单纯事实参数、单独“太美了／我很满意”等个人评价，不能仅因公开发布就视为给他人的选择建议 |
| 个人消费／使用经历 | 作者明确自述本人已发生的旅游参与、消费或使用经历；记录自述证据，不核实其现实真实性 | “我推荐”、计划出行、朋友的经历、单独第一人称代词，都不能代替本人已发生经历的证据 |

判断单位是一篇帖子；在本任务约定的材料范围内至少有一处明确证据即可记录“出现”，不因重复而升级。单帖不承担“作者持续如此”的判定。是否要求建议附带理由／条件、经历须有何种具体细节，仍须用边界例明确；本版不把这些未确认的限制或数量阈值暗中设为必需条件。引述、转载与作者本人表达须区分，无法判断归属时保留相应未知。

每项分别记录以下状态；正式字段名和接口值待对齐，不新增V编号：

- **明确出现：** 约定材料中存在符合定义的证据；其他材料缺失不抹去已看见的阳性。
- **未见：** 已完成约定范围的充分核查，材料可判，未发现符合定义的表达。仅表示本帖该材料范围未见，不表示作者从无这种行为。
- **无法判断：** 材料缺漏、不可读、表述或归属含混，影响该项判断；两项可以一项明确、另一项未知。
- **未编码：** 尚未完成该项，属于任务进度，不与“未见”或“无法判断”合并。

两项均明确时，可展示“仅判断／建议、仅个人经历、两者都有、两者均未见”四种组合；它们不分别等同KOL、KOC、兼具型或其他作者。部分未知须保留，不能强行塞入四种组合。“未见”须绑定实际审阅的材料版本与范围；未提供的图片／视频不视为已读，是否影响文本标签或整帖可判状态须按任务范围说明。

以下均为自拟教学例句，不是真实数据或正式金标；“未见”仅针对表中完整示例文本：

| 示例 | 判断／建议 | 个人经历 |
|---|---|---|
| “带老人游览建议选A路线，台阶比B路线少。” | 明确出现 | 未见 |
| “昨天我坐公交去了景区，在门口排队四十分钟。” | 未见 | 明确出现 |
| “我上周住了这家酒店，两晚都被走廊声音吵醒；带孩子的家庭建议选隔音更好的酒店。” | 明确出现 | 明确出现 |
| “景区每天九点开门。” | 未见 | 未见 |

**与V3／V5的关系：** V3记录呈现方式，V5记录事实／评价／建议等语言功能；本组分别关注是否面向他人的选择，以及是否出现本人经历自述。判断／建议项与`AT-SUG`、`CS-INF-PRO`存在实质重叠；不能因改名或改成帖子级就称为独立构念。试用前应逐项对照；若与既有人工字段完全同义且单位、材料、状态一致，应讨论共用一次人工判断，避免重复填写，但本版不自动复制标签或修改金标流程。

**身份用途撤回的含义：** 判断／建议描述表达功能，个人经历描述自述依据，均不与KOL／KOC一一对应；两项都有不证明作者兼具。增加观察帖数、计算占比或设置多数票，不能自动建立缺失的身份区分依据。未来若有独立身份标准，可检验这些内容特征是否存在组间差异；目前没有这种验证，不能据此生成身份或以同一特征反证分类有效。小红书5,000／知乎10,000人数线、低粉规模路径及专业背景后置裁决未因本次纠正而改变，专业性不恢复初判。核心未决问题是哪些独立可观察的作者证据能支持身份条件，而非先为这两项补一套汇总阈值。

只有在确认内容研究确需独立保留本组后，才讨论证据定位、界面及一致性检查；不为已撤回的身份用途增加编码负担。现有定义和例子未产生正式标签。

## 五、同一属性不同强度：三个备选

自拟例句：

> 门票有点贵。景区餐饮简直贵得离谱。好在公交很实惠。

它包含价格的一般负面、强烈负面和一般正面。现行1／2是有序等级，不把差值当作等距测量；本轮未提出人工估算“平均情绪”的方案。

| 备选 | 示例记录 | 用途及代价 | 本版状态 |
|---|---|---|---|
| A：正负分别取最高强度 | 价格正面1、负面2 | 填写较少，保留最强表达；丢失一般与强烈共存信息和次数，不表示总体满意程度 | 助手建议，待用户选择 |
| B：各方向、各强度分别记是否出现 | 一般正面有、强烈正面无；一般负面有、强烈负面有 | 保留强度层次共存，不保留次数；勾选项更多 | 备选，未选择 |
| C：只记各方向是否出现 | 价格正面有、负面有 | 最简，但不再回答表达强度差异 | 备选，未选择 |

若最终选择A，拟按以下含义记录：

- 同属性、同方向至少出现一次明确强烈表达，记2；只出现一般表达，记1。
- 在适用且充分可判定时，未出现该方向，记0；不适用、不可判与未完成按独立状态处理，不用0代填。
- 重复五次一般评价，不因重复而升级为2；重复次数与强度不是同一变量。
- 正负两列分别保留，不用相减后的净值覆盖。例如正面2、负面2不等于中性。
- 含义限定为“本帖该属性出现过的最高表达强度”；一句强烈评价即可决定该方向的最高值。

长帖或评价次数较多的帖子可能更容易出现强烈表达，故A不能直接解释为作者普遍更激烈。若需要研究“整体态度”“典型强度”或具体对象的满意度，应另行定义，不能借用本方案名称替代。部分表达不可判时是否仍能确定最高值，也要在状态规则中明确，不能未经规则直接忽略未知表达。

当前选择为**未定**。备选A的展开仅供审阅，不因写入独立版本而生效。

## 六、自动切分在候选方案中的位置

已有[客观结构规则](../methods/客观文本片段切分规则.md)`objective-structure-0.5`处理标点、换行和列表，具有[独立验证记录](../decisions/客观文本片段切分冻结记录.md)。它不根据评价属性或情感方向切分，也未因此证明最新库和平台已接入。

若采用本候选，人工记录不依赖其生成的每个`seg_id`；既有结构片段可以保留用于技术处理或显示，不能据此把帖子级答案自动派给各片段。若另行探索模型语义切分，它属于需要独立检查的工程任务，不是本次减负方案已经完成的一部分。

## 七、研究与分析能够保留什么

| 可以讨论保留的输出 | 需要明确的解释 |
|---|---|
| 某资源／策略在多少篇帖子中出现 | 帖子层面的出现比例，不是片段密度或提及次数 |
| 哪些属性被评价、方向如何 | 按帖子×属性关联统计，方向与可判状态须保留 |
| 不同创作者类型的内容差异 | 身份规则和材料仍须独立通过验证，不能由本候选自动恢复角色比较 |
| 属性的表达强度差异 | 仅在选择并验证强度方案后开展，解释服从A／B各自含义；C不支持强度分析 |

仅靠本候选主记录不能直接恢复资源的片段密度、帖内出现频次、策略与资源的局部对应关系、具体资源对象与评价的绑定，或旧框架中依赖评价原子的指标。原模型与候选指标保留历史和条件状态；是否修订或放弃须另作研究决定，不因本稿自动删去。

统计时还需区分“全部合格帖子中的出现比例”和“该属性可判帖子中的正负比例”。同一作者多帖的依赖仍在，整帖记录并不会消除它。

## 八、试用与版本隔离原则

候选试用前须先选定强度方案、V5亚类与状态规则、证据要求，形成两名编码员共用的记录说明。任务界面还需通过独立账号、保存、原始答案保留及导出核验；本文不是可以直接发放的完整任务配置。

若后续获准试用：

1. 从既有材料按既定小批量安排开始，不在本稿新增人数、帖子配额或采集任务。
2. 候选任务与旧任务分开，记录方案标识、版本、材料身份及编码员；记录键不得仅靠post ID混合不同方案的答案。这里是谱系要求，具体工程字段名由接口对齐时确定。
3. 两人独立填写同一版本，保留首次答案、疑问、实际填写与找证据时间，讨论结果另存。
4. 共同校准用于修订可执行性；之后用未讨论的新材料检查帖子级／属性级一致性和类别支持。文档清楚不等于验证通过。
5. 若将同一批材料用于比较两种操作方式，注明熟悉材料和先后顺序的影响；不把这种比较当作独立盲试结果。

旧V0及内容编码、原文、结构片段和模型结果保持原样。新旧标签不能无记录地合并；即使某些存在性标签可从完整旧片段记录汇总，也须另核标签定义、缺失、材料覆盖和汇总规则，不能声称与直接整帖人工判断天然等价。

## 十、后续版本如何管理

- 本文件使用稳定名称`整帖人工编码候选方案.md`，版本号写在内部，独立于编码表版本序列。
- `v0.1.x`用于不改变测量含义的文字、链接或例子勘误；单位、字段含义、强度选项或状态规则发生改变时升为`v0.2.0`等下一候选版本，并记录选择依据。
- 后续正式提交Git时，在版本记录中补充真实commit；当前未提交就如实写“未提交”，不把HEAD冒充候选文件版本。本文记录的SHA识别建档时基线字节，不代替可恢复的版本提交。
- 用于实际任务时，绑定任务当时的候选版本和文件哈希，不只链接到可能继续更新的文件；历史答案继续指向原规则。
- 最终采用需要单独的采纳决定及编码表同步；不通过把本文件状态改为`CURRENT_CANONICAL`建立第二套最高标准。未采用则保留候选历史。
