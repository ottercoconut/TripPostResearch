> **语义优先与保守粒度冻结（2026年10月19日，`semantic-conservative-20261019`）**：统一采用“保留完整连贯块，只有明确必要时才增加边界”的口径。少标点、短行密集或空格代停顿只作为理解排版的背景，不切换另一套未定义的整帖标准。换行保留为候选位置和结构证据；换行、空格、句号、编号、对象或编码属性变化本身均不足以决定切分，不给原文批量补标点，也不把普通空格逐个升级为常规切点。除既定必切及长度兜底外，新增边界须同时满足前一叙述已经完成、后文转入相对独立的主题／叙述任务且不会割裂必要语义关系；语义相似度的局部下降只能提名，不能单独构成充分依据。

## 一、核心设计理念

### 1.1 从"感知端"到"生产端"的理论转向

v2.0 用游客感知理论（CAC三层次模型）编码创作者生产行为，存在理论错配。v3.0 将编码对象调整为"目的地资源调用策略"。这里的“策略”仅指成品UGC中可观察、可重复编码的功能性内容呈现模式，不表示创作者主动规划或意识到某种策略，也不据此推断受众效果。自v3.4.3起，所有进入编码记录表的字段均由编码员逐字段人工判断；字段间的逻辑关系仅用于试标复核和一致性审计，不得自动改写人工记录。

### 1.2 文本主轨、身份分组与视觉辅助

**2026年10月2日研究定位确认：** 文本轨提供主要分析依据，身份轨提供创作者分组依据，图片轨提供视觉补充与对照。三轨共同服务于不同类型创作者的目的地形象建构研究；“建构机理”在本研究中限指成品UGC中可观察的资源选择、表达策略、属性评价与视觉呈现的组织关系，不表示已经验证身份的因果作用、创作者意图或受众效果。模型用于扩展已冻结标签的测量范围；视觉辅助工作不阻塞文本主线。

用户已确认图片与文本可通过`postid`对应到同一篇帖子。文本、图片和身份先按各自材料独立编码，再在分析阶段汇合，按创作者类型比较。图片可辅助观察图文共同突出什么、各自补充什么及呈现重点有何不同；这些是分析方向，不新增“图文一致／互补／冲突”等人工标签。同帖对应不等于句段与单张图片一一对应，也不意味着V4资源与V7主体可直接互换标签。

<a id="image-text-correspondence-20261021"></a>

**图文对应的解释边界（2026年10月21日确认）：** 同帖归属只是关联材料的前提；只有内容证据显示文字与图片涉及相同对象或相关属性，才可描述为相应内容的跨模态共现／对应。图片把文字描述具体化，也可在功能上称为广义“互补”，不强制将重复表达与互补设为互斥类别。正式报告暂以“内容对应／图文呼应”描述可观察现象；语义重叠与是否提供额外信息须分别判断，不因使用“互补”一词就宣称已经测得信息增量。

讨论正负一致或相反前，须核对是否针对同一对象、同一属性及可比的时间／范围。文字说服务有瑕疵、图片展示菜品，并不自动相反；图片没有展示某项瑕疵，不等于否定文字。菜品照片可展示品相，不能据此验证味道、真实性或游客信任。多图可以分别对应不同段落或部分内容，不能仅凭一张图代表全帖的对应关系。

首轮V7主体及V8场景／景别／视角四字段不直接测量“江南园林风”等全部具体特征、语义增量或视觉情感；现有V11条件性可见状态也不能在未启用、未验证时补充这些判断。先由试编码复盘核对字段覆盖，正式比较前再确定类别映射、对象／属性范围、多图聚合、未覆盖状态及分母；本次不新增人工图文关系标签，不自动生成互补／冲突结果。

首轮仍按既定30张、两批各15张及V7／V8四字段检验规则，不因可对应而要求补齐每篇帖子的全部图片。当前首图或视频封面安排只覆盖选中的视觉材料；正式分析的多图、缺图及对应范围在试编码反馈后明确。单项策略或策略组合、关注程度与评价倾向的比较口径、身份差异与题材／商业披露的关系三项研究取舍，同样留到试编码反馈后、正式比较前讨论，见[总备忘录第七节](../planning/研究问题与待办总备忘录.md#research-discussion-current)。本次说明不改变编码字段、值域或首轮任务。

### 1.5 唯一方法定位：理论导向的结构化内容分析

本研究的唯一正式分析方法是**理论导向的结构化内容分析（量化取向；theory-directed structured content analysis）**。这里的“理论导向”指初始类目来自目的地形象与内容生产相关理论、GB/T 18972-2017、既有研究和预先提出的研究问题；“结构化”指使用固定分析单位、预先定义的变量和值域、证据定位、编码员训练与一致性检验，将UGC转化为可比较的结构化记录。正式结果以类目频数、比例、共现、组间差异及其不确定性为主；校准期的语境解释与分析备忘只服务于测量工具开发，不构成并列的质性分析方法。

| 方法环节 | 本研究的唯一口径 |
|----------|------------------|
| 初始类目形成 | 以理论、标准、既有研究和研究问题作演绎式定义，不把样本中的高频词或模型聚类直接升格为类目 |
| 数据反馈 | 仅在共同校准与盲试标冻结前，系统登记框架遗漏、边界案例、反例、语境依赖和切分问题；由研究团队形成书面修订决定 |
| 正式测量 | 对冻结的`seg_id`、`img_id`和帖子级字段逐项编码；以编码簿版本、证据跨度、信度和裁决轨迹保证可复核性 |
| 分析产出 | 输出结构化变量、描述统计、共现与预设组间比较；模型只扩展已冻结字段的测量范围 |
| 方法取向 | 量化取向；校准中的材料阅读、问题登记和备忘是编码簿开发步骤，不另行产出质性主题 |
| 明确排除 | **不采用主题分析法**，不生成开放代码、候选主题、主题地图或“数据饱和”结论；V0—V11是分析类目/变量，不称为“主题” |

数据反馈的作用是检验并修订测量工具，不是另开一条归纳主题轨。任何新增、合并或改写类目都必须在正式冻结前完成并升版；冻结后若发现足以改变判定边界的问题，须暂停受影响字段、启动版本评审，并按第6节规则重编码，不能在正式数据中静默增加标签。

**解释边界：** `creator_role`是本研究操作类型，`reach_tier`是独立保存的规模记录，两者不再是定义独立的变量。低粉KOC路径为本研究自定纳入规则，不宣称已由文献验证其真实消费、同伴取向或行业身份；所有角色均不证明受众信任、说服效果或实际意见领导。`ORDINARY`沿用字段值，仅解释为“其他可判定创作者”，不等于普通游客。

**范围与单位：** 内容研究保留五平台；角色可行性检查以小红书为主，知乎须独立通过材料与质量条件后补充。B站、抖音、微博暂不建立角色行，其身份是未测量，不记UNK或NA。角色观察单位仍为`平台账号 × 作者证据窗口`，同一窗口多帖只关联一次角色。单一自然人及旅游UGC纳入条件须有现有材料支持；机构／多人账号为NA，主体不清为UNK。显示名和粉丝数本身不证明个人主体。

**只用已有材料：** 不补采主页、历史帖或商业资料，不新增创作者／受众调查。主页URL仅用于追溯，不能据链接访问实时主页补证据。原始作者键及强证据仅留在受限环境，同名或相似头像不自动跨平台合并。最低材料检查包括稳定账号及可审计主页或等价主体材料，不预先按预期角色筛样。

**隔离：** T0为现有作者档案和固定历史证据，T1为待分析目标帖，两者不重复使用；内容编码员不见作者、粉丝、角色或模型建议。角色组件先在粉丝遮蔽下记录，随后按本节路径开放合格粉丝快照；粉丝可以决定最终类型，不能改写已记录EA／CE／SC。点赞、评论、收藏、转发等不参与身份判断。CI继续为`UNAVAILABLE`。

**快照边界：** 五平台均可保留规模快照，只有小红书／知乎进入候选角色范围。快照日期不得用目标帖日期代填；后置主页或粉丝不能补成历史主分析身份。工程与平台本轮不修改，旧导出器／任务包不得仅改版本号后使用。

#### V0.4 组件证据与未测状态

EA、CE、SC分别保留原子证据、来源和人工判断，粉丝不得生成或覆盖组件值。相关领域限旅游、旅行、目的地体验及直接服务旅行决策的本地餐饮、亲子、户外和生活方式内容。

| 组件 | 证据代码与候选判断 | 边界 |
|---|---|---|
| EA专业性 | `EA_CREDENTIAL / EA_DOMAIN_OCCUPATION / EA_DOMAIN_VERIFICATION / EA_INSTITUTION_AFFILIATION`中任一明确相关背景，或`EA_SPECIALIST_HISTORY`持续专业分析，支持EA=1 | 背景路径成立后不再要求持续专业分析或SC=1；一般学历、泛认证、自称专家、单篇详细攻略不能自动成立。背景自述与已有核验信息须分别记录 |
| CE经验分享 | `CE_FIRSTHAND_REPEAT`与`CE_PEER_ORIENTATION`同时成立支持CE=1；重复经历暂沿用至少两个不同日期来源作为候选参数 | 只判断第一手表述及同伴分享，不证明真实消费，不要求商业合作；不是低粉KOC路径的必要条件 |
| SC持续创作 | 暂沿用至少3个不同日期、跨度不少于30天作为历史覆盖检查参数 | 研究自定、待验证；不作为背景路径EA阳性或低粉KOC路径的共同必要条件 |

EA／CE已评估组件仍用`1 / 0 / UNK / NA`；EA_NONE／CE_NONE只在规定窗口覆盖充分时使用，不能把未见或未采集写成0。旧“3日期／30天＋可用主页或等价材料”暂作为阴性证据覆盖的候选门，不限制由明确背景获得EA=1。缺历史不代表实际偶发创作。

**未测与未知分开：** 低粉路径不强制额外评估EA／CE／SC。未评估组件值留空，在候选记录的`component_assessment_status`逐项记`NOT_ASSESSED`；已评估但证据不足才记组件UNK及`ASSESSED`。这是文档契约草案，本轮不修改数据库／平台值域，不把空白旧记录批量认定为未测，也不新增`NOT_ASSESSED`到旧组件值域。

`evidence_status`按所走路径判断充分性：低粉路径只要求个人旅游UGC纳入、账号及合格低粉快照等必要证据；EA／CE未测不使该路径自动失败。高粉路径的EA或CE任一必要维度未知时，最终角色未定。`role_evidence_json`保留来源ID、来源类型、发布日期、实际采集日期、判据及观察说明；不复制受限原文到公开材料。

#### V0.5 粉丝门与候选角色矩阵

对平台p使用固定人数门槛`T_p`：小红书`T_xhs=5,000`、知乎`T_zhihu=10,000`。两平台数值已于2026年9月24日按用户决定写入研究方案，状态为`THRESHOLD_FROZEN`，门槛规则ID为`role-followers-20260924`。`follower_count < T_p`为低粉，`follower_count >= T_p`为达到门槛；恰好5,000的小红书作者和恰好10,000的知乎作者均进入达到门槛分支。数值已定不表示身份体系已验证或正式任务已启动。

以下表格以个人旅游UGC基本纳入、账号连续性、粉丝观测与时间条件合格为前提；EA／CE的0必须有充分阴性材料。

| 粉丝条件 | EA | CE | `creator_role` | KOC进入来源 |
|---|---|---|---|---|
| 低粉 | 任意，包括未测或UNK | 任意，包括未测或UNK | `KOC_TYPE` | `SCALE`；如独立确认CE=1，再记`BOTH` |
| 达到门槛 | 1 | 0 | `KOL_TYPE` | `NONE` |
| 达到门槛 | 0 | 1 | `KOC_TYPE` | `EXPERIENCE` |
| 达到门槛 | 1 | 1 | `HYBRID` | `EXPERIENCE` |
| 达到门槛 | 0 | 0 | `ORDINARY`（其他可判定创作者） | `NONE` |
| 达到门槛且必要维度未测／未知，或粉丝／时间无法判定 | — | — | `UNK` | `UNDETERMINED` |
| 机构／多人账号 | — | — | `NA` | `NOT_APPLICABLE` |

**充分条件的层级：** 有明确专业背景但低粉，最终为KOC型，EA仍为1；有明确背景而高粉、CE=1，最终为HYBRID；CE未知则保留EA=1但最终UNK。低粉且两轴阳性也为KOC型，不是HYBRID，因为没有满足KOL规模必要条件。不能用高粉反推EA，也不能用低粉反推CE。

**候选记录契约（文档设计，未部署）：** 每个作者快照保留`role_rule_version`、门槛ID／平台／数值／冻结状态、实际粉丝值及来源时间、粉丝与门槛关系、组件状态、KOC路径、必要材料状态与最终人工角色。缺少有效粉丝证据或必要条件时路径不强行填写；使用历史规则的记录保留其当时门槛状态。`koc_entry_path=SCALE/BOTH/EXPERIENCE`用于区分纳入机制；BOTH表示低粉路径与经独立判断成立的CE并存，不是第三个角色。对照类型用NONE，缺必要判断用UNDETERMINED，机构用NOT_APPLICABLE。

`creator_role_pre_reach`、`reach_tiebreak_used`及其规则ID仅保留旧版语义，不再承担新规则。新规则中每个实质角色都使用粉丝门，不能再只标“边界裁决是否使用粉丝”。旧记录不自动改标或迁移；旧HYBRID也须按新证据／版本重新验证，不能直接纳入新分析。

**拟议人工顺序：** 先检查主体和已有证据时间；在不见粉丝时记录确有必要且可评估的组件及未测状态，不预填最终角色；随后开放合格粉丝材料，按统一门槛判断角色及路径；最后保存双人独立原始答案，再裁决必要分歧。低粉路径允许组件未测，高粉路径必须完成EA／CE判断。共同校准不作为正式信度，人工判断阶段不自动派生金标、不展示模型建议。

2. 只读核查现有粉丝数、缺失、取整、快照时间及同作者多次观测。没有原始显示或独立主页时间时记录不可验证，不把归一化整数当作精确原值。不得选择最大粉丝快照方便过门；不新增采集。
3. 按已定人数线报告规模侧人数、缺失／跨界／时间不合格比例；只有另有合格EA／CE和主体、时间证据时才能计算相应角色人数与路径。低粉人数不冒充KOC人数。此项是材料适用性与组别支持检查，不是阈值筛选实验。
4. 先覆盖低粉专业作者、高粉经验作者、高粉兼具作者、高粉但两轴阴性、缺失／取整跨界／后置快照等边界，记录作者级耗时。旧25／50名配额、15—25篇核读配额和各组10名起点均不自动恢复，正式样本支持须独立论证。
5. 规则稳定后另取现有库中未讨论作者，双人独立编码，逐组件及最终类型报告Krippendorff's alpha、类别支持、未知和系统性分歧；核心字段`alpha >= 0.80`并不单独证明构念效度。旧信度不能沿用；平台材料和组别支持不足时不合并凑组。
6. 人数门槛已定；时间门、组件边界、独立编码验证、组别支持及平台契约未通过前，正式角色比较、金标和身份模型继续暂停。五平台内容及视觉轨按自身条件推进，不等待身份轨。

**分析边界：** 分开报告KOC规模路径、经验路径及两者兼具的组成，比较结果须检查是否由某一路径主导；不能解释为整个KOC组均有消费经验或同伴取向。粉丝已参与类型定义，组间粉丝差异不是独立效度证据，控制粉丝也不能自动消除定义依赖；只在共同覆盖存在时辅助比较。不能再“剔除所有使用粉丝的案例”作稳健性，因为新规则所有实质类型都经过粉丝门。身份依据与V3—V6逐项检查概念重叠；直接用于定义的特征只作描述或校验。同一作者多帖按作者单位处理，不把片段数当独立样本。

V1只记录帖子中是否存在可直接观察的商业披露，不根据正面程度、品牌出现次数或写作风格推断真实合作关系。

| 代码 | 定义 | 识别方式 |

| 0 | 未观察到明确商业披露 | 帖文及其可用披露区域中未出现广告、赞助、合作、受邀体验或推广声明；该值不证明不存在商业关系 |

#### 主要目的地类型：整帖总体取向（v3.23.1澄清，v3.24.0新增NONE）

`destination_type`回答：**整篇帖子主要呈现什么取向的目的地内容？** 编码员阅读全文后，从原有五类和新增NONE共六个选项中选择一项，概括整帖的主要内容及呈现重心；完整文本未呈现明确取向时按下方NONE规则记录。字段继续称“主要目的地类型”，不依据景点的客观地理位置给地点分类，也不把每个片段的资源标签逐项相加后决定整帖类型。

| 代码 | 中文取向 | 整帖观察重点 |
|---|---|---|
| NATURE | 自然 | 全文主要围绕山海、地貌、动植物、天象等自然景观及相关游览展开 |
| CULTURE | 文化 | 全文主要围绕历史遗产、地方文化、民俗或其他明确的文化内容展开 |
| CITY | 城市 | 全文主要围绕城市整体游览、城市街区或城市生活体验展开；山海、历史建筑、餐饮等可作为城市体验的组成部分 |
| RESORT | 度假 | 全文主要围绕度假休憩、度假场所或相应的整体度假体验展开；仅出现酒店、住宿或“休息”等词不足以直接成立 |
| MIXED | 混合 | 全文对不同取向均有实质展开，整体没有清晰的单一主导取向；不由资源类别多、地点多或城市多自动成立 |
| NONE | 未呈现明确取向 | 已完整阅读文本，但帖子仅表达出游、到访、打卡等一般旅行动态，未提供足以识别主要目的地内容取向的具体内容；不表示其他类别、材料缺失或编码员拿不准 |

**整帖与片段的分工：**

1. **先看全文重心。** 标题、分节和篇幅可帮助理解，但不单独决定取值，不设置按字数、段数或景点数判定的固定比例。不能仅因提到青岛或位于市区就选CITY。
2. **附带信息不自动改变主类。** 自然观光帖带有交通、门票或吃饭信息，仍可保持自然取向；城市整体游览帖同时写海岸、古建筑与餐饮，仍可具有城市取向，不能只因多类资源共现就改为MIXED。
3. **V3—V6继续按固定片段判断。** 整帖选CITY不排除片段标自然、历史或饮食资源；整帖选NATURE也不排除片段有建筑设施、建议或评价。两层没有父子OR关系，不能相互代填。
4. **现有细节先由已有标签记录。** 美食、活动、资源及路线等继续按V3／V4等相应规则编码；片段标签可在分析阶段汇总为“本帖出现过什么”，该出现性汇总不等于“本帖主要讲什么”，也不能自动拆出ARC内未分别记录的住宿与交通。
5. **当前不增加二级题材。** 前序讨论的具体题材细分层尚未采纳，不新增填写项、计数或切点。已有具体内容但主次确实难分、五类覆盖不明确时，按本批疑问流程记录原文位置与候选解释；MIXED和NONE均不承担“拿不准”的兜底功能。纯餐饮、纯交通等材料怎样体现既有五类，以及CITY／MIXED的具体灰色判例，继续通过人工试编码核对，不在本次强行归类。

以下为自拟说明，未裁决报告中的真实帖子：

| 整帖内容重心 | 判断方向 |
|---|---|
| 以山海景观及自然观览为主，附带交通、票价与餐饮信息 | NATURE；附带信息不自动使其成为混合 |
| 以历史建筑的来历与文化价值为主，地点位于城市中 | CULTURE；城市位置不单独决定CITY |
| 围绕城市整体游览组织海岸、老街与餐饮等内容 | CITY；资源多样不自动决定MIXED |
| 围绕度假休憩场所及整体度假体验展开 | RESORT；依据全文重心，不凭单个住宿词 |
| 不同取向各自充分展开，全文没有清晰主次 | MIXED；依据整帖并重关系，不凭标签数量 |
| 全文只有“假期开始，去海滨小城逛逛。”，没有具体游览内容 | NONE；一般旅行动态未呈现明确取向，不因提到城市就选CITY |
| 全文只有“去山顶看日出。” | NATURE；虽短但自然观览取向明确，不因字数少而选NONE |

<a id="destination-orientation-none-20261025"></a>

**NONE“未呈现明确取向”的使用边界：**

1. **判断原文有没有呈现，而不是编码员会不会判断。** 仅宣布出游、到访或一般打卡，完整文本中没有可识别的具体内容取向时可填NONE；不要求每篇都能归入前五类。不设置最低字数，也不凭“旅游”“打卡”等词直接赋值；短帖只要取向明确，仍按相应实质类别记录。
2. **与混合、疑问及材料故障分开。** 不同取向都有实质展开且无清晰主次时填MIXED；已有具体内容但类别边界、主次或框架覆盖不清时，填最可辩护值并标`?`，现行规则不能支持唯一值时用`UNRESOLVED`。正文加载失败、应有文字缺失或材料损坏时提交材料问题报告，不能填NONE。纯餐饮、纯交通等有具体主题但归类仍待讨论的材料，也不因五类难选就归NONE。
3. **NONE是本字段的正式类别值。** 它表示已完成判断且文本未呈现明确取向，不是NA、UNK、空白或临时未决；存储与导出保留字符串`NONE`，不转换为null。符合定义且无疑问时无需例行标`?`。汇总时保留这一类别，不以它为由自动剔除帖子；若后续只比较明确取向的帖子，应说明分母范围并单列NONE数量。
4. **只影响整帖类型这一项。** V1及V3—V6继续独立判断，不因为整帖选NONE就把其他标签全部填0或NA，也不改变固定片段。此次仅扩展现有字段的选项，不新增二级题材或额外填写项。

**记录与适用边界：** v3.24.0保留原五类定义，新增NONE，字段名、整帖单选责任及V3—V6设计不变。旧任务的原始答案与实际`codebook_version`保留，不把旧CITY、MIXED、NA或UNRESOLVED批量改成NONE，也不凭短文本自动回填；按新版复核的结果另存并注明依据。新版选项须由实际模板、保存／导出及校验承接，旧代码和工作簿不能只改版本号即视为兼容。当前只完成规范修改，未改平台、旧答案或验证分类效果。

#### V3 层级一致性规则

1. 任一正向子类为1时，其父类应为1；父类为1时，至少一个对应正向子类应为1。父类和子类仍分别人工判断，程序只报告冲突。
2. 同一父类内的具名子类可以共现；各`*_oth`子类只在同组具名子类均不适用时使用。
3. `is_non=1`时，`cs_int=0`且`is_que/is_dir/is_soc/is_oth`均为0；`cs_int=1`时`is_non=0`。
4. `cs_oth_gre/cs_oth_str/cs_oth_met`有明确功能证据时，可以与`cs_inf/cs_edu/cs_emo/cs_int`共现，`cs_oth`父类相应允许共现；SYM与RES按下方整段条件单独核对。不能因`cs_oth=1`就要求前四个父类均为0。上述关系仅用于复核，不自动补写、清零或覆盖人工记录。

<a id="cs-oth-cooccurrence-20261022"></a>

**CS-OTH具名功能共现与整段兜底（v3.23.4）：**

1. **GRE／STR／MET有证据即可并记。** 同一固定片段既有信息提供、知识阐释、情感渲染或互动，又有可辨认的寒暄、篇章导航或创作／平台元话语时，分别判断并保留符合定义的标签；GRE、STR、MET之间也可共现。独立功能证据不要求独立成句或另起片段，同一标签在本段只记一次，不统计内部次数。
2. **SYM的“纯”限定整个片段。** 整个固定片段仅由emoji、颜文字、话题标签或无实义符号组成时才按SYM判断；有实质正文并夹有emoji或话题词，不据此额外记SYM。
3. **RES仍作整段兜底。** 仅当整个固定片段未命中INF／EDU／EMO／INT，且GRE／STR／MET／SYM均不适用时，才记录`CS-OTH-RES/cs_oth_res`。已有其他策略或具名其他功能时，不因剩下几个字或几句话不好归类就再加RES，也不将RES当成拿不准的替代值。
4. **不改变其他兜底与人工责任。** 同组`cs_inf_oth/cs_edu_oth/cs_emo_oth/is_oth`继续按各自具名子项均不适用的条件使用；`is_non`排除规则不变。CS-OTH父类及所有子类仍分别人工填写，父子关系只供复核，不由程序OR补值，也不把合法的父类共现作为冲突或模型互斥惩罚。
5. **本条只明确共现资格。** STR、MET仍须满足各自功能定义；本次不统一裁决原报告中的标题、链接、平台提及或导流案例。固定切分、V4资源、V5语言功能与情感、V6主导属性均沿用原规则。

### V4 目的地资源（片段级，三级编码）

该片段调用了目的地的哪类资源来建构形象？参考《旅游资源分类、调查与评价》（GB/T 18972-2017），结合本研究的UGC内容分析目的设置类别，并非逐项照搬国标层级。[国标附录A表A.1](https://zwgk.mct.gov.cn/zfxxgkml/zykf/202206/P020220601691454918935.pdf)将“旅游购品”单列为G主类，下设农业产品、工业产品和手工工艺品；本研究将其作为人文资源下的具名亚类，采用下述文本证据边界。

**编码员同时标注Layer 1基本大类、Layer 2资源亚类，以及`RS-R-EVT=1`时直接涉及的Layer 3事件子类；层级逻辑只用于复核，不得自动补写或覆盖人工值。**

#### Layer 3：节事与文体事件子类（编码员标注）

仅当片段直接调用节事与文体事件资源时逐项判断；四个子类可以共现。`RS-R-EVT=0`时四项均记0，`RS-R-EVT=1`时至少一项为1；层级冲突只进入复核，不自动改写。

| 代码 | 子类 | 定义 | 语义锚点 |
|------|------|------|----------|
| EVT-SPT | 体育赛事 | 具有竞赛、赛会或职业/大众体育赛事属性的时限性事件 | 马拉松、足球赛、帆船赛、自行车赛 |
| EVT-PER | 演艺活动 | 以音乐、戏剧、舞蹈、曲艺或其他现场表演为核心的时限性事件 | 演唱会、音乐演出、舞台剧、现场演艺 |
| EVT-FES | 节庆会展 | 以节庆、庆典、主题节、展览或会议会展为核心的时限性事件 | 青岛啤酒节、灯会、文化节、博览会 |
| EVT-OTH | 其他节事与文体事件 | 已满足`RS-R-EVT`，但不属于上述三个具名子类的事件 | 颁奖活动、主题公共活动等边界事件 |

**边界规则**：

1. `RS-R-REC`与`RS-R-EVT`不按“是否收费”“是否由企业组织”区分。游船、潜水等即使由经营者组织，只要不依赖特定一次赛会、演出或节庆，仍归`RS-R-REC`；是否依赖具有明确时限的事件才是核心边界。
2. 同一运动的一般体验与赛事必须分开：“来青岛体验帆船”标`RS-R-REC`；“来看青岛国际帆船赛”标`RS-R-EVT + EVT-SPT`。片段分别调用两类资源时允许`REC`与`EVT`共现。
3. 音乐节可同时满足`EVT-FES`与`EVT-PER`；啤酒节本身标`EVT-FES`，只有片段还直接调用啤酒、美食或餐饮体验时才并标`RS-R-GAS`。
4. 节庆、赛事或演出不自动标`RS-R-FOL`；只有片段直接调用民俗传统、地方仪式、非遗或宗教文化时才并标`RS-R-FOL`。
5. `RS-R-HIS`与`RS-R-ARC`按文本中被调用的内容判断：强调年代、遗产身份或历史意义时标HIS；呈现建筑外观造型、空间设计或住宿、交通、服务等当代使用功能时标ARC。历史建筑仅呈现外观且相关语境未调用历史／遗产意义时可归ARC；同一固定片段两类内容均有直接证据时可并标。具体判据见下方[ARC／HIS边界](#arc-his-boundary-20261022)。
6. `RS-R-GDS`判断的是商品及其地方／纪念意义，不是所有购物行为。只在旅途中购买普通矿泉水、防晒霜或日用品，不据此标GDS；仅说“买了东西”且无法确认商品性质，也不凭购物动词补标。即使没有购买，只要明确介绍地方特产或旅游纪念品，也可标GDS。
7. `RS-R-GDS`与`RS-R-GAS`可共现：现场吃海鲜、喝地方啤酒等饮食描述本身标GAS，不自动标GDS；将地方食品、特色饮品作为特产或伴手礼介绍、推荐、购买时，可同时满足GDS与GAS，不因其“可食用”排除购品，也不因“带走”取消饮食标签。
8. 商场、店铺、市场作为设施或服务场所被描述时按`RS-R-ARC`判断；逛街、逛市集作为休闲体验被描述时按`RS-R-REC`判断。出现购物场所不自动标GDS，商品与场所／体验均有直接证据时才并标。工艺品本身可标GDS；只有还直接描述传统技艺、非遗或民俗时才并标`RS-R-FOL`。
9. 本轮不新增`RS-R-OTH`作为兜底。已明确的人文资源若仍无法由具名亚类表达，登记`FRAMEWORK_GAP`并按既有疑问流程复核，不把“其他”当成拿不准或缺少证据的替代值，也不因子类未覆盖就自动把人工`RS-R`改为0。

<a id="arc-his-boundary-20261022"></a>

**建筑观赏价值与ARC／HIS边界（v3.23.3）：**

1. **ARC覆盖观赏与使用。** 原文将建筑、构筑物或设施作为目的地资源，呈现其外观造型、空间设计或当代使用功能时，可标ARC。仅谈建筑外观也可以成立，不要求同时介绍住宿、交通或服务功能，也不要求已有参观经历或作出好坏评价。
2. **HIS依据文本中的历史／遗产意义。** 原文调用年代、遗产身份或历史意义时按HIS判断。建筑实际年代久远，不足以单独成立HIS；历史建筑仅呈现外观且相关语境未调用历史／遗产意义时按ARC判断。语义锚点只作理解提示，不凭景点名称或编码员外部知识补出历史价值；必要指代、省略及拿不准的情形沿用既有上下文与疑问流程。
3. **并标须分别有证据。** 同一固定片段既呈现历史／遗产意义，又呈现外观造型、空间设计或当代使用功能时，可以并标HIS与ARC；只有历史意义的叙述不因对象属于建筑就自动增加ARC。两项均按整个片段的出现性记录，同一标签只记一次。
4. **人工形成不是ARC的充分条件。** 人工栽植花海、人工水体等仍按文本呈现的植物、水域等资源内容判断；若还独立呈现建筑或构筑物，再分别判断ARC，不将所有人工景观统一归为建筑设施。
5. **资源与活动、评价独立判断。** “出片”“打卡”不能单独证明对象是建筑，不自动生成ARC或HIS；ARC也不自动推出REC、PHO、RES、ATM或其他V6属性。REC沿用活动证据边界，V6沿用原主导评价规则，不为此新增切点。

下表均为自拟教学例，只列ARC／HIS及直接相关的判断，不是人工金标或对原报告帖子的裁决：

| 表达 | ARC／HIS判断 | 依据 |
|---|---|---|
| “这座展馆的曲面外墙很有特点。” | ARC | 明确呈现建筑外观 |
| “这座教堂的尖顶和拱窗很好看。”（相关语境未调用历史／遗产意义） | ARC，不据此标HIS | 不凭建筑名称或外部常识补历史意义 |
| “这座旧车站见证了当地铁路发展的历史。” | HIS，不据此标ARC | 只调用历史意义 |
| “这座旧车站见证了当地铁路发展的历史，现在仍提供乘车和行李寄存服务。” | HIS与ARC | 历史与当代功能分别有直接证据 |
| “这里很出片。”（无其他资源线索） | 不据此标ARC或HIS | 摄影评价没有说明资源类型 |

**旧记录与承接范围：** 字段名称和值域不变，V4仍为17个二元字段（v3.24.3新增`rs_r_lif`后为18个）。按v3.23.3使用受影响记录前，须回原文复核ARC、HIS及必要的`RS-R`父类和资源汇总，范围包括原阳性及可能漏记的原阴性，不只检查模型分歧。保留首次答案与实际版本，不根据景点词表互换标签、不自动改签，也不将旧版信度直接视为修订判据的验证。平台说明、任务规则与训练标签兼容由相应流程另行核对；本次只修规范，未重编码、改平台、训练或开展新的效果验证。

<a id="rec-activity-boundary-20261022"></a>

**REC活动证据边界（v3.22.1）：**

> 单纯提供游览站点顺序、总时长或照片地点索引，不据此标记休闲游憩；明确呈现观赏、休闲、运动或互动活动时，再按活动内容判断。

“游览”“观光”字样本身不足以使REC成立；需要原文呈现可辨认的活动内容，但不要求特殊项目或长篇体验描写，赏叶、观海、登山、骑行、动物互动等均可。只列地点与时长的普通游览路线不据此标REC；明确以骑行、徒步等活动组织的线路可以标REC。描述、推荐或安排活动均按其内容判断，不要求作者已经亲身参与。

**活动提及与活动评价分开（v3.23.6）：** 叙述作者、朋友或其他游客在目的地进行明确的休闲游憩活动，即使只陈述事实、未表达好坏，也可记REC；参与者是否为作者不是门槛。赛事、节庆等仍按既有REC／EVT边界判断，不因有骑行、登山等动作就把特定赛事改为REC。V6的`asp_act`另按活动／游览体验的评价或建议判断，不能由REC=1推导；纯活动事实且整段无适用评价／建议时，`asp_applicable=0`，ACT等V6属性记NA。具体对照见[REC／ACT与相邻属性边界](#rec-act-boundary-20261023)。

REC与路线、参数及其他资源标签独立判断。REC=0不等于整段不编码，也不排除V3行程／参数或其他有证据的V4资源。同段多次呈现同一活动标签仍只记一次；不增加逐句次数、对象字段或新切点。拍照适宜性仍按V6已有边界，不自动推出REC。

下表仅示意REC，均为自拟对照，不裁决其他字段：

| 表达 | REC | 理由 |
|---|---|---|
| “游览顺序：地点甲→地点乙→地点丙，全程约三小时。” | 0 | 仅有站点顺序和总时长 |
| “图1某广场，图2某展馆外观。” | 0 | 照片地点索引不足以推出活动 |
| “沿岸观海，在林间赏叶。” | 1 | 明确呈现观赏活动 |
| “湖畔骑行线路沿水岸环行。” | 1 | 线路明确承载骑行活动，不要求已骑过 |
| “带孩子登山，随后参加动物互动体验。” | 1 | 明确呈现运动和互动活动 |

**地方生活风貌：可观察的日常生活内容（v3.24.3）：**

1. **记录内容，不记录氛围评价。** `RS-R-LIF`记录文本中可辨认的当地居民日常生活内容，包括日常生产、生计、买卖、邻里交往、社区生活等场景。对“烟火气、松弛、热闹、生活气息”等的评价，仍按V5语言功能与V6 ATM判断；同一片段可以既有具体生活内容又有氛围评价，但LIF不自动生成ATM，ATM也不要求LIF。本条不恢复已删除的RS-ATM：LIF是内容，ATM是评价指向。
2. **与FOL分开。** 传统礼俗、非遗、宗教文化、地方仪式及方言按FOL；普通人的日常劳作、买卖与邻里交往按LIF。两类都有直接证据时可以并标。
3. **与GDS、GAS分开。** 作为地方特色商品、旅游纪念品或伴手礼被介绍、推荐或购买的实物按GDS；地方美食、特色饮品与餐饮体验按GAS；LIF只记录围绕商品或饮食发生的生活场景本身（如摊贩经营、集市交往），不把商品或餐饮描述自动算作LIF。
4. **与ARC、HIS分开。** 建筑外观、空间设计或当代使用功能按ARC；历史／遗产意义按HIS；LIF不因场所是老街、市场或社区就自动成立，须有生活内容本身。
5. **与REC分开。** 具体游览、休闲、运动或互动活动按REC；观察或呈现当地人的生活不等同于作者的游憩活动。作者参与当地生活活动时，如同时呈现明确活动内容与生活场景，可分别判断。
6. **证据门槛。** 须有具体、可辨认的生活场景内容（谁在做什么、怎样的日常场景）；仅出现“有居民”“有商店”“当地人”等泛称，普通付款、一次性服务接触或纯背景路过，不足以成立。同段多次出现只记一次，不设次数、对象字段或新切点。
7. **不要求作者参与或评价。** 作者、朋友或其他游客的观察均可；事实叙述即可，不要求好坏评价。
8. **旧记录与承接。** `rs_r_lif`为实质新增字段；旧记录缺列不得补0，受影响片段须回原文复核并保留首次答案与实际版本；不按关键词批量回填，也不把旧RS-ATM或ATM记录转换过来。平台说明、模板、导出、模型与独立验证另行承接；本次只同步规范。

以下均为自拟教学例，只列直接相关的 V4 判断，不是人工金标或对报告原帖子的裁决：

| 表达 | LIF | 其他资源判断 | 依据 |
|---|---|---|---|
| “巷口的阿姨摆摊卖菜，边称重边和邻居聊天。” | 1 | GDS=0 | 普通蔬菜没有地方特色或纪念意义；卖菜经营本身是生活场景 |
| “早市上摊贩在收拾海鲜，居民挑挑拣拣。” | 1 | GAS=0 | 未涉及饮食体验；不因出现海鲜就标GAS |
| “老街上的居民在门口下棋、晒太阳。” | 1 | ARC按建筑证据另判 | 生活内容与建筑资源分开 |
| “这里的烟火气很足，生活很松弛。” | 0 | ATM=1（若为主导评价） | 只有氛围评价，没有具体生活场景 |

### V5 语言功能与情感（片段级，可共现）

V5回答“片段承担什么语言功能，以及片段主导评价或建议表达什么情感方向和强度”。Layer 1语言功能按整个片段判断、可共现；评价亚类、情感方向与强度只针对按“片段主导评价判定规则”选出的主导评价记录（v3.20.0）。信息、评价和建议不强制互斥；旧编号V3-L3目的地属性指向自v3.8.0起独立为V6，不再混入V5。

#### Layer 1：语言功能（3个实质项 + 1个排除项）

| 代码 | 类型 | 定义 | 操作化标准 |
|------|------|------|-----------|
| AT-INF | 信息性陈述 | 包含至少一个可核验的事实命题 | 可判断真假的时间、地点、属性、数据或知识陈述 |

**其他／未命中现有评价亚类（AT-EVL-OTH，v3.24.2）：** 仅当主导评价已经成立（`at_has_eval=1`），但按原文没有充分证据归入ADM／SAT／EXC／DIS／FRU／NOS时使用，字段值记`OTH`。方向、双向强度、主导评价选择及V6属性仍按同一主导评价独立判断，不因记OTH而清空、改记`NEU`或降低强度；OTH不是“中性”（`NEU`是情感方向取值）、不是“没有评价”（`at_has_eval=0`）、不是编码员在两个已有亚类之间拿不准（仍标`?`），也不是材料缺失（另报问题）。若同一类评价在人工校准中反复无法归类，再讨论是否新增具名亚类，不以OTH代替理论扩充。旧答案保留，不自动改签或回填。

#### ADM赞赏／惊叹与SAT满意／舒适：评价性质与表达强度分别判断（v3.23.5）

以下判据用于已经成立的目的地评价，并针对既有主导规则选出的评价判断亚类；不把建议或主体状态自动当成评价，不改变每段单选责任。

1. **ADM看对象的美感、特色、品质或令人赞叹之处。** 明确称赞景观、建筑、活动等对象本身的吸引力或品质时，可归ADM。普通的“景色很好看”也属于赞赏，不要求震撼、惊叹或强烈表达。
2. **SAT看体验是否满足需要，以及满意、舒适的感受。** 评价目的地、设施或体验令人满意、舒心，或符合使用与游览需要时，可归SAT。满意也可以表达得很强烈，不因“满意极了”就改归ADM。
3. **亚类与强度分别依据原文判断。** ADM和SAT都允许一般正面强度1或强正面强度2；强度仍按下方既有0／1／2规则，取本段针对主导属性的同方向最高表达。ADM不自动等于2，SAT不自动等于1，也不从强度反推亚类。重复普通赞美不升档。两类的高低唤醒仅保留为典型特征，不作为硬门槛，不另填唤醒度，也不将其等同于表达强度。
4. **填写顺序不代替测量分工。** 仍先按既有规则确定主导评价及属性，再分别填写适用的亚类、方向和双向强度。界面先填哪一列不构成另一项的判断依据，不要求为本条重排平台流程。资源／活动对象、第一人称或是否已经实际参与，也不单独决定ADM／SAT；仅有主体状态时仍先按既有V3／V5规则核对是否构成对象评价。
5. **泛化认可保留语境与疑问。** “不错”“值得来”等须结合评价指向及相关上下文，先区分评价和建议，再判断亚类；不设一律归SAT或ADM的默认值。仍无法明确区分时，按既有最可辩护值及疑问流程记录，不以缺少强烈词语推定SAT。
6. **其余定义与责任保留。** EXC、DIS、FRU、NOS的定义不变；多项评价仍按原主导顺序处理，不为两类分别增加字段、片段或段内次数，也不从亚类反推V6属性。本条是本研究的操作定义调整，不把具体分法或效果归作情感环状模型已经验证的结论。

以下教学例均假定所列评价已选为主导，且片段中没有其他影响强度的表达；不是报告原样本的裁决或人工金标：

| 主导评价（自拟） | `at_eval_subtype` | `sentiment_pos_val` | 依据 |
|---|---|---|---|

#### V3／V5交界判定规则（v3.20.0补充）

V3与V5从不同角度描述同一片段，允许共现；以下规则只规定易混标签的判定条件，不改变字段与值域。

**第一组：`CS-INF`信息提供与`AT-INF`信息性陈述（2026-09-29确定）**

1. **先判`AT-INF`**：片段含至少一个可核验的事实命题即记1，包括作者本人经过的叙述。
2. **再判`CS-INF`，与叙述人称无关**：第一人称讲述自己的经过，只要满足下列条件之一，同时记`CS-INF`与`AT-INF`：
   - **`CS-INF-ITN`**：片段呈现站点、日程或路线的顺序结构（箭头、序号、Day1／Day2、“路线：”等）；
   - **`CS-INF-PAR`**：片段含读者可直接复用的决策参数，如开放时间、地址、票价、线路、交通方式与换乘、预约或限制条件。
3. **可复用检验**：参数“换一位读者、换一天去是否仍然成立”。“福山支路16号”“周一闭馆”成立，记PAR；“10:30出门”“12点停好车”只是作者当天安排，不记PAR。
4. **纯经过叙述**只记`AT-INF`：没有顺序结构、也没有可复用参数，如“那天下雨了”“娃很闹”“一路往上走”。
5. 知识类事实（历史、成因、意义）记`AT-INF`与`CS-EDU`，不因可核验而记`CS-INF`。

| 片段（自拟） | `AT-INF` | `CS-INF`子类 | 理由 |
|------|------|------|------|
| “行程为栈桥→吃饭→天主教堂→总督楼旧址” | 1 | ITN | 第一人称经过，但有站点顺序结构 |
| “小鱼山导航到福山支路16号，一路往上走” | 1 | PAR | 含可复用地址；“一路往上走”是否构成PRO归第三组 |
| “10:30出门，自驾，12点停好车。” | 1 | 无 | 只有当天时间线，不可复用 |
| “那天下雨了，娃很闹。” | 1 | 无 | 纯经过叙述 |
| “天主教堂周一闭馆，门票15元。” | 1 | PAR | 可复用参数 |
| “栈桥始建于1892年。” | 1 | 无（记`CS-EDU-BKG`） | 知识类事实 |

**第二组：`CS-EMO`情感渲染与`AT-EVL`评价性表达（2026-09-29确定）**

1. **`CS-EMO`须有具体描写**：只有评价词或感叹（“太美了”“绝了”“很漂亮”“很值”）只记`AT-EVL`，不记`CS-EMO`；写出下列任一内容时同时记`CS-EMO`：
   - 感官细节（颜色、声音、气味、触感、味道）→ `CS-EMO-SEN`；
   - 氛围描写 → `CS-EMO-ATM`；
   - 作者具体的身体或情绪反应（“站那半天说不出话”“鸡皮疙瘩都起来了”）→ `CS-EMO-AFF`。
   判断口诀：去掉评价词后，剩下的内容能否让读者感受到当时的体验。
2. **主体感受不等于评价**：作者只陈述自身状态（“很放松”“好开心”“累死了”）只记`CS-EMO-AFF`，`AT-EVL=0`；把感受归于目的地或体验对象（“这里很让人放松”“这段路走得人很累”）时构成评价，同时记`AT-EVL`，并按V6判断属性。
3. 强烈评价词（“震撼”“绝了”）本身只影响`AT-EVL`亚类与强度，不单独触发`CS-EMO-AFF`。

| 片段（自拟） | `AT-EVL` | `CS-EMO`子类 | 理由 |
|------|------|------|------|
| “太美了！” | 1 | 无 | 只有评价词 |
| “震撼到站那半天说不出话。” | 1 | AFF | 有具体身体反应 |
| “红瓦绿树，尽收眼底，很漂亮。” | 1 | SEN | 有视觉画面 |
| “海风咸咸的，走在沙滩上很放松。” | 0 | SEN、AFF | 感官细节＋主体感受，未评价对象 |
| “这片沙滩很让人放松。” | 1 | 无 | 感受归于对象，构成评价 |
| “整条街很安静，只有海浪声。” | 0 | ATM、SEN | 氛围与声音描写，无好坏判断 |

**第三组：`CS-INF-PRO`操作指导与`AT-SUG`建议（2026-09-29确定）**

1. **`CS-INF-PRO`须有可照做的内容**：步骤、技巧、避坑方法、比较或选择依据，且具体到读者能执行；沿用第一组可复用检验。作者经过的粗略描述（“一路往上走，没几分钟到顶”）不记PRO。
2. **`AT-SUG`须有明确劝导措辞**，包括：
   - 推荐与建议词：建议、推荐、值得去、可以试试；
   - 祈使劝导：一定要、记得、最好、别、不要、千万别；
   - 平台惯用劝导语：必去、避雷、冲、闭眼入、劝退、慎入。
   没有此类措辞、只以事实或经验隐含指导的（“早上去人少”）不记`AT-SUG`；满足第1条时记`CS-INF-PRO`，并按第一组记`AT-INF`。上列以外、疑似劝导的措辞，按最可辩护值填写并标`?`，校准时决定是否补入。
3. **只有步骤、没有劝导措辞**：只记`CS-INF-PRO`，不记`AT-SUG`。
4. **只劝不给方法**：只记`AT-SUG`，不记`CS-INF-PRO`。
5. 两者都满足时同时记；`AT-SUG`仍不等于`IS-DIR`，后者限于号召评论、收藏、转发等互动。

| 片段（自拟） | `CS-INF-PRO` | `AT-SUG` | 其他 | 理由 |
|------|------|------|------|------|
| “必去！” | 0 | 1 | — | 只劝不给方法 |
| “坐3号线到青岛站，出站右转200米就到。” | 1 | 0 | `AT-INF`、PAR | 有步骤，无劝导措辞 |
| “一路往上走，没几分钟就到顶了。” | 0 | 0 | `AT-INF` | 经过描述，不可照做 |
| “带老人的话选A路线，台阶比B路线少。” | 1 | 1 | `AT-INF` | 有比较依据；“选A路线”为祈使劝导 |
| “早上去人少。” | 1 | 0 | `AT-INF` | 有选时间依据，但无劝导措辞 |
| “人很多，建议早上去。” | 1 | 1 | `AT-INF` | 有“建议”措辞与选择依据 |

**测量边界**：`AT-SUG`按明确措辞判定，隐含建议不计入，建议功能的比例会被低估；分析须表述为“使用明确劝导措辞的建议”。

#### Layer 2：情感方向（片段含AT-EVL或AT-SUG时，针对主导评价标注）

| 代码 | 含义 | 判定标准 |
|------|------|----------|
| POS | 正面情感 | 评价/建议中的情感倾向明确为正面 |
| NEG | 负面情感 | 评价/建议中的情感倾向明确为负面 |
| MIX | 混合/矛盾情感 | 本片段内对主导属性同时存在正面与负面表达（v3.20.0起；不同属性各有正负不记MIX，只按主导属性判断） |
| NEU | 中性 | 主导评价或建议表达真实中性、无褒贬方向的立场 |

新增`sentiment_judgeable`（情感方向可判定，0/1）：当片段不含评价或建议，或虽含评价/建议但无法从文本判定情感方向时，记为0，`sentiment_dir`记为`NA`；当其为1时，`sentiment_dir`必须人工编码为POS、NEG、MIX或NEU之一。NEU不得再承担“不适用”或“无法判定”的含义。

以两个独立的人工强度字段记录情感，不再使用单一`sentiment_val`：

| 字段 | 取值 | 人工判定规则 |
|------|------|-------------|
| `sentiment_pos_val` | 0 / 1 / 2 / NA | 无正面表达 / 一般正面 / 强正面 / 情感不可判定 |
| `sentiment_neg_val` | 0 / 1 / 2 / NA | 无负面表达 / 一般负面 / 强负面 / 情感不可判定 |

两字段记录**本片段内针对主导属性**的正面、负面最高强度（备选A，v3.20.0）：同方向出现一般与强烈表达时取2；重复一般表达不升级为2；非主导属性的表达不计入。当`sentiment_judgeable=0`时，两字段均记NA；POS对应`pos=1或2, neg=0`，NEG对应`pos=0, neg=1或2`，NEU对应`pos=0, neg=0`，MIX对应`pos=1或2, neg=1或2`。强度2仅用于明确的强烈情绪、显著强化词或极端评价；其余明确方向表达记1。后续若需净方向，仅在分析阶段计算`pos - neg`，不得覆盖这两个原始人工字段。

### V6 目的地属性指向（片段级，4个实质父类 + 14个子类 + 1个其他项 + 1个适用性状态）

V6回答“片段主导评价或建议指向目的地的什么属性”。自v3.20.0起每段只记录一个主导属性；片段中其余被评价属性不记录，也不设“另有其他属性”标记。V6标签只记录属性对象，不携带正面或负面方向；方向与双向强度由同一片段针对该主导属性的V5字段记录。V6不替代V4资源分类：V4回答“调用了什么旅游资源”，V6回答“对目的地的什么属性作出评价、建议或回避”。

#### V6层级与跨维度规则

1. V6父类、子类、`asp_applicable`和`asp_oth`均由编码员判断并由模型逐字段输出；程序只报告冲突，不自动生成或覆盖记录。
2. 任一V6子类为1时，对应父类应为1；父类为1时，至少一个对应子类应为1。父子关系只用于一致性审计与模型层级损失。
3. 每段只有一个主导属性：恰有一个具名子类及其父类为1，或仅`asp_oth=1`；其余父类、子类记0。一个评价同时涉及两个子类且无法按判定顺序分出主导时，取先出现者并可标`?`说明。
4. `asp_oth=1`仅表示存在框架未覆盖的目的地属性，不表示无评价、无建议或无法判断。
5. 纯事实提及“门票80元”“有地铁站”但没有评价或建议时，`asp_applicable=0`；只评价创作者本人、平台或无关商品时同样记0。
6. V6标签保持方向中立。“卫生好”和“卫生差”都编码`asp_hyg=1`，其正负方向分别由V5的`sentiment_dir`与双向强度记录，不建立`asp_hyg_pos/asp_hyg_neg`等重复标签。

#### RES资源品质与ATM地方氛围：片段内的评价指向（v3.23.2）

以下判据用于判断**同一条已选主导评价**应归RES还是ATM，仍须先满足V6适用条件；不代替主导评价选择，也不把纯描写自动变成评价。

1. **孤立的资源审美赞美按RES。** 评价对象明确是建筑、景观等资源，文字只作整体外观、风格或审美品质的泛化称赞，例如“这座建筑很有氛围感”，而本片段内没有与该评价关联的明确场所氛围含义时，按资源本身的品质／吸引力判断。该判据限于明确的资源审美评价，不把所有模糊的“环境好”“体验好”都归入RES。
2. **同段有明确相关解释时按ATM。** 同一固定片段内，通过同一句或相邻句明确说明了该评价所指的场所氛围、生活节奏或社会情境，且说明与被评价对象／场所有语义联系时，按ATM判断。浪漫、热闹、松弛等可以提供线索，但不能因片段中碰巧出现某个词就改标；须确实是在说明这条评价的氛围含义。
3. **简短不妨碍明确指向ATM。** “这里的氛围很好”等直接评价场所氛围的表达，即使未展开具体氛围类型，仍可按ATM；不要求长篇描述或最低字数。本条不把V3情感渲染的具体描写要求移入V6。
4. **按固定片段区分，不能按句号或换行机械拆开。** 评价与其相关解释在同一固定片段内，即使分成两句或换行，仍结合判断。若解释落在别的固定片段，不把该段独立的氛围描述自动补成本段评价证据；相邻上下文仍可用于确认对象、指代及必要省略关系，关系不明确时标疑问，不自行改段。该区别不授权为了得到某个标签重新切分。
5. **同段出现多个独立评价仍按主导规则。** 建筑品质评价与场所氛围评价各自成立时，继续按“转折后→强度高→先出现”及既有自行判断规则选主导；不设“只要同段有氛围线索，ATM就覆盖RES”的新优先级。PHO、WEA及其他属性也按各自定义参与既有主导判断。
6. **无法明确归类仍保留疑问。** 本条只处理RES／ATM；ACT与两者的交界见下方v3.23.6补充，FAC／ATM见下方v3.23.7补充，CRO／ACT见下方v3.23.9补充。不把OTH当作RES／ATM拿不准的替代项，也不依据关键词批量迁移旧答案。

以下为自拟教学例，均假定所列评价已选为主导、且没有其他影响判断的上下文；不是报告原样本的裁决：

| 固定片段与语义关系 | 判断方向 | 理由 |
|---|---|---|
| 一段仅有“这座建筑很有氛围感。”，作为建筑整体审美称赞 | RES | 本段没有明确关联的场所氛围指向 |
| 同段为“这座建筑很有氛围感。小院安静，整体气氛悠闲而松弛。”，后句在解释前句 | ATM | 两句同属一个固定片段，且解释明确落在场所氛围 |
| 一段为“这个街区的氛围很好。” | ATM | 简短但已直接评价场所氛围，无需补成长篇描写 |
| 片段甲仅评价建筑整体审美，片段乙另评价周边街区的松弛氛围 | 甲按RES、乙按ATM各自判断 | 别段独立评价不自动搬入甲段，不自行合并 |
| 同段为“建筑造型精致，但周边街区的氛围很压抑。” | 按原主导规则取ATM | 两项独立评价，仍由转折后优先决定，不是ATM一般优先 |

**旧记录与承接范围：** 本次未新增字段，RES／ATM含义及所需片段内依据的补充仍可能改变旧值。转用新说明时须按受影响字段回看原固定片段、必要上下文、主导取舍及证据，保留原始答案和实际版本，复核必要的父类与V5绑定；不自动互换RES／ATM或改签版本。训练和比较按既有逐字段兼容规则处理，旧信度不自动覆盖改变的判断。实际任务说明、平台承接、受影响记录复核与独立验证另行完成；本次未执行这些环节。

#### REC活动提及与ACT体验评价／建议，以及ACT与RES／ATM的边界（v3.23.6）

1. **V4记录活动内容，V6记录评价或建议指向。** 原文明确呈现目的地相关的休闲游憩活动时，可按REC判断；事实叙述、活动介绍、安排或推荐均可提供活动证据，不要求作者已经参与，也不要求表达好坏。具体活动由作者、朋友或其他游客进行均可。REC／EVT的既有区分继续适用，不能把所有活动都归REC。
2. **ACT必须满足V6适用性与主导条件。** 只有评价或建议指向活动／游览体验，且按既有规则选为主导属性时，`asp_act=1`、`asp_exp=1`。纯活动事实且整个固定片段没有适用的评价或建议时，`asp_applicable=0`，ACT等V6属性记NA，不记0或中性来代替不适用。若片段另有资源品质等适用评价成为主导，REC仍可为1，V6按主导属性填写，ACT为0。
3. **ACT包含整体游览体验，但不承接所有笼统认可。** 对具体活动或整体游览过程的参与感、趣味、丰富程度、体验价值或适宜性作评价／建议，均可纳入；不要求特殊项目、长篇描写或出现“活动／体验”字样。整体游览适宜性须有可辨认的游览体验指向，可由同一固定片段的相关上下文明确；不能把所有“适合一个人来”“舒服”“值得来”等泛化表达固定映射到ACT，也不能凭活动动词推导评价。

#### 设施体验FAC与地方氛围ATM：评价指向与含混表达（v3.23.7）

以下判据用于判断**同一条已选主导评价**应归FAC还是ATM，仍须先满足V6适用条件；不代替主导评价选择，也不把场所名称或“环境”一词自动当作某一属性。

1. **FAC看设施的配置、功能、可用性或使用舒适性。** 座椅、隔音、房间空间、设备、卫生间、休息区、标识等设施本身的属性，按FAC判断；“座椅很舒服”“隔音差”“房间宽敞”均为设施使用体验，不因发生在住宿或餐饮场所就自动归ATM。
2. **ATM看场所气氛、生活节奏或社会环境。** 安静、浪漫、热闹、松弛、烟火气、音乐氛围、居民友好等，明确指向场所呈现的气氛或社会情境时按ATM；“餐厅氛围温馨”“街区烟火气很浓”“适合聊天、约会”可归ATM。
3. **“环境”是待解释的名词，不直接映射。** “环境好／环境超棒”可能指设施，也可能指氛围。只有设施线索时按FAC；只有氛围或社交线索时按ATM；两类线索都有时按第4条选主导；两类线索都没有，或按第4条仍无法明确分出主次时，选最可辩护的一个并标`?`，原因记`BOUNDARY`，替代值填另一属性，摘录证据；不设“环境一律归ATM”或“一律归FAC”的默认。

#### 客流拥挤CRO与活动体验ACT：事实、评价与原因关系（v3.23.9）

以下判据先检查是否满足V6的评价／建议条件，再辨认评价所指属性；多项评价按既有主导规则选择。v3.23.9收紧v3.23.8的事实与原因处理，不改变单主导结构。

1. **CRO看客流、排队、等待或拥挤的评价／建议。** 直接评价客流密度、拥挤程度、等待长短或通行体验，或明确围绕这些属性提出建议时，按CRO判断。“人太多”“太挤”“等得太久”“排队真快”有评价依据；“排队两小时”“人少”单独出现时不自动成立，须结合原文相关语境判断有无评价或建议，不能由编码员自行认定某个时长或人数好坏。
2. **ACT看活动或整体游览过程的评价／建议。** 评价具体活动、游览过程、参与感、趣味、体验价值或适宜性时按ACT；“玩得很开心”“没玩尽兴”“体验一般”“项目值得玩”等须有明确的活动／游览指向。纯活动事实不触发ACT；整段没有适用评价或建议时V6不适用。
3. **纯等待时长按事实记录。** 单独说“排队排了一小时”，且无其他评价或建议时，`at_has_info=1`、`at_has_eval=0`、`at_has_sug=0`，`asp_applicable=0`，CRO及其他V6属性为NA；`sentiment_judgeable=0`，情感方向和正负强度为NA，不填中性代替不适用。若另有明确评价或建议，再按整段内容判断，不因出现时长就判整段不适用。当天经历也不自动满足`CS-INF-PAR`的可复用条件。评价可以通过明确措辞或相关上下文中的等价表达成立，不要求固定关键词；本条不新增“排队事实”标签或次数。
4. **原因与评价可以同时成立。** 原因、条件或背景中的纯事实不单独触发V6属性；其中本身含明确评价时，仍纳入主导候选。例如“人太多，根本没玩尽兴”中，“人太多”既解释原因，也含客流评价；“没玩尽兴”评价游览体验。不能仅因前句承担原因作用就将它排除，也不能因出现“人、排队”便认定有评价。
5. **多项评价继续按既有单主导顺序处理。** 按“转折后→强度高→先出现”选一个，不新增“原因优先”或“结果优先”。上述例句若后半句评价明确更强，可选ACT；若强度明确相同，按先出现规则；无法明确判断时沿用`?`、`BOUNDARY`、另一候选属性及原文证据的既有处理。主导候选的辨认不等于同时记录多个V6属性，不凭“根本”等单个词机械定强度。
6. **“体验很差”等泛化结果词要看对象。** 指整体游览过程时按ACT；指排队、等待或拥挤本身时按CRO；仅凭“体验”一词不能自动归ACT。对象仍不明确时按疑问处理，不补写未表达的原因。
7. **字段、主导顺序、强度与切分保留。** V6仍14个具名子类、20字段，每段一个主导属性；V5仍按同一主导评价记录亚类、方向与强度，不按属性分别另填情感；不新增对象字段、不数次数、不拆并片段。

#### 拍照适宜性：纳入、排除与情感绑定（v3.22.0）

1. **编码对象是文字对场所／机位拍摄条件的呈现。** 明确评价是否出片、是否容易取得理想画面，或评价光线、背景、构图空间、遮挡等对拍照的影响时纳入。不要求作者已经拍摄，不从是否第一人称推断真实性；这也不是研究者根据图片作出的客观摄影评分。明确以拍照适宜性为依据提出机位选择、推荐或回避时，也按V6既有建议适用规则判断。
2. **须明确指向摄影用途。** 仅说景色、建筑、街道好看而没有拍摄含义，仍按原有资源品质等属性判断，不补PHO；只有“打卡”字样，也不自动等于拍照评价。仅陈述机位位置、拍摄事实或拍照限制、没有评价或指向该属性的建议时，不据此使V6适用。

| “摄影师把这张照片修得很好看。” | 不属于目的地拍照适宜性 | 不把技术或后期评价当作场所属性 |

**旧记录与承接范围：** `asp_pho`是新增字段，旧记录未标不等于0。转用v3.22.0时须回到原文补编，并复核主导属性、EXP父类及必要的V5方向、强度和亚类；此前归RES／ACT／ATM／OTH等记录不能自动改成PHO，也不能由关键词、V4或图像代填。保留旧答案和版本，按字段核对兼容后再用于训练／比较。新增字段及改变判断的边界仍待共同校准和独立验证；平台字段、导出、任务生成器和旧宽表须另行核对。本次未执行这些迁移或验证。

#### 天气与气候适宜性：纳入、排除与旧记录兼容（v3.23.0）

1. **须有游览舒适或适宜性的明确指向。** 气温、湿度、风雨、日照、季节等被用来评价目的地游览是否舒适、是否适合出行或开展游览时纳入；明确围绕该适宜性推荐或回避季节、时段、行程时也纳入。不要求作者已到访或已有亲身体验，记录的是文字呈现，不是研究者判定的客观天气质量。
2. **纯事实与一般提醒不自动纳入。** 只报气温、预报降雨、记述当日天气或交代季节，没有评价或相关建议时，`asp_applicable=0`、其余V6字段为NA。“带伞”“注意防晒”等一般提醒本身不证明在评价游览适宜性；是否构成AT-SUG、是否指向目的地属性仍按既有规则判断，不凭天气词补WEA或正负方向。
3. **按实际评价指向区分景观、摄影和风险。** 评价日出、云海、雪景等天象景观本身的美观或吸引力时按RES；评价天气、光线等对目的地场所／机位取景、出片的影响时按PHO；明确评价或警示天气导致的人身、财产、活动风险时按SAF，警示／防护／应急保障则按SEC。仅说冷、热、雨大或不宜游览，不推断存在安全风险；提到风雨也不使SAF自动成立。
4. **季节与舒适词不构成固定映射。** 季节只是时间背景、活动好玩、地方氛围松弛、设施空调舒适、交通受阻或旺季拥挤时，分别按实际证据判断，不能只因“夏天”“舒服”“风”等词改标WEA。泛称城市适合度假而没有天气／气候适宜性依据，不据此纳入WEA。
5. **沿用主导评价、出现性及V5绑定。** 只有WEA按既有顺序成为片段主导属性时，`asp_wea=1`且`asp_exp=1`，其余V6属性为0；适用而未选中WEA时填0，不适用时填NA。同段重复天气评价或涉及多个季节、地点仍只记录一次，不增设对象计数，不为WEA拆并片段。V5亚类、方向、正负最高强度围绕同一主导评价填写；同一天气适宜性属性正负并存仍记MIX。WEA与RES、PHO、SAF等同时出现时，仍须选一个主导属性；不能为覆盖天气而并标多个V6子类。
6. **V4与V6独立判断。** `RS-N-CLI/rs_n_cli`记录被调用的天象气候资源，WEA记录被评价的天气与气候适宜性；二者不互为前提或推导关系。不能由CLI或天气词自动补WEA，也不能由WEA反填CLI、REC、语言功能或策略。须保留所选主导评价的最短充分证据，含会改变判断的否定、程度及条件；拿不准时沿用`?`与未决处理规则。

#### 片段主导评价判定规则（v3.20.0）

固定语义片段内仍可能出现多个被评价属性或正负方向。编码员不拆分片段，只选出一个**主导评价**，据此填写V6属性、V5亚类、情感方向与强度；V3、V4及V5语言功能仍按整个片段判断。

第1—3条只在能明确判定时适用：

1. **转折后优先**：片段中有“但、不过、可是、然而、只是”等转折，且转折后是对目的地属性的评价时，取转折后的评价。
2. **强度高优先**：无转折且各评价强度差别明确时，取表达最强的评价（强度2优先于1）。
3. **先出现优先**：各评价强度明确相同时，取片段中先出现的评价。

**第1—3条无法明确判定时由编码员自行判断主导评价**，典型情形包括：转折后不是对目的地属性的评价（如转向同行人状态）；评价与建议并存、无法比较强度；强度差别模糊；以及其他未列情形。自行判断时必须：在V6相关字段标`?`、原因记`BOUNDARY`，替代值填另一候选属性，写一句选择理由，并摘录所选主导评价的原文证据。共同校准时负责人按情形归类，反复出现者写成新增判定条款，其余保留为判例；分析时“规则判定”与“自行判断”片段分别报告一致性。

4. **主导属性内正负并存**：选定主导属性后，本段对该属性的正面、负面表达分别取最高强度记录，`sentiment_dir`记MIX；其他属性的表达不计入。
5. **亚类同规则**：`at_eval_subtype`按同一顺序选出主导评价的亚类，单选。
6. **不拆并片段**：片段边界按已确认的embedding语义切分配置统一生成并固定；编码员认为边界严重影响判断时登记`UNITIZATION_PROBLEM`，不改边界。
7. **同属性不同对象**：同一属性评价不同对象时不设对象字段。分属不同片段时各自记录；在同一片段时按第4条记录。需要区分对象时，以同一片段的V4资源作近似。

**判定示例**：

| 固定片段 | 主导评价 | V6 | V5方向／强度 | 理由 |
|------|----------|--------|--------|------|
| “景色很美，但厕所很脏。” | 厕所很脏 | `asp_wel+asp_hyg` | NEG；pos=0，neg=1 | 规则1：转折后优先；“景色很美”不记录 |
| “服务一般，隔音简直差到离谱。” | 隔音差到离谱 | `asp_sup+asp_fac` | NEG；pos=0，neg=2 | 规则2：强度高优先 |
| “位置方便，早餐也不错。” | 位置方便 | `asp_ops+asp_acc` | POS；pos=1，neg=0 | 规则3：强度相同取先出现 |
| “门票虽贵，但总体很值得。” | 价格 | `asp_sup+asp_pri` | MIX；pos=1，neg=1 | 规则1选出价格；转折前“门票虽贵”同属价格，按规则4两列分别记录 |
| “人太多，排队也很久。” | 客流拥挤 | `asp_ops+asp_cro` | NEG；pos=0，neg=1 | 同一属性同方向，只记一次 |
| “栈桥始建于1892年。” | 无 | `asp_applicable=0`，其余V6字段NA | NA | 只有事实命题，没有评价或建议 |
| “风景很漂亮，但是娃有点闹腾。” | 编码员自行判断（通常为风景很漂亮） | `asp_exp+asp_res`，标`?` | POS；pos=1，neg=0 | 转折后不是目的地属性评价，第1条不适用；须标`?`、写理由并摘证据 |

**测量边界**：V6统计的是“作为片段主导评价出现的属性”，不是片段或帖子中被提及的全部属性；次要属性覆盖被系统性低估，并偏向转折后和更强烈的评价。主导判断本身是分歧来源，共同校准与盲试标须单独检查。

#### 帖子层汇总（程序派生，编码员不填写）

由片段记录按帖子汇总，字段名在实现时另定：

- 本帖出现过的主导属性（V6子类、父类及`asp_oth`）；
- 每个主导属性在本帖的正面最高强度与负面最高强度（取各片段最大值）；同一属性不同片段分别为正、负时，表现为正负共存，不改写片段记录；
- 本帖出现过的主导评价亚类，多选集合。

汇总只读取人工记录，不回写或覆盖片段字段；`NA`不参与最大值计算，全部片段均为`NA`时帖子层记为不可判。汇总只对已关闭全部`UNRESOLVED`的正式记录执行。

## 四、视觉轨：各维度操作定义

视觉轨对帖子的每一张配图进行编码。编码单位：单张图片。

**编码原则**：
1. 每张图片独立编码，不因上下文图片而改变对该图本身的判断
2. 当画面包含多个元素时，选择视觉上最突出、面积占比最大的元素作为编码依据
3. 仅当品牌/标识在画面中清晰可辨时才编码消费符号

### V7 视觉主体（图片级，单标签）

| 代码 | 类别 | 定义 | 典型内容 |
|------|------|------|----------|
| VS-NAT | 自然景观 | 以自然地貌、水体、天空、植被为主要视觉元素 | 海景、山峦、日出日落、森林、花海 |
| VS-ARC | 建筑遗产 | 以人造建筑、古迹、城市地标为主要视觉元素 | 古桥、城墙、寺庙、现代地标建筑 |
| VS-PEO | 人物活动 | 以人物及其活动为主要视觉元素 | 游客打卡照、当地人生活场景 |
| VS-FOD | 美食/物产 | 以食物、饮品、地方特产为主要视觉元素 | 海鲜大餐、啤酒、烧烤 |
| VS-FAC | 服务设施 | 以旅游服务设施、交通工具为主要元素 | 酒店、民宿、游船、缆车 |
| VS-OTH | 其他／无明确视觉主体 | 画面主体不属于上述五类（如路线地图、文字截图、聊天记录、票据），或画面没有可辨认的主导主体（严重模糊、过曝、遮挡、无主分区拼图） | 行程地图、聊天记录截图、无主次拼图 |

<a id="visual-subject-oth-20261025"></a>

**其他与“无明确视觉主体”（VS-OTH，v3.24.1）：** `VS-OTH`是正式类别值，不是缺失、NA或材料故障。仅在两类情形使用：①画面有可辨认主体，但不属于自然景观、建筑遗产、人物活动、美食物产、服务设施五类（如路线地图、文字截图、聊天记录、票据）；②画面没有可辨认的主导主体（严重模糊、过曝、遮挡，或拼图各分区无主次）。多主体但可依视觉突出度与面积选出主导时，仍按五类判断；编码员拿不准时按既有疑问机制标`?`并说明，材料损坏或无法加载另报材料问题。`VS-OTH`不自动决定V8场景语境、景别或视角，也不把整张图判为不适用或剔除；V7仍单标签，其他字段独立判断。旧答案保留，不自动改签或回填。

### V8 视觉呈现方式（图片级，三个独立子字段）

将旧编号V12的5类互斥单选拆分为三个相互独立的单选子字段，消除"标志性景点的航拍全景"同时满足多个类别的问题。

**场景语境 scene_context**

| 代码 | 类别 | 定义 |
|------|------|------|
| SC-ICO | 标志性场景 | 画面中有仅凭图片即可辨认的具体地点特征（建筑、雕塑、门楼、招牌、标志性海岸线等）；清单只帮助辨认，不单独决定 |
| SC-STR | 日常场景 | 画面主要呈现街道、市场、社区或市井生活，不论该地现在是否出名或是否在清单中 |
| SC-OTH | 其他/不适用 | 美食特写、室内设施或无法归入前两类的画面 |

<a id="scene-context-content-20261029"></a>

#### 场景语境：按画面内容判断，不以地点身份替代（v3.24.4）

1. **V8看画面，不看地点身份。** 场景语境按当前图片呈现的内容判断；地点是否在2026年共同清单中、是否在网络上走红、帖子标题或作者是否提到该地，都不单独决定SC-ICO。清单只帮助辨认画面中的地点特征，不把“清单有名称”自动变成ICO。
2. **SC-ICO要求仅凭图片可辨认的具体地点特征。** 画面中有足以确认具体地点的特征，例如建筑、雕塑、门楼、招牌、标志性海岸线；该特征不能是可忽略的偶然背景。若清单有名称、但画面认不出具体地点特征，不得仅凭名称选ICO；需要读正文、标题或作者才能确认的，按图片独立判断处理，必要时标`?`／UNRESOLVED。
3. **SC-STR按日常内容判断。** 画面主要呈现街道、市场、社区或市井生活时选STR，不论该地现在是否出名、是否在清单中。旧定义中的“普通”不再作为门槛，避免把“是否出名”带入判断。日常场景走红为吸引物的现象由文字侧`rs_r_lif`与`at_has_sug`／评价等组合记录，不由V8改记ICO。
4. **两者都有时看视觉突出度。** 标志性地点特征与街市日常内容同时出现时，看哪类场景内容在画面中更突出；V8看场景，不看V7主体，人物在前景不自动把ICO降为STR。仍不能判断时标`?`／UNRESOLVED，说明两类证据。
5. **疑似地标但图片无法确认时保留疑问。** 不自行上网查地名，不读对应正文、标题、作者或其他图片来补ICO；SC-OTH只用于食物特写、室内设施或确实不属于前两类的画面，不作为“不知道”的兜底。
6. **地点身份作为分析变量，不进入人工V8。** `mentions_2026_landmark_list`由程序按冻结的2026清单名称／别名匹配帖子正文生成（1／0／NA）；含义仅为“正文提及2026清单地点”，不表示发帖时该地已经是景点，也不用于填写V8。海泊河早市等日常场景型地点可加入该匹配清单，但不因此改变V8判断。

以下为自拟教学例，均按画面内容判断，不是原始样本裁决：

| 画面内容 | V8 | 理由 |
|---|---|---|
| 早市摊位、人群、买卖 | SC-STR | 日常街市内容，不因该地走红改ICO |
| 早市门楼或招牌是画面主体，能确认地点 | SC-ICO | 仅凭画面可辨认的具体地点特征 |

### V11 可见对象状态（图片级，10个条件性原子项）

V11回答“画面中与目的地体验有关的对象呈现出什么可直接观察的状态”，不回答“这张图片整体是正面还是负面”。编码员须分别判断以下原子项；同一状态轴的正向与负向字段彼此独立，若画面不同区域或对象同时提供充分证据，可以同时记1，以保留混合状态。

| 状态轴 | 代码 | 字段 | 标签 | 纳入规则 | 关键排除 |
|--------|------|------|------|----------|----------|
| 设施维护 | VSC-FAC-POS | `vis_fac_condition_pos` | 设施完好/维护良好 | 设施主体清晰可见，且存在完好、维护良好或功能状态正常的直接证据 | 豪华、新颖、价格高或拍摄精美本身不足以判1 |
| 设施维护 | VSC-FAC-NEG | `vis_fac_condition_neg` | 设施破损/失修 | 出现破损、严重老化、关键部件缺失或明显无法正常使用的设施证据 | 历史建筑的年代感、风化质感不自动视为失修 |
| 卫生整洁 | VSC-HYG-POS | `vis_hyg_condition_pos` | 干净整洁 | 相关区域覆盖充分且清晰，并呈现干净、整洁、无明显垃圾、污渍或霉斑的状态 | 远景中“没有看到垃圾”或因裁切未显示地面不足以判1 |
| 卫生整洁 | VSC-HYG-NEG | `vis_hyg_condition_neg` | 脏乱/不卫生 | 出现垃圾、污渍、积水、霉斑、废弃物或明显不卫生处理方式 | 单纯陈旧、色调暗或画面噪点不足以判1 |
| 现场秩序 | VSC-ORD-POS | `vis_order_condition_pos` | 秩序清晰 | 服务、排队、市场或交通空间中存在排列有序、动线清晰、通道无明显阻塞等证据 | 无人场景或人数少本身不足以判1 |
| 现场秩序 | VSC-ORD-NEG | `vis_order_condition_neg` | 杂乱/秩序混乱 | 出现杂乱堆放、通道堵塞、无序排队或明显现场混乱 | 人多、画面拥挤或热闹氛围本身不足以判1 |
| 环境维护 | VSC-ENV-POS | `vis_environment_condition_pos` | 环境维护良好 | 自然或公共环境呈现维护良好、生态完整或修复到位的直接证据 | 风景美、天气好、滤镜鲜艳或构图漂亮不足以判1 |
| 环境维护 | VSC-ENV-NEG | `vis_environment_condition_neg` | 污染/环境退化 | 出现污染、植被破坏、岸线或公共环境明显退化等直接证据 | 季节性枯黄、正常潮汐或阴天不自动判1 |
| 可见安全线索 | VSC-HAZ | `vis_hazard_present` | 可见危险源 | 出现湿滑无防护路面、破损护栏、裸露电线、明显坠落或碰撞风险等可见危险源 | 不据此推断事故概率，也不把刺激性活动自动视为危险 |
| 可见安全线索 | VSC-PRO | `vis_protection_present` | 可见防护措施 | 出现护栏、警示标志、救生设备、隔离设施或其他清晰可辨的防护措施 | 未出现防护措施不得反推场景不安全 |

**条件状态规则**：

1. 先判断该状态轴是否被画面触发。没有相关对象、相关区域未进入画面，或可见范围不足以评价该轴时，成对字段均记`NA`。
2. 状态轴适用且画面足以判断时，各原子项分别填`1`或`0`。`0`只表示本标签未成立，不代表相反标签必然成立。
3. 共同校准期若现行规则或画面证据无法支持唯一判断，填`UNRESOLVED`，同时标`?`并写一句疑问说明。V11与其他内容字段一致不设`UNK`（v3.20.0）；画面可见范围不足以评价某轴时按第1条记`NA`。
4. 正负字段可以同时为1，例如酒店大堂主体整洁但角落存在垃圾；不得强制抵消、择一或计算“净正负”。
5. V11不得由V7主体、V10消费符号、滤镜色彩或文本情感自动派生，也不得用于推断服务态度、食物味道、住宿舒适度、满意度或整体目的地质量。

V11当前用于视觉描述、质量审计及候选图文属性方向匹配；其正式假设、聚合方式与模型发布门在视觉人口和独立信度冻结前均为`DEFERRED`。

### 5.4 状态、疑问标记与文本证据记录契约

#### 5.4.1 一般状态语义

以下语义在共同校准前统一使用，但不预先为每个字段增加专门例外。共同校准用于发现哪些字段确实需要额外`NA`条件或边界规则，不能把同一批经讨论材料的高一致率当作独立信度。

**内容字段不设`UNK`（v3.20.0）：** V1—V11全部内容字段的正式值域只含`1`、`0`、`NA`（以及各字段定义的类别代码，含V2 `destination_type=NONE`）。NONE只表示该字段的“未呈现明确取向”，不是通用未知或未决状态。文本材料由固定快照与片段提供，材料缺失不属于字段层面问题；编码员拿不准时填最可辩护值并标`?`，规则无法唯一裁决时填`UNRESOLVED`，材料本身损坏或缺失时提交材料问题报告。V0作者身份轨资料确有缺失，继续使用`UNK`，缺失不得当作阴性，见第V0.4节。

| 状态 | 操作定义 | 使用边界 |
|------|----------|----------|
| `1` | 字段适用，且观察到支持该标签或类别的材料证据 | 正式值 |
| `0` | 字段适用，完整判断后未观察到相应内容 | 不得用于表示未检查、无法判断或结构性不适用 |
| `UNK` | 字段适用，但材料缺失、过度模糊或证据冲突，无法形成有证据的唯一判断 | **仅V0作者身份轨使用**；V1—V11内容字段不设此值（v3.20.0） |
| `NA` | 字段因条件未触发而结构性不适用 | 不参加该字段信度分母和模型损失 |
| `UNRESOLVED` | 共同校准期的临时工作状态，表示现行规则尚不能唯一裁决 | 不属于正式研究值；必须进入问题登记并在盲试标前关闭；关闭时只能改为该字段的`1`／`0`／`NA`或类别代码 |

规则冻结后使用新样本进行独立盲试标。字段达到`alpha >= 0.80`、类别支持足够且分歧审计未发现反复出现的系统性边界问题时，维持一般状态语义，不再为了形式完整追加字段专门规则。若修改值域、定义或适用条件，原信度失效，并须用新的未讨论样本确认。

#### 5.4.2 可选逐字段疑问标记

疑问标记是编码员在完成某个主观判断后，用来说明“这个字段我拿不准，需要锁定后讨论”的可选过程标记。正常判断只填写标签值，不需要额外评分；客观导入字段和结构性`NA`不得标记。它不是准确概率、研究变量、信度指标或模型监督目标。

| 人工情况 | `review_flag` | 强制动作 |
|----------|---------------|----------|
| 已按规则形成可辩护判断，没有主动疑问 | 留空 | 只填写标签值，继续下一个字段 |
| 已填写当前最可辩护值，但边界、语境、冲突或材料使编码员拿不准 | `?` | 选择原因，必要时填替代值，并用一句话说明难点 |
| 共同校准期现行规则无法支持唯一值 | `?`，且`label_value=UNRESOLVED` | 选择原因、写一句说明，并进入负责人问题队列 |

规范长表把人工问号统一保存为`review_flag=1`，无标记保持空白；`review_notes_json`只覆盖被标记字段，每项保存`reason_code`、`alternative_values`和`note`。`alternative_values`没有合理替代值时允许为空数组，编码员不手写JSON。原因只从`BOUNDARY`、`CONTEXT`、`CONFLICT`、`EVIDENCE_MISSING`或`OTHER`中选择。带问号但已有可辩护标签的记录保留供锁定后复核，不自动进入问题队列；只有`UNRESOLVED`或另行登记的框架、反例、语境、切分问题自动入队。

两名编码员独立工作时只能看见自己的疑问标记。两份原始文件锁定后，负责人同时查看实际字段分歧和双方疑问标记；一致性计算仍检查全部字段，不能只检查标过问号的字段。旧轮次已有1—5级置信度原样留作历史过程资料，不删除、不换算，也不与新轮次疑问标记合并统计。

#### 5.4.3 统一文本证据跨度

文本轨统一使用`evidence_spans_json`，不再分别维护`resource_spans_json`和`aspect_spans_json`。每个对象包含`fields`、`start`、`end`和`quote`：

```json
[
  {"fields": ["rs_n_wat"], "start": 3, "end": 5, "quote": "海风"},
  {"fields": ["at_has_eval", "sentiment_dir"], "start": 8, "end": 11, "quote": "很舒服"}
]
```

- offset始终定位不可变的`raw_text`，按Unicode字符从0开始计数；区间采用左闭右开`[start, end)`。
- 必须满足`raw_text[start:end] == quote`；导入时校验非负、未越界且引文完全一致。
- 编码员只复制最短充分的`quote`；转换工具自动计算`start/end`。同一引文在`raw_text`中重复出现时，编码员才填写其起始位置，不要求日常手工计算offset。
- 同一字段可以有多个不连续跨度；同一跨度可以支持多个字段；跨度之间允许重叠。
- 选择能够支持判断的最短充分文本；否定、程度和转折会改变含义时必须一并纳入。
- **v3.20.0证据要求**：`asp_applicable=1`时，V6主导属性必须有至少一个证据跨度，覆盖所选主导评价；V3、V4、V5的其余阳性标签不强制填写，编码员标`?`时必须为该字段提供证据。以下旧规则保留作为非必填时的填写方式。
- 实质性阳性标签原则上至少有一个证据跨度。`0`、`NA`以及`at_non`、`is_non`、`asp_applicable=0`等整体排除或不适用判断不伪造局部跨度，其原因由状态或疑问说明承担；V3和V6的父类与子类可共享同一最短充分证据。
- 问题登记中的文本`evidence_spans_json`使用同一契约；视觉图像区域的坐标契约待视觉轨T0关闭后另行冻结。

### 5.5 校准问题与编码簿修订记录（不属于研究变量）

本节记录只在**共同校准、盲试标及版本评审**中使用，用于检验预设框架是否完整、边界是否可执行。它们不进入H1—H8检验，不作为BERT监督目标，也不得被汇总为主题分析结果。

**最低负担的人机分工**：共同校准的编码员只填写一张`calibration-coding`主表。系统预填身份、观察单位、字段、值域与版本；编码员只填写编码值，在确实拿不准时标`?`并写原因和一句说明，实质性阳性判断摘录证据原文，极少数框架外或切分问题另行登记。转换工具生成`labels.csv`所需JSON与文本offset，并把`UNRESOLVED`和额外问题整理为负责人问题队列。编码员不填写独立问题表或修订决策表。

<a id="pilot-review-20261021"></a>

**负责人复盘（2026年10月21日确认）：** 首批材料可以探索与校准。两人首次答案保存后，由研究负责人利用现有问题登记／修订记录，最低限度保留“材料位置—观察到的图文配合—对应研究问题—现有编码能否覆盖／是否必要”。不要求编码员逐帖新增关系命名、开放编码或另一套表格，复盘观察本身不作模型监督标签或组间出现率。

## 六、编码规则清单

### 文本轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **逐字段人工编码** | 编码员对所有进入记录表的字段逐项判断；跨字段逻辑仅用于复核，不得由程序自动生成或覆写 |
| 2 | **可选疑问标记** | 每个主观判断先填写标签值；确实拿不准时才按第5.4.2节标`?`并写一句说明 |
| 3 | **贴着文本** | 编码来自句子自身传达的信息，不过度推断 |
| 4 | **证据先行** | V6主导属性必须定位证据；V3/V4/V5阳性判断在标`?`时必须定位，其余可选（v3.20.0）；均使用统一`evidence_spans_json`；父类与子类可以共享证据，层级和跨字段逻辑仅用于复核；`rs_r_act`分析汇总不另记证据 |

| 10 | **主导评价绑定** | 片段不按属性或方向再切分；按“转折后→强度高→先出现”选出主导评价，V6记其属性，V5记其亚类、方向与强度；V6保持方向中立 |

### 视觉轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **画面优先** | 编码依据是画面本身，而非配文描述 |
| 2 | **主体面积优先** | 仅V7视觉主体在多个元素共存时按视觉突出度和面积判定 |

### 编码簿开发与修订规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **问题登记不等于新增编码** | 编码员可登记框架遗漏、边界案例和反例，但在团队决策生效前只能按现行值域编码或依适用规则记`UNK/NA`，不得自造标签 |
| 2 | **相关性先行** | 只有与既定研究问题和分析范围直接相关、且现行字段无法有效表达的材料才能登记为`FRAMEWORK_GAP`；一般性新奇内容不扩张框架 |
| 3 | **支持证据与反例并列** | 每项实质修订必须同时检查支持材料、分歧案例和反例，不能只凭频次、单个典型例或理论期待改规则 |
| 4 | **语境单位不改观察单位** | 编码员可阅读完整帖子与必要图文语境来消歧，但文本标签仍落在固定`seg_id`，图像标签仍落在固定`img_id`；系统性切分问题另行登记 |
| 5 | **规则与备忘分离** | `issue_note`只保存问题和分析理由；只有进入新版编码表的定义、值域、纳入/排除规则与锚点例句才具有规范效力 |
| 6 | **冻结前修订，冻结后停表评审** | 共同校准和盲试标可触发修订；正式编码开始后发现判定边界改变时，须暂停受影响字段、升版并确定重编码范围 |
| 7 | **AI不能决定类目** | AI可辅助检索相似案例或提出候选问题，但须记录工具/模型版本并由研究者核验；AI不得新增类目、关闭问题或把聚类命名为正式发现 |

**重编码门**：仅修正错别字、链接或不改变任何判定结果的表述时，`recoding_scope=NONE`；增加锚点但不改变边界时至少复核试标样本；改动操作定义、纳入/排除规则、值域、分析单位，或新增/合并类目时，旧信度结果失效，至少对全部受影响字段重编码，并用未参与规则修订的新样本重新确认信度。是否达到“实质改动”必须由两名研究者共同决定并写入修订决策表。

## 七、候选帖子级聚合指标体系（`DEFERRED`）

本节保留既有公式用于未来评估，不是当前编码表冻结、文本试标或模型训练的前置条件。只有原子标签完成正式信度、模型效度和全语料发布后，才能决定是否采用SRM、SAM、AAM、COD或其他替代方法；在此之前不得将这些指标解释为因果“传导”。

### 7.1 文本轨聚合指标

| 指标 | 公式 | 取值范围 | 含义 |
|------|------|----------|------|
| segment_count | COUNT(seg_id) | 1-N | 有效文本片段总数 |
| **V4 Layer 1** | | | |
| rsd_n | SUM(rs_n) / segment_count | [0, 1] | 自然旅游资源提及密度 |
| rsd_r | SUM(rs_r) / segment_count | [0, 1] | 人文旅游资源提及密度 |
| **V4 Layer 2** | | | |
| ICB | 12个Layer 2自然+人文亚类出现数之和 | 0-12 | 总资源覆盖广度；事件Layer 3不重复计入 |
| IMP_N | [rsd_n_geo, rsd_n_wat, rsd_n_bio, rsd_n_cli] | 四维向量 | 自然资源亚类轮廓 |
| IMP_R | [rsd_r_his, rsd_r_arc, rsd_r_gas, rsd_r_fol, rsd_r_rec, rsd_r_evt, rsd_r_gds, rsd_r_lif] | 八维向量 | 人文资源亚类轮廓 |

| **V3** | | | |
| CSP | [csd_inf, csd_edu, csd_emo, csd_int] | 四维向量 | 内容策略出现率；各维可共现 |
| **V5 Layer 1** | | | |
| ATP | [atd_inf, atd_evl, atd_sug] | 三维向量 | 语言功能出现率；各维可共现 |
| **V5 Layer 2** | | | |
| ATD | [atd_pos, atd_neg, atd_mix] | 三维向量 | 情感方向轮廓（仅AT-EVL+AT-SUG） |
| **V6 Layer 1** | | | |
| AIP_L1 | [aspd_exp, aspd_sup, aspd_ops, aspd_wel] | 四维向量 | 四类目的地属性父类被评价/建议的出现率 |

### 7.2 视觉轨聚合指标

| 指标 | 公式 | 含义 |
|------|------|------|
| image_count | COUNT(img_id) | 配图数量 |
| VIC | 视觉主体覆盖广度（0-5） | 几类视觉主体被使用 |
| dominant_visual_subject | V7频次取最大值 | 主导视觉主体 |
| hpd_sin | COUNT(PC-SIN) / image_count | 单人呈现占比 |
| hpd_grp | COUNT(PC-GRP) / image_count | 群体呈现占比 |
| hpd_int | SUM(human_scene_interaction) / image_count | 人景互动占比 |
| v16_fac_pos / v16_fac_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 设施维护状态正向/负向出现率；各自排除NA |
| v16_hyg_pos / v16_hyg_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 卫生整洁状态正向/负向出现率；各自排除NA |
| v16_order_pos / v16_order_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 现场秩序状态正向/负向出现率；各自排除NA |
| v16_environment_pos / v16_environment_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 环境维护状态正向/负向出现率；各自排除NA |
| v16_hazard / v16_protection | SUM对应字段=1 / COUNT对应字段∈{0,1} | 可见危险源/防护措施出现率；各自排除NA |

V11只分别报告原子项或成对轮廓，不计算单一“视觉正负得分”。同轴正负同时为1表示混合状态，不应相互抵消。以上指标在V11完成独立信度冻结及分析预注册前均为`DEFERRED`。

**VS-OTH的聚合处理（v3.24.1）：** `VS-OTH`不计入`VIC`的0—5类覆盖，也不作为`dominant_visual_subject`的资源指向类别；如需报告，单独列为“其他／无明确视觉主体”，不并入任一具名主体。

### 7.3 跨维度关联指标

**SRM_L1：策略→资源大类关联（4×2）**

```
SRM_L1[CS-X][RS-Z] = COUNT(segments with CS-X AND RS-Z=1) / COUNT(segments with CS-X)
```

**SRM_L2：策略→资源亚类关联（4×11）**

**SRM_EVT：策略→事件子类关联（4×4；限`rs_r_evt=1`片段）**

**SAM_L1：资源大类→语言功能共现（2×3）**

**SAM_L2：资源亚类→语言功能共现（11×3）**

**SAM_EVT：事件子类→语言功能共现（4×3；限`rs_r_evt=1`片段）**

**AAM：V6属性子类→V5情感方向关联（14×3）**

```
AAM[ASP-X][DIR-Z] = COUNT(segments with ASP-X=1 AND sentiment_dir=Z) / COUNT(segments with ASP-X=1)
```

AAM仅分析`asp_applicable=1`且V6具名子类为1的片段。自v3.20.0起矩阵描述的是片段主导属性与其方向的关联，不覆盖次要属性；仍不得解释为因果传导。

**COD：共现密度**

| 指标 | 公式 | 含义 |
|------|------|------|
| COD_n_r | SUM(rs_n × rs_r) / segment_count | 自然+人文大类同片段共现密度 |
| COD_ngeo_rhis | SUM(rs_n_geo × rs_r_his) / segment_count | 地文景观+历史遗存共现密度 |
| COD_inf_evl | SUM(cs_inf × at_has_eval) / segment_count | 实用信息策略+评价功能共现密度 |
| IFD | SUM(rs_depth) / segment_count | 平均资源融合深度（0-12）；`rs_depth`只累加12个Layer 2亚类，不重复累加Layer 3事件子类或`rs_r_act`汇总项 |

## 八、标注方案与模型验证

理论导向的结构化内容分析依次完成“框架建立—数据校准—盲试标冻结—正式人工测量—模型扩展—统计分析”。神经网络是扩大已冻结测量的辅助工具，不是类目生成方法。人工信度与模型效度必须分开报告。

| 阶段 | 文本轨 | 视觉轨 | 目的 |
|------|--------|--------|------|
| 阶段0：框架与范围预定义 | 根据理论、标准、既有研究与H1—H8定义变量、一般状态语义、文本观察单位、疑问标记和证据规则；达到`CALIBRATION_READY`即可启动共同校准 | 在启动前另行冻结视觉人口、图片单位及边界T0 | 确认研究问题—构念—字段—分析输出的可追溯关系 |
| 阶段1：共同校准与规则修订 | 首批50篇完整帖子（含全部固定片段）随机抽取，两人独立试编码后讨论（2026-10-01确定，原“约20—30篇”不再适用）；编码员只填写单一主表，确实拿不准的字段标`?`并写一句说明，`UNRESOLVED`必须标记；工具提取问题队列，研究负责人按第5.5节分类和裁决；不计算正式信度 | 暂不启动，或只做不占用文本预算的小规模规则探索并单独记账 | 决定哪些字段需要专门`UNK/NA`或边界规则，不生成主题或正式结果 |
| 阶段2：独立盲试标与冻结 | 另取约70—80篇新样本，双人独立编码且首轮完成前不交换判断；计算逐字段信度并在完成后裁决 | 视觉轨启动条件满足后采用同样流程 | 冻结编码表、锚点例句与裁决规则；实质修订后旧信度失效并用新样本确认 |
| 阶段3：评估金标与训练标注 | 锁定测试集全部双人独立编码并共识；训练池由主编码员标注，第二人复核预注册随机比例及全部稀有、带疑问标记、冲突样本 | 文本人工证据通过后另行确定，不预设600张固定承诺 | 建立可追溯评估金标和训练标注；按作者/重复簇隔离训练、开发与测试 |
| 阶段4：主动学习 | 与同人工分钟数的随机扩样作等预算对照；主编码员标注，第二编码员承担风险复核和随机审计 | 仅在视觉标签信度与图片质量门通过后启动 | 检验而非预设主动学习是否节省人工；不触碰锁定测试集 |
| 阶段5：模型与统计验证 | 在预先锁定的测试集上报告逐标签Precision/Recall/F1、PR-AUC、校准、子群表现和置信区间；只对达到发布门的字段执行预设统计 | 同样执行锁定测试与选择性复核 | 逐标签决定可自动、AI辅助、人工专判或探索性，并回答预设研究问题 |

**冻结边界**：共同校准材料可用于修订规则，不能进入正式信度估计；盲试标首轮不得边标边改。若盲试标后仅增加不改变边界的锚点例句，可在决策日志中说明并复核试标样本；若定义、值域、单位或纳入/排除规则发生实质变化，必须升版、重编码受影响字段并用新样本重新验证。正式编码后不得以“框架外内容”为名增加临时类别。

训练标注按每批50篇完整帖子逐批累积：初期随机抽取，后期依据模型评估反馈针对薄弱类别或反复错误定向补样，不预设总量（总备忘录B12，2026-10-01确定）。旧“500篇文本”预算锚点不再作为目标；实际训练规模由逐标签阳性数、学习曲线、区间宽度和人工分钟数共同决定，停止条件由模型负责人落实（B14）。定向补样所得标签比例不代表研究总体分布。

**信度指标**：文本多标签信度对每个原子二值标签分别计算Krippendorff's alpha（名义尺度）；两位编码员时可同时报告Cohen's kappa作为敏感性结果。目标为`alpha >= 0.80`；同时检查类别样本数、阳性/阴性一致率、`UNK/NA`比例和分歧类型。达到目标且没有反复出现的系统性边界分歧时不再追加字段专门规则；`0.667 <= alpha < 0.80`只用于暂定分析并须复查，低于0.667的标签不得直接进入模型训练。任何实质修订均使原信度失效。

**训练标签兼容（2026年10月21日确认）：** 规则修订后按“字段×版本”判断训练资格，不把整批旧材料一律作废。定义、值域、单位或必要上下文不兼容的旧标签不进入新标准训练；原始答案及版本保留，未标或不兼容不补0、不作阴性。未变字段也须逐项确认含义、观察单位、上下文及数据集隔离仍兼容，不能只因字段同名就沿用。首批试编码不自动成为金标，仍须满足相应规则冻结、独立信度与裁决门；共同讨论材料不能回用于正式信度或锁定独立评估。具体筛选、隔离与训练实现由模型负责人落实，B14继续条件启动；本次只确认规范，不修改已有标签、训练配置或数据集。

**AI边界**：模型只学习已冻结并通过信度门的人工金标，包括获准后的V0、V3（含旧编号V5并入的互动子项）、V4、V5、V6及后续获准的视觉字段。V0训练、锁定测试和质量门全部完成前不得对非金标样本输出正式角色；训练完成后人工退出生产编码，程序预测与派生只作用于非金标扩展样本，不得回写人工金标。V4的`rs_r_rec`、`rs_r_evt`与四个事件子类须逐字段输出，`rs_r_act`只由预测后的二值结果在分析层OR汇总，不设训练头；层级关系不得覆盖模型概率。V6适用性、父类、子类与其他项均须逐字段输出；不得以V5情感方向替代V6属性预测，也不得以父子逻辑覆盖模型概率。V11在完成视觉人口定义、专门规则冻结与独立信度验证前不得训练或发布；获准后仍须逐原子项输出，不得用一个图像情感分数替代10个字段。聚类、关键词、生成式摘要或模型建议只能作为金标锁定后的错误分析和问题检索线索；它们不能直接改变值域、关闭问题登记、替代人工裁决，也不能被命名为正式“主题”。所有模型扩展结果必须回到锁定人工金标上验证。

## 九、候选研究问题与假设

**研究问题与分组适用范围：** 主问题及RQ1—RQ3沿用2026年10月1日确认的内容研究安排。10月6—10日的三组方案保留为历史；2026年10月29日起先分别记录主体、公开定位与规模，正式比较分组待定。下述候选命题不授权恢复旧分组或自动启动比较。

**主问题：** 不同类型的旅游内容创作者，如何运用内容策略呈现青岛的旅游目的地形象？

| 研究问题 | 表述 | 作用 | 主要字段 |
|---|---|---|---|
| RQ1 | 不同类型创作者在内容策略的使用上有哪些差异？ | 策略分布，为核心问题提供基础 | V3（含互动子项） |
| RQ2 | 不同类型创作者呈现的青岛目的地形象有哪些差异？ | 资源、属性及评价等形象内容，为核心问题提供基础 | V4、V5、V6 |
| RQ3 | 不同类型创作者如何将内容策略与目的地资源、属性及评价相结合？ | **核心问题**，分析策略与形象内容的联系及类型差异 | V3与V4／V5／V6的同片段共现及帖子汇总 |

**创作者类型的正式比较分组待定。** 当前按[分开记录规则](#creator-positioning-scale-separated-20261029)保存主体、所有个人账号的公开定位及粉丝原值；不再把低于门槛直接等同普通个人，也不自动冻结三组／四组。正式比较前确定分组、规模用途及纳入／缺失处理，核对分平台独立账号、材料和测量支持；身份任务仍覆盖文本和图片作者，合并去重后两轨共用。历史三组只解释旧任务。

以下保留原H编号作为候选比较命题，均为非方向性描述比较，不构成创作者对受众的因果机制。机构可能更偏向正面呈现、个人可能附带瑕疵或建议，只是待检验预期；不得把“机构一定正向／图文一定同向／只有个人会相反”作为编码规则。相似结果也应依测量及不确定性报告，不把未检出差异直接证明为相同：

```
H1（RQ2）: 经正式方案确定的创作者群体在目的地资源调用轮廓（V4）上存在差异
H2（RQ1）: 经正式方案确定的创作者群体在内容策略轮廓（V3父类及子类）上存在差异
H3（RQ3）: 经正式方案确定的创作者群体在内容策略与目的地资源的同片段共现上存在差异
H4（RQ2／RQ3）: 经正式方案确定的创作者群体在主导评价属性（V6）及其表达方向与强度（V5）上存在差异，并在策略与属性评价的同片段共现上存在差异
H5（RQ1）: 经正式方案确定的创作者群体在互动信号轮廓（V3-CS-INT子项）上存在差异
H6（辅助，条件启动）: 同一帖子文字资源（V4）与图片主体（V7）的对应情况在经正式方案确定的创作者群体间存在差异
H7（试编码反馈后讨论）: 身份差异是否在相同明确商业披露状态（V1）或相近题材下仍然存在
H8（DEFERRED）: 在分别满足身份材料与组别支持的平台之间，组间比较结果存在平台异质性
```

**分析口径（已确认部分）：** 片段记录、帖子汇总、作者等权比较（B13）。RQ3的“结合”以同一片段内的编码共现为基础再向帖子汇总，只解释为表达上的共同出现，不推断创作者意图或因果作用；SRM、SAM、AAM等旧矩阵只作为候选计算形式。单项策略还是策略组合、关注程度与评价倾向如何分别报告、身份差异与题材／商业披露的关系三项取舍，在试编码反馈后、正式比较前确定（总备忘录第七节）。

**定义重叠与解释边界：** 当前身份只依据账号认证、用户名、粉丝与简介定位，不使用目标帖的内容策略、建议、个人经历或情感，因而与V3—V6没有直接定义重叠；正式比较前仍须确认没有字段同时用于分组和结果。新版定位不由粉丝决定；若正式方案进一步按规模分组，组间粉丝差异仍不是独立身份效度证据。研究问题只由冻结的结构化字段及其预设聚合回答，不另设“从数据中生成主题”的研究问题；不得在查看结果后调整身份定义或分组方式。
