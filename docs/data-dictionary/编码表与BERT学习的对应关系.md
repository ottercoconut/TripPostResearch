## 一、核心认识

编码表定义 BERT 需要学习哪些判断任务，但不直接规定 BERT 内部应该提取哪些语言特征。

普通监督微调中，BERT 不会直接阅读编码表中的文字定义。实际过程是：

```text
编码表定义研究概念
        ↓
人工依据定义产生标签
        ↓
标签成为模型监督信号
        ↓
BERT从正例和负例中学习实际判定边界
```

因此，BERT 真正学习的是编码表经过人工操作化之后形成的标签分布。

## 二、编码表与模型结构的基本映射

| 编码表中的内容 | BERT中的对应结构 |
|---|---|
| 一个研究维度 | 一个任务族；可按值域拆为多个技术头 |
| 维度下的一个代码 | 分类头中的一个输出节点 |
| 一个固定语义片段的编码结果 | 文本主任务的目标向量 |
| 多个代码可以同时成立 | 多个独立 Sigmoid |
| 类别严格互斥 | Softmax |
| 独立人工连续目标 | 可使用回归头；当前文本编码没有此类目标 |
| 有顺序的等级变量 | 序数分类头 |
| 父类—子类关系 | 父类与子类均建输出；关系可作一致性审计或候选层级约束 |
| 无法判断、不适用 | 损失掩码，不参与该项训练 |
| 标签对应的文本证据跨度 | 可选证据抽取或解释任务；不默认等同于attention |
| 标签次数、片段比例、是否出现 | 预测后进行的基础帖子级统计，不作为模型标签 |
| 密度、广度、轮廓、共现与自定义指数 | 原研究设计的后置分析计算；按各自现有质量门与`DEFERRED`状态保留 |

## 三、理论维度与技术头的关系

假设研究包含四个维度：

```text
共享BERT编码器
├── 旅游主题头
├── 叙事方式头
├── 体验维度头
└── 推荐意图头
```

这些分类头共享BERT的文本表示，但分别学习不同的研究判断。

通常可先把一个理论维度视为一个任务族，而不是把每个标签都建成独立任务。同一维度内部如果同时包含多标签、互斥分类或条件字段，可以按输出值域拆成多个技术头。例如当前V5需区分语言功能、评价亚类、情感可判定状态、方向和双向强度；V6则是独立的属性任务族，不能并入V5情感头。

例如，某个分类头包含：

```text
[大海, 高楼, 山岳, 古建筑]
```

一个固定片段同时出现“大海”和“高楼”时，其目标向量为：

```text
[1, 1, 0, 0]
```

不需要额外建立“大海+高楼”这一复合类别。

## 四、多标签与单标签的区别

当同一维度中的多个标签可以同时成立时，使用独立 Sigmoid：

\[
\mathbf p^{(d)}=\sigma(W_d\mathbf h+\mathbf b_d)
\]

模型可以同时输出：

```text
大海：0.92
高楼：0.81
山岳：0.07
```

当类别理论上严格互斥时，才使用 Softmax。Softmax 会使同一分类头下的概率总和为 1，不适合“大海”和“高楼”可以共存的情况。

## 五、BERT如何学会一个代码

BERT先把帖子编码成上下文表示：

\[
H=\operatorname{BERT}(x)
\]

然后每个标签利用自己的参数进行判断：

\[
p_k=\sigma(\mathbf w_k^\top\mathbf h+b_k)
\]

训练数据不断向模型提供：

```text
帖子A → 大海=1
帖子B → 大海=0
帖子C → 大海=1
```

模型由此学习哪些上下文模式与“大海=1”相关。它学习的不是单个关键词，而是训练样本中形成的语言决策边界。

如果书面定义和人工实际编码不一致，模型最终会学习人工编码表现出来的规则。

## 六、当前研究的监督单位

| 编码单位 | 模型任务 |
|---|---|
| 一篇完整帖子 | 帖子级分类 |
| 一个句子或段落 | 片段级分类 |
| 一个词语或文本跨度 | Token/Span分类 |
| 两个实体之间的联系 | 关系分类 |

当前编码表已经确定：

```text
固定客观片段（objective-structure-0.5，v3.20.0）= V3/V4/V5/V6文本主任务的人工判断与模型监督单位；V5情感与V6属性对应片段主导评价
帖子 = 片段预测完成后的候选聚合与下游比较单位
```

确定性切分规则必须先生成并冻结`seg_id`；编码员不得在标签任务中改变边界。帖子级“是否出现/密度/主导”口径不能反向成为训练标签，除非编码表以后明确增加独立帖子级构念。

## 七、帖子级聚合

同一个“大海”标签可能表示三种不同任务：

1. 文本只要提到一次大海即为 1；
2. 文本必须对大海作出实质描述才为 1；
3. 大海必须是整篇帖子的主导意象才为 1。

三者对应的学习难度和模型聚合方式不同：

- 出现型标签主要依赖局部证据；
- 实质型标签需要理解完整上下文；
- 主导型标签需要比较不同内容在全文中的相对重要性。

同一标签在帖子各片段中的出现次数、出现次数除以有效片段数、是否至少出现一次，是片段预测或人工金标锁定后的基础汇总。它们不反向成为训练标签，也不取代IMP、CSP、ATP、ATD、AIP、ISP等轮廓指标。

SRM、SAM、AAM、COD及其他综合指标按原研究设计保留`DEFERRED`：它们不属于模型监督目标，但也不因本轮编码方法改进而删除。

## 八、未标注不能自动等同于负例

多标签训练中应区分：

```text
1   = 标签明确存在
0   = 完整判断后确认不存在
UNK = 字段适用但无法形成有证据的唯一判断
NA  = 对该材料不适用
```

`0`会作为负例训练模型；`UNK`和`NA`通常需要从对应标签的损失中屏蔽。

如果把未经检查的标签直接写成0，BERT会收到错误的负例信号。

`UNRESOLVED`只允许出现在共同校准工作记录中，必须在盲试标前关闭，不能成为模型类别。字段专门`UNK/NA`规则在共同校准后决定；新样本盲试标达到`alpha >= 0.80`且没有系统性边界分歧时不再追加规则。

人工`review_flag`和`review_notes_json`只在编码员拿不准时记录，用于两份原始文件锁定后的复核，不是监督标签、输入特征或损失权重。文本证据统一使用`evidence_spans_json`：offset定位不可变`raw_text`，从0开始、左闭右开，并保存`quote`校验；原`resource_spans_json`与`aspect_spans_json`停止使用。

## 九、父子标签的处理

假设标签存在以下结构：

```text
自然景观
└── 海滨景观
    └── 大海
```

如果某个项目明确把父标签定义为纯逻辑汇总，可以由程序计算；但当前编码表没有把V3、V4或V6父类定义为可覆盖人工值的派生项：

```text
大海=1
→ 海滨景观=1
→ 自然景观=1
```

只有编码表把父类定义为独立人工判断时，才可考虑分别输出并检验层级约束：

\[
p(\text{大海})
\leq p(\text{海滨景观})
\leq p(\text{自然景观})
\]

父类和子类是否都需要预测，只能由编码表是否把它们定义为独立研究判断决定。当前V3父类与22个子项、V4两个大类与10个Layer 2亚类及4个事件子类、V6四个父类与12个子类均为人工金标；`cs_oth`、`at_non`、`is_non`、`evt_oth`、`asp_oth`也须输出。规则只能报告冲突，不能补写或覆盖概率。`rs_r_act`是`rs_r_rec OR rs_r_evt`的分析汇总，不是模型节点。

## 十、派生指标不作为主要预测目标

如果若干原子标签可以进一步形成：

- 组合模式；
- 建构广度；
- 标签密度；
- 共现矩阵；
- 综合指数；

这些结果应在 BERT 输出以后由程序计算：

```text
BERT预测原子标签
        ↓
统计程序计算派生指标
```

不应让模型同时预测原子标签和可以由原子标签精确计算的组合编号，否则容易产生逻辑矛盾。

## 十一、当前任务头与共享表示

编码表v3.16.0的文本任务包括：V3的5个父类与22个子项，V4的2个大类、10个Layer 2亚类与4个事件子类，V5的4个语言功能字段、AT-EVL亚类、情感可判定状态、方向与双向强度，以及V6的适用性、4个父类、12个子类和其他项。除明确声明为分析汇总的`rs_r_act`外，所有字段均由编码员判断，模型原则上逐字段输出；任何裁剪都只能作为经验证的工程消融，不能反向改变人工金标。AT-EVL亚类及V4新增字段的信度门尚未冻结。

V0不是上述文本BERT的内容预测头。角色任务以作者证据窗口为单位，EA、CE、SC、证据充分性和最终角色均为直接人工金标，CI固定`UNAVAILABLE`，并与V1—V6目标内容执行T0/T1隔离。只有全部人工裁决锁定、角色规则冻结且50名新作者独立盲试标通过后，才可另行训练和锁定测试作者级模型；通过后人工退出非金标生产编码，程序只处理非金标样本。不得用目标帖文本、粉丝量、认证或互动量静默替代角色证据，也不得回写金标。

视觉任务另用图像模型或多模态模型实现。V7/V8/V9/V10按各自值域建头；V11的10个条件性原子字段须逐项输出并对`NA`掩码。视觉人口、V7/V8边界和V11专门规则完成共同校准与独立信度冻结前，不得训练或发布V11，也不得用整图情感分数替代它。

不同分类头共享同一个 BERT，因此多个任务会共同影响文本表示。

例如：

```text
“沿着海边散步特别舒服，建议傍晚过来。”
```

可以同时支持：

- 旅游主题：海滨；
- 体验维度：放松；
- 叙事方式：体验描述；
- 推荐意图：建议。

这些任务的训练梯度共同更新 BERT，使其学习可以被多个研究维度复用的旅游语言表示。

相关任务可能相互促进；定义冲突或无关的任务也可能产生负迁移。因此，分类头的划分应反映研究维度之间的理论边界。

## 十二、最终关系

```text
研究维度
    → 一个任务族，可按值域拆分技术头

维度中的原子代码
    → 一个输出节点

代码是否可以共存
    → Sigmoid或Softmax

代码的分析单位
    → 由编码表决定；当前文本主任务为固定片段

代码的父子结构
    → 父类与子类逐字段输出；关系只作审计或候选层级约束

代码的不确定状态
    → 损失掩码

代码的文本证据
    → 可追溯Span；是否增加证据抽取头由实验决定

简单帖子聚合
    → 计算标签次数、片段比例和是否出现

组合模式与统计指数
    → 按原研究设计与各自质量门保留；当前DEFERRED不等于删除
```

核心结论是：

> 编码表不是把人工定义的“特征”直接放进 BERT，而是把研究概念转换成一组可监督的判断任务。BERT通过带标签的文本样本，学习这些研究概念在真实语言中的操作化边界。
